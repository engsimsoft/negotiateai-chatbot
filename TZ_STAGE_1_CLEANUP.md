# Техническое задание: Этап 1 — Очистка и подготовка проекта

**Проект:** NegotiateAI Chatbot  
**Дата:** 2026-01-26  
**Тип задачи:** Рефакторинг документации, удаление legacy контента

---

## Контекст

Проект NegotiateAI изначально создавался как AI-ассистент для бизнес-переговоров (MIR.TRADE). Этот проект закрыт. Кодовая база переиспользуется для нового назначения — **персональный семейный AI-ассистент** для двух пользователей:

| Пользователь | Роль | Специализация ассистента |
|--------------|------|--------------------------|
| Владимир | Инженер | Технический помощник |
| Юлия | Маркетолог | Маркетинговый помощник |

**Текущий статус:** Код работает, задеплоен на Vercel. Нужно очистить от старого контента и подготовить документацию под новые цели.

### CLAUDE.md

**Назначение:** Контекст для Claude Code при работе с проектом.

**Должен содержать:**

- Описание проекта (персональный семейный AI-ассистент)
- Пользователи: Владимир (инженер), Юлия (маркетолог)
- Текущее состояние (Этап 1 завершён, готов к Этапу 2)
- Технологии (ссылка на README, без дублирования)
- Ключевые директории и файлы
- Команды разработки (npm run dev, build, etc.)
- Контекст для AI:
  - Это приватный проект для двух человек
  - Не нужна регистрация и guest режим
  - Будет система ролей (engineer/marketer) с разными промптами
  - Будут проекты с персональной базой знаний (как в Claude)
- Текущие задачи / следующие шаги (Этап 2)
- Ссылка на _archive/ для справочной информации

**Стиль:** Информативный, для AI. Не дублировать README.

**Содержание:**

  - Авторизация (NextAuth)
  - AI Chat (Vercel AI SDK + Gemini)
  - База данных (Drizzle ORM)
  - AI Tools (webSearch, readDocument, etc.)
- Потоки данных
- Ссылки на ADR для обоснования решений

**Примечание:** Описывать текущую архитектуру. Планируемые изменения (роли, проекты) — это Этап 2.

### docs/deployment.md

**Содержание:**

- Деплой на Vercel (уже настроен)
- Environment variables (список обязательных)
- База данных (Neon integration)
- CI/CD (auto-deploy из master)
- Мониторинг (Vercel Analytics)

### docs/decisions/ (ADR)

**Три ADR + шаблон:**

#### 001-why-gemini.md

- Контекст: выбор AI модели
- Решение: Google Gemini 2.5 Pro
- Причины: цена, качество, русский язык, бесплатный tier
- Альтернативы: OpenAI GPT-4, Claude (дороже для личного проекта)

#### 002-family-bot-concept.md

- Контекст: переиспользование кодовой базы MIR.TRADE
- Решение: персональный семейный ассистент с ролями
- Причины: проект закрыт, код рабочий, новая потребность
- Пользователи: Владимир (инженер), Юлия (маркетолог)
- Последствия: разные system prompts, персональные проекты

#### 003-no-guest-mode.md

- Контекст: текущая авторизация создаёт guest users
- Решение: убрать guest режим, только два пользователя
- Причины: приватный проект, guest накапливаются в БД, не нужна регистрация
- Последствия: упрощение авторизации, seed скрипт для создания пользователей

Шаблон для будущих ADR.

## Примечания для исполнителя

1. **Гибкость решений:** Это ТЗ описывает цели и ожидаемый результат. Конкретная реализация может отличаться если ты видишь лучший способ. Например, структура директорий или формат документов могут быть адаптированы.

2. **Код не трогать:** На этом этапе изменения только в документации и удаление файлов. Код (app/, lib/, components/) остаётся без изменений — это Этап 2.

3. **Справочные материалы:** Файлы в `_archive/` (AUTH_ANALYSIS.md, PROJECT_OVERVIEW.md) содержат детальный анализ текущей системы. Используй их для понимания архитектуры при написании документации.

4. **Проверка работоспособности:** После всех изменений убедись что проект запускается и собирается. Удаление файлов не должно сломать код.

5. **Git:** Рекомендуется создать архивную ветку перед началом работы (`archive/mir-trade-v1.0.14`), чтобы сохранить историю старого проекта.
