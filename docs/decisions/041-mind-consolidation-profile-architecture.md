# ADR 041: MIND Consolidation + Profile Architecture

**Дата:** 2026-04-07
**Статус:** Принято
**ТЗ:** RAG-2 (v3.72.0)

## Контекст

RAG-1 (v3.71.0) извлекает факты из каждого разговора, но не проверяет их на противоречия. При длинных сессиях (4-10 часов) пользователь может принять решение A, затем передумать и выбрать B — оба факта остаются активными. Retrieval может вернуть устаревший факт. Дедупликация на cosine 0.92 не ловит семантические противоречия с разными формулировками.

## Решение

### Гибридная консолидация: batch + event-triggered

| Триггер | Когда | Scope | Модель |
|---------|-------|-------|--------|
| **Event** | Каждые 20 новых фактов | Последние 30 фактов | Sonnet |
| **Nightly** | 3:00 MSK (cron) | Все активные факты | Sonnet + Opus |

**Мини-консолидация** срабатывает из `extract.ts` через fire-and-forget — `chat/route.ts` не затрагивается. Счётчик `factsSinceConsolidation` в таблице `memory_settings`.

### Opus-профиль

Ночной cron генерирует нарративный профиль (800-1200 слов) из всех активных фактов. Профиль — стабильный первый блок system prompt (`<user-profile>`), дополненный динамическим retrieval (`<memory>`).

Порог генерации: >= 10 активных фактов + есть новые факты с последней генерации.

### memoryEnabled gate

Отдельная таблица `memory_settings` (паттерн `briefingSettings`). Пользователь может отключить извлечение и retrieval через UI `/settings` → «Память».

## Альтернативы

1. **Inline консолидация в chat/route.ts** — отвергнута: файл 1130+ строк, ещё один fire-and-forget увеличивает risk surface.
2. **Только ночной batch** — недостаточно: при 10-часовой сессии противоречия копятся до ночи.
3. **memoryEnabled в User таблице** — отвергнута: User = auth entity, у памяти свои настройки (расширяемость).

## Последствия

- Стоимость: ~70₽/день на активного пользователя (Sonnet консолидация + Opus профиль)
- Opus профиль добавляет ~400-600 токенов к system prompt
- Cron maxDuration=240 — ограничение Hobby plan, при масштабировании нужен Pro или batch
