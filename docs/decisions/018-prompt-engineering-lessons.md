## Назначение

Этот ADR — **живой журнал** слабых мест промптов и уроков prompt-инженерии. Обновляется каждый раз, когда обнаруживается проблема с промптом, которая потребовала изменения кода или формулировок.

**Цель:** Не повторять одни и те же ошибки. При написании нового промпта — сверяйся с этим документом.

## Уроки

### Урок 1: Мягкие инструкции без data-level маркировки не работают

**Дата:** 2026-02-22
**Промпт:** `briefing-author.md` v6
**Модель:** Claude Sonnet 4.6
**Контекст:** ТЗ-BF5 — дедупликация между брифингами

**Проблема:**
Промпт содержал инструкцию "Не повторяй новости из предыдущего выпуска" и передавал список headlines прошлого брифинга. Модель получала ~30 кандидатов, из которых ~80% были теми же статьями (те же источники, тот же день). Результат: ~60% headlines совпадали между выпусками.

**Почему не работало:**
- Инструкции были мягкими: "не повторяй", "свежее в приоритете"
- Кандидаты передавались без маркировки — модель не видела связь между headlines и конкретными кандидатами
- Модель оптимизировала по качеству контента, а не по уникальности — выбирала "лучшие" статьи, игнорируя что они повторы

**Решение (3 изменения):**
1. **Data-level маркировка кандидатов** — сбор `Set<URL>` из `sources[].url` прошлого выпуска, каждый кандидат с совпадающим URL получает тег `⚠️ БЫЛ В ПРОШЛОМ ВЫПУСКЕ` прямо в данных
2. **Сводка повторов** — строка `⚠️ 18 из 30 кандидатов помечены как повторы. Приоритет — оставшимся 12 НОВЫМ.` в user message
3. **Жёсткие правила вместо рекомендаций** — 4 пронумерованных правила + самопроверка дедупликации

**Результат:** Совпадение headlines упало с ~60% до <15%.

**Принцип:**
> Если модель должна различать элементы в списке — маркируй элементы на уровне данных, а не полагайся только на инструкции в system prompt. Структурированные сигналы (теги, метки) работают надёжнее текстовых указаний.

**Файлы:**
- `lib/prompts/briefing/briefing-author.md` — усиленная секция "Предыдущий выпуск"
- `lib/briefing/briefing-author.ts` — маркировка кандидатов по URL
- `lib/briefing/briefing-section-author.ts` — аналогичная маркировка для per-section refresh

## Общие принципы (извлечённые из уроков)

1. **Data > Instructions.** Маркировка данных (теги, метки на элементах) работает надёжнее текстовых инструкций в промпте. Модель лучше реагирует на структурированные сигналы в данных, чем на абстрактные правила.

2. **Жёсткость формулировок.** "Не повторяй" — модель может проигнорировать. "Нарушение = дефект выпуска" + самопроверка — работает. Если правило критическое — формулируй как жёсткое требование с последствиями.

3. **Самопроверка.** Встраивай в промпт шаг самопроверки: "Перед завершением проверь X. Если условие нарушено — переработай."
