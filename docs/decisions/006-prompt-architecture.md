# ADR 006: Новая архитектура промптов (v3.0.0)

**Дата:** 2026-02-02
**Статус:** Superseded by [ADR 008](008-skills-agents-architecture.md)

---

## Контекст

После завершения этапов 1-6 система содержала 8 агентов в БД с UI для выбора и @-mentions для переключения. Это создавало сложность:

**Проблемы старой архитектуры:**
- 8 агентов = 8 промптов в БД (сложно редактировать)
- UI выбора агента перегружал интерфейс
- @-mentions добавляли когнитивную нагрузку
- Таблицы Agent/UserAgent усложняли схему БД
- Промпты без type safety (строки в БД)

**Требования:**
- Упростить интерфейс (Apple-подход)
- Type safety для промптов
- Модальные помощники вместо агентов
- Подготовка к Anthropic (мультипровайдер)

---

## Решение

Заменить систему агентов в БД на файловую систему промптов + модальные помощники.

### Новая архитектура

```
lib/prompts/
├── index.ts           # buildPrompt() API
├── types.ts           # TypeScript типы
├── builder.ts         # Логика сборки
├── chat/config.ts     # Универсальный чат
├── ben/config.ts      # Бен (помощник)
└── assistants/
    └── prompt-agent/  # Prompt-агент
```

### Модальные помощники

| Помощник | Кнопка | Назначение |
|----------|--------|------------|
| Prompt-агент | 📝 | Улучшение промптов |
| Бен | ❓ | Помощь по платформе |

### Удалено

- Таблицы БД: `Agent`, `UserAgent`
- Поля: `agentId` в `Chat` и `Message`
- UI: выбор агента, @-mentions
- Страницы: `/agents/*`
- Код: `seed-agents.ts`, `parse-mentions.ts`

---

## Причины

1. **Простота** — один чат вместо выбора из 8 агентов
2. **Type safety** — TypeScript конфиги с автокомплитом
3. **Поддерживаемость** — промпты в Git, code review, версионирование
4. **UX** — чистый интерфейс, меньше решений для пользователя
5. **Гибкость** — модальные помощники для специальных задач

---

## Последствия

**Плюсы:**
- Чистый интерфейс (logo, чат, 📝, ❓)
- Промпты с type safety
- Проще добавлять новые промпты
- Меньше таблиц в БД

**Минусы:**
- Breaking change (версия 3.0.0)
- Потеря персонализации агентов (UserAgent)
- Миграция БД (удаление таблиц)

---

## Альтернативы

### 1. Оставить агентов, упростить UI
- Убрать только @-mentions
- Оставить выбор агента

**Отклонено:** Не решает проблему type safety и сложности БД.

### 2. YAML конфиги вместо TypeScript
- Промпты в YAML файлах
- Загрузка через парсер

**Отклонено:** Нет type safety, нужна зависимость (Handlebars).

### 3. Оставить всё как есть
- Агенты в БД
- UI выбора

**Отклонено:** Противоречит Apple-подходу, сложность растёт.
