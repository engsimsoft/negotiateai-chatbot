## Контекст

После завершения Этапа 2 (базовые возможности AI-ассистента) возникла необходимость в персонализации опыта для двух пользователей с разными ролями и потребностями:

- **Владимир (engineer)** - технический специалист, нужен помощник для разработки и личностного роста
- **Юлия (marketer)** - маркетолог-копирайтер, нужна помощь в продвижении, написании текстов, переводах, плюс развлечение и быт

**Проблемы с единым промптом:**
- Один универсальный промпт для всех задач был слишком общим
- Невозможно оптимизировать под специфику задач (маркетинг vs разработка)
- Нет возможности выбирать оптимальную AI модель под задачу
- Отсутствие персонализации снижало ценность ассистента

**Требования:**
- Персонализация по ролям (разные агенты для engineer/marketer)
- Оптимизация затрат (дорогая модель только для сложных задач)
- Понятный UX (пользователь выбирает агента перед началом чата)
- Простая расширяемость (легко добавлять новых агентов)

---

## Решение

Реализовать **систему из 8 специализированных AI-агентов** с уникальными промптами и автоматическим выбором AI модели:

### Архитектура:

1. **8 агентов с уникальными ролями:**
   - **Маркетолог** 📊 - профессиональная стратегия и аналитика
   - **Копирайтер** ✍️ - продающие тексты для соцсетей
   - **Переводчик** 🌐 - технический перевод
   - **Кулинар** 🍳 - рецепты и советы по готовке
   - **Астролог** ⭐ - гороскопы и нумерология
   - **Наставник** 📚 - личностный рост (методика Кови)
   - **Универсальный** 💬 - общий ассистент
   - **Одессит** 😄 - развлечение и одесский юмор

2. **Персонализация по ролям:**
   - Юлия (marketer) → видит все 8 агентов
   - Владимир (engineer) → видит 3 агента (Наставник, Универсальный, Одессит)

3. **Автоматический выбор AI модели:**
   - **Gemini 3 Pro** - для профессиональных задач (Маркетолог, Копирайтер, Переводчик, Наставник)
     - Dynamic thinking, 1M контекст, 64K output
     - Цена: $2/$12 за 1M токенов
   - **Gemini 2.5 Flash** - для развлекательных задач (Кулинар, Астролог, Универсальный, Одессит)
     - Быстрее и дешевле

4. **Режим "auto" по умолчанию (v2.1.1):**
   - Все новые чаты создаются в режиме "auto"
   - Система автоматически выбирает оптимальную модель для агента
   - Пользователь может переключить на конкретную модель вручную

5. **UI индикатор модели (v2.1.1):**
   - Badge в header чата показывает активную модель
   - Tooltip объясняет выбор (авто vs ручной)
   - Адаптивный дизайн (мобильный/десктоп)

### Технические решения:

- **Промпты:** Markdown файлы в `lib/ai/agents/*.md` (один файл = один агент)
- **Конфигурация:** `lib/ai/agents/index.ts` (список агентов, модели, роли)
- **Загрузка:** `lib/ai/prompts.ts` функция `loadAgentPrompt()` с кешированием
- **Выбор модели:** `getModelForAgent(agentId)` на основе `agent.defaultModel`
- **БД:** Добавлено поле `agentId` в таблицу `chat` (миграция 0010)
- **UI:** Главный экран с карточками агентов, иконки в header и sidebar

## Причины

### 1. Персонализация опыта
- Каждый агент оптимизирован под конкретную задачу
- Юлия получает маркетинговых агентов, Владимир - технические
- Промпты написаны с учетом специфики задач

### 2. Оптимизация затрат
- Дорогая модель (Gemini 3 Pro) только для сложных задач
- Простые задачи (кулинария, астрология) решаются быстрой дешевой моделью
- Автоматический выбор снижает расходы

### 3. Четкое разделение ответственности
- Один агент = одна роль = один промпт
- Легко обновлять и тестировать промпты
- Понятная структура для разработчика

### 4. Улучшение качества для специфичных задач
- Маркетолог знает SMM и стратегию
- Копирайтер пишет продающие тексты с эмодзи
- Переводчик сохраняет термины и стиль
- Каждый агент - эксперт в своей области

### 5. Понятный UX
- Пользователь выбирает агента как "собеседника"
- Визуальные карточки с иконками на главном экране
- Иконка агента в header чата
- Приветственное сообщение при создании чата

## Последствия

### Плюсы

- ✅ **Высокое качество для специфичных задач** - каждый агент оптимизирован под свою область
- ✅ **Экономия средств** - дорогая модель только там где нужно (профессиональные задачи)
- ✅ **Персонализация** - каждый пользователь видит только своих агентов
- ✅ **Понятный UX** - выбор агента как выбор собеседника
- ✅ **Простая расширяемость** - добавить нового агента = добавить один файл
- ✅ **Кеширование** - промпты загружаются один раз и кешируются в памяти
- ✅ **Гибкость** - можно переключать модель вручную при необходимости
- ✅ **Прозрачность** - UI показывает какая модель используется

### Минусы

- ❌ **Больше файлов для поддержки** - 8 промптов вместо одного
- ❌ **Сложнее добавлять глобальные фичи** - нужно обновлять промпты 8 агентов
- ❌ **Риск дублирования** - базовые инструкции могут повторяться в промптах
- ❌ **Сложность тестирования** - нужно тестировать всех 8 агентов
- ❌ **Больше состояния** - нужно хранить `agentId` в БД

## Альтернативы

### Альтернатива 1: Единый универсальный промпт

**Что это:** Один промпт для всех задач, как в Этапе 2

**Почему отклонили:**
- Слишком общий, не оптимизирован под специфику
- Невозможно выбрать оптимальную модель (всегда дорогая или всегда дешевая)
- Нет персонализации под роли пользователей
- Плохой UX - пользователь не знает на что способен ассистент

**Когда может быть лучше:**
- Если пользователей сотни и нельзя персонализировать
- Если нужна простота поддержки любой ценой
- Если нет требований к оптимизации затрат

### Альтернатива 2: Dynamic prompts (генерация на лету)

**Что это:** Генерировать промпт динамически на основе контекста запроса

**Почему отклонили:**
- Сложнее контролировать качество (промпт меняется каждый раз)
- Невозможно тестировать стабильность промптов
- Сложнее отлаживать проблемы (промпт не детерминирован)
- Риск ухудшения качества на edge cases

**Когда может быть лучше:**
- Если задач очень много (100+) и нельзя создать отдельный промпт
- Если контекст меняется радикально от запроса к запросу
- Если есть ML модель для генерации оптимальных промптов

### Альтернатива 3: Больше агентов (10+)

**Что это:** Создать 15-20 узкоспециализированных агентов

**Почему отклонили:**
- Только 2 пользователя - нет смысла в десятках агентов
- Сложнее поддерживать и обновлять
- UX перегружается (слишком много выбора)
- Риск дублирования промптов

**Когда может быть лучше:**
- Если пользователей сотни с разными потребностями
- Если бизнес-модель требует узкой специализации
- Если есть команда для поддержки множества промптов

### Альтернатива 4: Меньше агентов (3-5)

**Что это:** Только самые важные агенты (Маркетолог, Универсальный, Наставник)

**Почему отклонили:**
- Теряем персонализацию (Копирайтер vs Маркетолог - разные стили)
- Развлекательные агенты (Одессит, Астролог) добавляют ценность
- Текущее количество (8) удобно для 2 пользователей

**Когда может быть лучше:**
- Если нужна максимальная простота
- Если бюджет на разработку ограничен
- На MVP этапе (но сейчас это уже Этап 3)

## Примечания

### Технические детали реализации:

**Промпты агентов:**
- Каждый промпт в отдельном `.md` файле (Markdown)
- Загружается через `fs.readFile` при старте чата
- Кешируется в Map для производительности (production) или пропускается (development)
- Fallback на `system-prompt.md` если агент не найден

**Выбор модели:**
```typescript
// Режим "auto" → используется agent.defaultModel
// Режим "manual" → используется выбор пользователя
if (selectedChatModel === "auto") {
  modelToUse = getModelForAgent(agentId);
} else {
  modelToUse = selectedChatModel;
}
```

**UI индикатор модели (v2.1.1):**
- Показывает "Авто" или название модели
- Tooltip объясняет выбор
- Адаптивный: короткое название на мобильных, полное на десктопе

**Персонализация:**
```typescript
function getAgentsByRole(role: UserRole): Agent[] {
  return AGENTS.filter(
    (agent) => agent.availableFor === role || agent.availableFor === "both"
  );
}
```

### Lessons learned:

1. **Специализация лучше универсальности** - узкие промпты дают лучшие результаты
2. **Автоматический выбор модели оптимизирует затраты** - пользователю не нужно думать
3. **Кеширование промптов критично** - без него каждый запрос читает файл с диска
4. **Иконки и приветствия улучшают UX** - агенты чувствуются как "личности"

### Будущие улучшения:

- **Память агента:** Контекст между чатами с одним агентом
