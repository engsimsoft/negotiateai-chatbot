# ADR 014: Route Groups для режимов чатов

**Дата:** 2026-02-18
**Статус:** Принято

---

## Контекст

Все три режима чатов (chat, expertise, create) использовали единый маршрут `/chat/[id]`, различаясь только полем `chatMode` в БД. Sidebar был единый и не знал контекста режима — показывал "Чаты", кнопку "+ Новый чат" и смешанную историю всех режимов, даже когда пользователь работал в режиме "Экспертиза".

Breadcrumbs говорили "Экспертиза", а sidebar показывал "Чаты" — для целевой аудитории (40-60+) это критичная проблема доверия к интерфейсу.

---

## Решение

Перевести три режима на отдельные Next.js Route Groups с собственными URL:

```
app/
  (chat)/chat/[id]/page.tsx           → /chat/[id]
  (expertise)/expertise/[id]/page.tsx → /expertise/[id]
  (create)/create/[id]/page.tsx       → /create/[id]
```

Все три page.tsx используют **один и тот же** компонент `Chat`. Различия только в layout (дублирован с провайдерами) и контекстном sidebar.

Sidebar определяет режим из pathname (`getSidebarContext()`), а не из БД — мгновенно, без мерцания, без зависимости от загрузки данных.

---

## Причины

1. **URL стали осмысленными** — `/expertise/abc123` сразу говорит о контексте
2. **Sidebar стабилен** — не зависит от загрузки данных, режим определяется из URL
3. **Layout не перемонтируется** — навигация между чатами одного режима не вызывает remount
4. **Старые URL работают** — redirect из `/chat/[id]` если `chatMode ≠ chat`
5. **История фильтруется** — API `/api/history?chatMode=expertise` возвращает только релевантные чаты

---

## Альтернативы

### Альтернатива: Деривация chatMode в sidebar из данных текущего чата

**Почему отклонено:**
- Мерцание при навигации — sidebar показывает "Чаты" пока не загрузятся данные чата
- Зависимость от загрузки данных — для нового чата (ещё нет в БД) невозможно определить режим
- Сложность cleanup при уходе со страницы

---

## Последствия

### Плюсы

- Каждый режим имеет контекстный sidebar: заголовок, кнопка создания, ссылка "Все...", отфильтрованная история
- URL являются закладко-пригодными и shareable
- Shared компонент Chat — без дублирования логики

### Минусы

- Layout файлы дублированы (3 копии с провайдерами) — приемлемый trade-off, т.к. layout минимален
- `getChatUrl()` утилита нужна везде, где формируется URL чата
