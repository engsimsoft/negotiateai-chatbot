# ADR 012: Разделение Context и Instruction в проектах

**Дата:** 2026-02-07
**Статус:** Принято
**Связано с:** ТЗ-11 (Project Creation Polish)

---

## Контекст

При создании проекта Секретарь проводит интервью с пользователем и собирает информацию. До этого решения вся информация записывалась в одно поле `instruction` — "инструкция для AI".

**Проблема:** Это смешивает два разных типа информации:
- **Контекст** — справка о бизнесе, аудитории, целях (факты)
- **Инструкция** — как AI должен работать с проектом (поведение)

Эти данные создаются разными персонажами в разные моменты:
- Контекст → Секретарь (при создании проекта)
- Инструкция → Менеджер проекта (после создания, при настройке)

---

## Решение

Добавить отдельную колонку `context` в таблицу `Project`. Секретарь пишет в `context`, а `instruction` остаётся для Менеджера.

**Схема ответственности:**
```
Секретарь  → context     (справка о бизнесе)
Менеджер   → instruction (инструкция для AI)
```

**Изменения в БД:**
```sql
ALTER TABLE "Project" ADD COLUMN "context" text;
```

**Маппинг на странице проекта:**

| Вкладка "Паспорт" | Колонка БД |
|--------------------|------------|
| ЦЕЛЬ | `description` |
| КОНТЕКСТ | `context` |

| Вкладка "Инструкция" | Колонка БД |
|-----------------------|------------|
| Инструкция для AI | `instruction` |

---

## Причины

1. **Разные персонажи** — Секретарь и Менеджер имеют разные зоны ответственности
2. **Разные моменты** — контекст собирается при создании, инструкция формируется позже
3. **Чистота данных** — не нужно будет разделять смешанный текст при реализации Менеджера
4. **TODO в коде** — в `ProjectPassport` уже был комментарий `// TODO: Add context field to project schema`

---

## Последствия

### Плюсы

- Чёткая архитектура: один персонаж — одно поле
- Менеджер сможет писать инструкцию не затрагивая контекст
- Нет необходимости в миграции данных при реализации Менеджера
- На странице проекта КОНТЕКСТ теперь отображает реальные данные

### Минусы

- Дополнительная колонка в БД (минимальный overhead)
- `instruction` пока пустая у новых проектов (заполнится при реализации Менеджера)

---

## Альтернативы

**Вариант B: Перенаправление** — Секретарь пишет в `instruction`, на странице проекта показываем как "Контекст".

Отклонён: при реализации Менеджера пришлось бы мигрировать данные и разделять текст, который был смешан.
