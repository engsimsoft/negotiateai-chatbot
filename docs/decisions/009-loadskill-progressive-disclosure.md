# ADR 009: loadSkill Tool — Progressive Disclosure (v3.3.2)

**Дата:** 2026-02-03
**Статус:** Принято
**Extends:** [ADR 008](008-skills-agents-architecture.md)

---

## Контекст

После внедрения Skills + Agents (ADR 008) возникла проблема:

**Проблема:**
Skills созданы, но модель не следует инструкциям из SKILL.md.

**Причина:**
```
Текущий flow:
Запрос → промпт с metadata skills → модель отвечает
                ↑
        Только name + description
        Полные инструкции НЕ загружаются
```

Модель видит только краткое описание skill (Level 1), но не получает инструкции как работать (Level 2).

**Временный костыль:**
Добавили хардкод правил в `base.md`:
```markdown
### ⚠️ ОБЯЗАТЕЛЬНО: Создание документов
НИКОГДА не создавай документ сразу. ВСЕГДА сначала задай вопросы...
```

Это нарушает SSOT и делает skills бесполезными.

---

## Решение

Создать tool `loadSkill`, который модель вызывает сама когда нужны инструкции.

### Новый flow

```
Запрос пользователя
        ↓
Модель видит metadata skills в промпте
        ↓
Модель понимает: нужна презентация → нужен skill
        ↓
┌─────────────────────────────────────┐
│ loadSkill("document/create-presentation") │
└─────────────────────────────────────┘
        ↓
Tool возвращает полный SKILL.md контент
        ↓
Модель читает инструкции
        ↓
Модель следует инструкциям (задаёт вопросы)
        ↓
Создаёт результат
```

### Tool Definition

```typescript
export const loadSkill = tool({
  description: `Загружает инструкции для сложной задачи.

КОГДА ИСПОЛЬЗОВАТЬ:
- Перед созданием презентации → loadSkill("document/create-presentation")
- Перед созданием таблицы → loadSkill("document/create-spreadsheet")
- ...

ПРАВИЛО: Для сложных задач СНАЧАЛА загрузи инструкции.`,

  inputSchema: z.object({
    skillId: z.enum([
      'document/create-presentation',
      'document/create-spreadsheet',
      'document/create-text-document',
      'document/analyze-document',
      'research/web-research',
    ])
  }),

  execute: async ({ skillId }) => {
    const content = loadSkillContent(skillId);
    return { success: true, instructions: content };
  }
});
```

### System Prompt

В `base.md` добавлена секция:

```markdown
### Инструкции для сложных задач (Skills)

У тебя есть tool `loadSkill` для загрузки детальных инструкций.

**Доступные skills:**
- `document/create-presentation` — Создание презентаций
- ...

**Правило:**
Для ПРОСТЫХ задач → отвечай сразу.
Для СЛОЖНЫХ задач → loadSkill → читай → следуй.
```

---

## Причины выбора

### Почему tool, а не автоматическая загрузка?

| Подход | Проблема |
|--------|----------|
| **Загружать все skills** | Промпт 10,000+ токенов, дорого |
| **Keyword classifier** | Хрупкий, не понимает контекст |
| **LLM classifier** | +1 API вызов, задержка, деньги |
| **Tool (модель решает)** ✅ | Модель сама знает когда нужна помощь |

### Почему это правильный подход?

1. **Anthropic pattern:** Они используют `view` tool для загрузки SKILL.md
2. **Progressive Disclosure:** Загружается только нужный контент
3. **Модель решает:** Не нужен отдельный classifier
4. **Масштабируемость:** Добавил skill → он сразу доступен

### Почему не хардкод в base.md?

- ❌ Нарушает SSOT (инструкции в двух местах)
- ❌ Не масштабируется (каждый skill дублировать?)
- ❌ Раздувает промпт (все инструкции всегда загружены)
- ❌ Делает skills бесполезными

---

## Последствия

**Плюсы:**
- SSOT сохраняется (инструкции в SKILL.md)
- Экономия токенов (загружается только нужное)
- Масштабируемость (новый skill = сразу доступен)
- Проверенный подход (Anthropic pattern)

**Минусы:**
- Дополнительный tool call (+latency)
- Модель может забыть вызвать loadSkill
- Нужна хорошая формулировка description

---

## Альтернативы

### 1. Хардкод правил в base.md
- Дублировать инструкции из SKILL.md в base.md

**Отклонено:** Нарушает SSOT, не масштабируется.

### 2. Автозагрузка по keywords
- Если "презентация" → автоматически загрузить skill

**Отклонено:** Хрупкий classifier, ложные срабатывания.

### 3. Всегда загружать все skills
- Level 2 контент всегда в промпте

**Отклонено:** 10,000+ токенов, дорого, нерелевантный контент.

### 4. Отдельный LLM classifier
- Первый вызов определяет какой skill нужен

**Отклонено:** +1 API call, latency, деньги.
