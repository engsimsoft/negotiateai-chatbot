# ТЗ-4: Упрощение UX и исправление @-mentions

**Проект:** Simply
**Версия:** 1.0
**Дата:** 2026-01-29
**Этап:** 4 (рефакторинг после ТЗ-3B)

---

## 🎯 Цель

Убрать избыточную сложность, исправить логику @-mentions и сделать интерфейс понятным для пользователя 40+ без технического бэкграунда.

**Философия:** iPhone, не Android. Меньше опций — больше пользы.

---

## 📋 Проблемы текущей реализации

### 1. Персонализация агентов — бесполезна

| Что даёт | Ценность |
|----------|----------|
| Новое имя агента | Косметика |
| Стиль общения | Дублирует профиль пользователя |
| Специализация | Единственное полезное, но редко нужно |

**Результат:** Пользователь плодит клонов ("Мой маркетолог", "Маркетолог для работы") и через месяц не помнит чем они отличаются.

### 2. @-mentions — работает как dropdown

Текущая логика:
```
@Помощник вопрос → Chat.agentId = Помощник → весь чат переключился
```

Ожидание пользователя:
```
@Помощник вопрос → Помощник ответил → продолжаю с предыдущим агентом
```

### 3. Suggested actions — хардкод из старого проекта

"AGORA", "Saleor", "парсинг тендеров" — мусор, не имеющий отношения к Simply.

### 4. Шапка чата — теряет агента

Для user_agent не показывается имя агента. Пользователь не понимает с кем общается.

### 5. Два разных UI приветствия

- Каталожный агент → greeting как сообщение
- User agent → заголовок + suggested actions

Непоследовательно.

### Часть 2: @-mentions = одноразовый вызов

**Новая логика:**

```
Chat.agentId = Маркетолог (НЕ меняется при @-mention)

1. User: "Проанализируй рынок" → Маркетолог
2. Маркетолог: ответ
3. User: "@Помощник какие ещё агенты помогут?" → Помощник (одноразово)
4. Помощник: ответ (помечен как гостевой)
5. User: "Продолжим анализ" → Маркетолог (автоматически)
```

**Изменения в БД:**

Добавить в таблицу `Message_v2`:

| Поле | Тип | Описание |
|------|-----|----------|
| isGuestAgent | boolean | Default false. True если это одноразовый вызов через @-mention |

Или альтернатива: не добавлять поле, определять по сравнению `Message.agentId !== Chat.agentId`.

**Изменения в API:**

`POST /api/chat` — при @-mention:
- НЕ обновлять `Chat.agentId`
- Сохранять `Message.agentId` = вызванный агент
- Помечать ответ как гостевой

**Визуальное отличие гостевого ответа:**

```
┌─────────────────────────────────────────────────────┐
│ 📊 Маркетолог                                       │
│ Анализ показывает что ваша ЦА...                   │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ Вы                                                  │
│ @Помощник какие ещё агенты могут помочь?           │
└─────────────────────────────────────────────────────┘

   ┌──────────────────────────────────────────────────┐
   │ 🤝 Помощник                          ↩️ гость    │
   │                                                  │
   │ Для этой задачи также подойдут:                 │
   │ • Копирайтер — для текстов                      │
   │ • Презентатор — для питч-дека                   │
   └──────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ Вы                                                  │
│ Хорошо, продолжим анализ                           │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ 📊 Маркетолог                                       │
│ Вернёмся к сегментации...                          │
└─────────────────────────────────────────────────────┘
```

**Стилизация гостевого сообщения:**
- Отступ слева (margin-left или padding-left)
- Лёгкий фоновый цвет (серый или цвет агента с opacity)
- Метка "↩️ гость" или "консультация" в углу
- Опционально: тонкая левая граница цветом агента

### Часть 3: Подсказка с возможностью вызова

**Первый визит — обучающая карточка:**

```
┌─────────────────────────────────────────────────────┐
│ 💡 Совет                                        ✕  │
│                                                     │
│ Напишите @Помощник или @Маркетолог чтобы           │
│ позвать другого агента прямо в этот чат.           │
│ Он ответит и вы продолжите с текущим.              │
│                                                     │
│                                    [Понятно]        │
└─────────────────────────────────────────────────────┘
```

**Поведение:**
- Показывается один раз при первом чате
- Кнопка "Понятно" или ✕ — скрывает
- localStorage: `simply-hint-guest-agent-seen`

**Иконка для повторного вызова:**

```
┌────────────────────────────────────────────────────┐
│ Напишите сообщение...                     [💡] [↑] │
└────────────────────────────────────────────────────┘
```

Клик на 💡 → показывает ту же подсказку.

**Альтернатива:** Не делать иконку, просто показать один раз. Кто запомнил — пользуется. Кто нет — использует dropdown. Это проще и чище.

### Часть 4: Suggested actions из БД

**Текущее:** Хардкод в `components/suggested-actions.tsx`

**Новое:** Брать из `capabilities.exampleTasks` агента

```typescript
// Было
const suggestedActions = [
  "Объясни разницу между AGORA и Saleor...",
  // хардкод
];

// Стало
const suggestedActions = agent.capabilities.exampleTasks;
```

**Пример для разных агентов:**

| Агент | exampleTasks |
|-------|--------------|
| Маркетолог | "Проанализируй ЦА для...", "Разработай стратегию...", "Сравни конкурентов..." |
| Копирайтер | "Напиши пост для Instagram...", "Придумай заголовки...", "Адаптируй текст..." |
| Переводчик | "Переведи с сохранением тона...", "Адаптируй для аудитории..." |
| Универсальный | "Объясни простыми словами...", "Помоги составить план...", "Проанализируй информацию..." |

**Важно:** Проверить что у всех агентов в БД заполнены `capabilities.exampleTasks`. Если нет — заполнить в seed.

### Часть 5: Шапка чата — всегда агент

**Проблема:** Для персональных агентов не показывается имя.

**Решение:** Шапка всегда показывает:
- Иконку агента
- Имя агента
- Dropdown для смены

```
┌─────────────────────────────────────────────────────┐
│ [≡]  📊 Маркетолог ▼         | Gemini 2.5 Flash    │
├─────────────────────────────────────────────────────┤
```

Для каталожных и user_agents — одинаково.

После удаления персонализации это упростится — только каталожные агенты.

### Часть 6: Унифицировать приветствие

**Выбираем вариант B:** Заголовок + suggested actions

**Убираем:** Greeting как первое сообщение от агента

**Почему:**
- Сообщение "Привет! Чем могу помочь?" засоряет историю
- Suggested actions полезнее — сразу понятно что спросить
- Чище визуально

**UI пустого чата:**

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│              Привет, Владимир! 👋                   │
│              Чем могу помочь?                       │
│                                                     │
│  ┌─────────────────────┐  ┌─────────────────────┐  │
│  │ Проанализируй ЦА    │  │ Разработай          │  │
│  │ для приложения...   │  │ стратегию...        │  │
│  └─────────────────────┘  └─────────────────────┘  │
│                                                     │
│  ┌─────────────────────┐  ┌─────────────────────┐  │
│  │ Сравни              │  │ Оцени               │  │
│  │ конкурентов...      │  │ позиционирование... │  │
│  └─────────────────────┘  └─────────────────────┘  │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**Изменения:**
1. Убрать добавление greeting в `route.ts` при создании чата
2. Suggested actions берутся из `agent.capabilities.exampleTasks`
3. Greeting из БД можно оставить — просто не использовать

## 📝 Примечания

### Почему не удаляем таблицу user_agents

Она пригодится для будущей фичи "Проекты":
- Проект = контекст + база знаний + агенты
- Персонализация на уровне проекта, не агента
- Таблица может быть переиспользована

### Почему оставляем автокомплит @-mentions

Теперь он имеет смысл — помогает выбрать кого позвать. В отличие от dropdown (смена агента), @ — это консультация.

### Приоритет

Это ТЗ важнее новых фич. Текущий UX запутывает пользователей и создаёт негативное впечатление от продукта.
