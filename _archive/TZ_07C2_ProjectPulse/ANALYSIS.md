## Вопросы для уточнения — ОТВЕЧЕНЫ

### 1. Автопереход статуса not_started → in_progress
**Ответ:** В `chat/route.ts` при отправке первого сообщения. Если `projectId` не null и `taskStatus === 'not_started'` → UPDATE на `in_progress`. Один запрос, не блокирует ответ.

### 2. Sidebar проекта — где показывать галочку?
**Ответ:** Оба места:
- В sidebar — компактно (✓ перед названием или иконка)
- На `/tasks` — полноценнее (кнопка + визуальный статус)

### 3. Генерация итога проекта — какую модель использовать?
**Ответ:** `gemini-2.5-flash`. Итог — синтез из нескольких summary задач, нужно качество. Вызов редкий (только при "Готово" или ручном обновлении), экономия копеечная.

### 4. Обновление итога при "Готово" — синхронно или в фоне?
**Ответ:** Фоном с toast. Пользователь нажал "Готово" → мгновенно видит смену статуса → toast "Обновляем итог проекта..." → итог появляется через пару секунд. Если генерация упала — старый итог остаётся, можно обновить кнопкой 🔄.

## Потенциальные риски

1. **Много миграций** — 2 новых поля в Chat + 2 в Project = 2 миграции
2. **Race condition** — если два клиента меняют статус одновременно
3. **Производительность** — генерация итога требует загрузки всех задач + AI вызов
