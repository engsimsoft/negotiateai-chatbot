## Согласованные решения (по итогам обсуждения с Владимиром)

1. **Формат работы:** маленькими шагами, один этап = одна сессия, между сессиями — HANDOFF. Защита от «обрезания углов» в длинной сессии. *(Инициатива Владимира, 2026-04-15.)*
2. **Оформляем как ТЗ по стандарту WORKFLOW.** Папка `specs/TZ_DocsCleanup/`, стандартные файлы (SPEC / ANALYSIS / ROADMAP / CHANGELOG / HANDOFF). *(Владимир: «уже отработанный workflow — проще сделать».)*
3. **Порядок этапов:** ai-chats-map → architecture → SIMPLY_STATUS → WORKFLOW процессный фикс → ai-minimax. Почему: сначала чиним «врущие» документы, чтобы SIMPLY_STATUS строился на правдивой основе. Процессный фикс **после** практической работы — когда видны реальные триггеры, а не только гипотетические.
4. **`.bak` файлы НЕ делаем.** Полагаемся на git — каждый этап один commit. `CLAUDE.md.bak` из прошлой уборки владелец удалит сам после просмотра diff.
5. **Отдельные ТЗ в будущем:** `setup.md` / `deployment.md` / `troubleshooting.md` / `mcp-tools.md` / `ai-artifacts.md` — слишком большой scope для текущего ТЗ, требуют отдельного аудита env vars и реальных процессов.
6. **CLAUDE.md не трогаем** при финализации этого ТЗ — по свежему правилу инварианта «редактировать только если добавлен принципиально новый архитектурный слой». Docs cleanup под это не попадает.
7. **Версию проекта не поднимаем** — это docs/chore, не продуктовое изменение. Все изменения → `[Unreleased]` секция главного CHANGELOG.md.
8. **Концептуальное разделение STATUS ↔ CHANGELOG (Владимир, 2026-04-15 в чате):**
   - SIMPLY_STATUS.md отвечает на вопрос **«что работает»**, не «что было сделано».
   - STATUS — **не source of truth для кода** (им остаётся сам код в `lib/`, `app/`, `components/`). STATUS — обзорный документ для человека/AI, «паспорт проекта».
   - Настоящее время, не прошедшее. Нет дат, версионных тегов, ТЗ-пометок.
   - Старая запись **перетирается** новой, не аккумулируется.
   - Этап 3 критерий: ни одного глагола в прошедшем времени в описаниях компонентов. «Работает / частично / заглушка / не начат», а не «был добавлен в v3.X».
   - **Сиротные факты** (найденное в старом SIMPLY_STATUS, чего нет ни в CHANGELOG ни в SPEC какого-либо ТЗ) — **вариант A**: всё равно выкидываем. Git-история сохранит старый файл навсегда, если понадобится.
   - Полная формулировка принципа в SPEC.md секция «Концептуальное разделение STATUS ↔ CHANGELOG».
