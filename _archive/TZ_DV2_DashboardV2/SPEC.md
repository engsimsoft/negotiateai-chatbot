# ТЗ: Дашборд V2 — от помощников к карточкам инструментов

**Версия:** 2.0 | **Дата:** 2026-02-17 (обновление v1.0 от 2026-02-16)
**Результат:** Дашборд с карточками-лаунчерами, страницы инструментов (ListDetailPage), chatMode, AI = Simply

---

## Зачем

Помощники (Маркетолог, Копирайтер и т.д.) не работают для аудитории 40+. Паралич выбора. Заменяем на три карточки инструментов, где система сама решает что подключить. Пользователь общается с **Simply** — одним AI. Он не знает и не выбирает модели.

**Обновление v2.0:** Вместо простых карточек-ссылок — полноценные страницы для каждого инструмента. Паттерн двухколоночного list-detail layout (из `/chats`) становится универсальным компонентом.

---

## Что сделать

### 1. Удалить всю экосистему помощников ✅ (Этап 1)

Полное удаление: файлы, роуты, компоненты, БД-зависимости.

### 2. chatMode — новое поле в Chat ✅ (Этап 2)

`chatMode: varchar('chat' | 'expertise' | 'create'), default: 'chat'`. Сервер определяет модель автоматически.

### 3. Промпты и Tools по chatMode ✅ (Этап 3)

Composer-функции + tools routing по chatMode.

### 4. Три карточки на дашборде (Этап 4A)

Под блоком [История чатов + Поле ввода] — три карточки:

- **Экспертиза** (🔍) — «Точные ответы с проверкой фактов» → `/expertise`
- **Создать** (✨) — «Презентации, отчёты, изображения» → `/create`
- **Проекты** (📁) — «Сложная работа с вашими данными» → `/projects`

Секцию ПРОЕКТЫ с карточками конкретных проектов — убрать с дашборда.
Карточку «История чатов» — не трогать.
Grid расширяемый (будущие карточки: Утренний брифинг, Совещание и др.).
Убрать селектор модели из поля ввода.

### 5. Универсальный компонент ListDetailPage (Этап 4B)

Референс: страница `/chats`. Паттерн list-detail, но вместо копирования — **composition** компонент.

**Подход:** Layout-shell + render props (НЕ generics). Shell отвечает за:
- Header (← Dashboard, заголовок, счётчик, кнопка создания, UserMenu)
- Двухколоночный layout
- Empty state
- Mobile: правая колонка скрыта

Содержимое — через props.

### 6. Страницы инструментов (Этап 4C)

| Страница | Route group | Источник данных | Кнопка создания |
|----------|-------------|-----------------|-----------------|
| `/expertise` | `(dashboard)` | Чаты `chatMode='expertise'` | → `/chat?mode=expertise` |
| `/create` | `(dashboard)` | Чаты `chatMode='create'` | → `/chat?mode=create` |

Кнопка создания → redirect, чат создаётся при первом сообщении (вариант B).

### 7. Рефакторинг /projects (Этап 4D)

Перевести `/projects` с grid-карточек на list-detail layout. Единый паттерн.

| Параметр | Значение |
|----------|----------|
| **Заголовок** | Проекты |
| **Кнопка создания** | + Новый проект → `/projects/new` |
| **Правая панель** | Фаза, задачи, файлы, дата, «Открыть проект →» |
| **Действия** | Переименовать, удалить (в detail-панели и/или контекстном меню) |

### 8. AI = Simply + Badge chatMode (Этап 5)

- AI = Simply (не Claude)
- SparklesIcon (SVG позже)
- Badge в sidebar и списках: 🔍 expertise, ✨ create, 💬 chat (или без)
- Dev-индикатор модели — сохранён

### 9. chatMode определяет конфигурацию жёстко

| Параметр | `chat` | `expertise` | `create` |
|----------|--------|-------------|----------|
| **Модель** | Claude Haiku | Claude Sonnet | Claude Sonnet |
| **Промпт** | `composeChatPrompt()` | `composeExpertisePrompt()` | `composeCreatePrompt()` |
| **Tools** | базовые | расширенные | расширенные |

### 10. Страница /chats

Показывает **все непроектные чаты** (chat + expertise + create). Единый архив. В будущем — фильтр по chatMode.
