## Цель

Новый инструмент "Запись встречи" на дашборде. Пользователь записывает встречу (встроенный рекордер ИЛИ загружает готовый аудиофайл) и получает структурированный документ. Три уровня детализации: Сводка / Протокол / Детальный.

**Философия:** Одна кнопка — готовый документ.

---

## Что делаем

### 1. Карточка на дашборде

В существующую секцию ИНСТРУМЕНТЫ (`ToolsSection`) добавить карточку "Запись встречи" по паттерну `BriefingCard`. Тап → `/meeting`.

### 2. Страница /meeting

Два режима входа:

**А. Записать** (основной) — большая кнопка записи. Тап → запись идёт (таймер, пульсация). Пауза и стоп. Лимит 3 часа.

**Б. Загрузить файл** (дополнительный) — file picker, accept `audio/*`. MP3, M4A, WAV, WebM, OGG. Лимит 200MB.

**После записи/загрузки:**

1. Аудиоплеер (файл играет ЛОКАЛЬНО через Object URL)
2. Выбор формата: Сводка (~1 стр) / Протокол (~2-3 стр) / Детальный (полный) — single select, "Протокол" по умолчанию
3. Кнопка "Создать документ"

**Обработка:** прогресс с этапами (загрузка → расшифровка → анализ → документ). NDJSON streaming по паттерну briefing generate.

**Результат:** документ (markdown render) + аудиоплеер + метаданные (дата, длительность, кол-во спикеров). В детальном режиме тайм-коды кликабельные → перемотка аудио.

**Список записей:** предыдущие записи пользователя (дата, длительность, превью). Тап → результат. Аудио НЕ хранится — только текст. Если нужно послушать, кнопка "Загрузить аудиофайл".

### 3. Рекордер

MediaRecorder API. Запись в chunks → финальный Blob. Проще чем voice input — никакого streaming/WebSocket. Просто пишем аудио в память.

Хук `use-meeting-recorder.ts`: состояния idle/recording/paused/stopped, таймер, blob.

### 4. Backend Pipeline

**Route:** `POST /api/meeting/process` (maxDuration: 300)

**Flow:**

1. Client-side upload аудио в Vercel Blob (presigned URL — обход лимита 4.5MB на API route)
2. API route получает blob URL + выбранный формат
3. Deepgram Nova-3 batch: `transcribeUrl({ url }, { model: "nova-3", language: "ru", smart_format: true, diarize: true, utterances: true, paragraphs: true })`
4. Форматирование транскрипта: `[ЧЧ:ММ:СС] Спикер N: текст`
5. Claude Sonnet (`claude-sonnet-4-6`): суммаризация по выбранному уровню
6. Сохранение в БД
7. Удаление аудио из Vercel Blob
8. Результат клиенту через NDJSON stream

**Deepgram SDK:** `@deepgram/sdk` — уже в проекте.

### 5. Суммаризация

Модель: Claude Sonnet (встречи = серьёзная работа → Claude по архитектуре Simply).

Три промпта: `lib/prompts/meeting/meeting-summary-{compact|standard|detailed}.md`

**Compact (Сводка):** Участники, 3-5 ключевых решений, задачи (кто/что/срок). Максимум 1 страница.

**Standard (Протокол):** Участники, обсуждённые темы с резюме, решения с обоснованием, задачи (таблица), открытые вопросы, следующие шаги. 2-3 страницы.

**Detailed (Детальный):** Всё из Standard + хронология с тайм-кодами [ЧЧ:ММ:СС], позиции участников, ключевые цитаты, точки разногласий. Полный объём.

Базовые промпты — в ТЗ как ориентир. Claude Code: напиши промпты в .md файлы, стиль — деловой, русский язык.

### 6. База данных

Новая таблица `MeetingRecord`:

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID PK | |
| userId | UUID FK → User | |

Drizzle schema, миграция, queries.

## Чего НЕ делаем

- Real-time транскрипцию во время записи
- Экспорт PDF/DOCX
- Редактирование результата
- Переименование спикеров
- Постоянное хранение аудио в облаке
- Шаринг документа

---

## Технические ограничения

- **Upload:** client-side → Vercel Blob (presigned), НЕ через API route (лимит 4.5MB)
- **Function timeout:** 300 сек (Deepgram ~3 мин + Claude ~30 сек = ОК)
- **Транскрипт:** 2ч ≈ 30K слов ≈ 40K токенов → Claude 200K контекст, без chunking
- **Deepgram timeout:** макс 10 мин для Nova, 2ч обрабатывается за 2-3 мин

---

## Критерии приёмки

1. Карточка "Запись встречи" в секции ИНСТРУМЕНТЫ на дашборде
2. Кнопка записи работает: таймер, пауза, стоп
3. Загрузка аудиофайла (MP3) работает
4. Выбор формата из трёх, кнопка "Создать документ"
5. Прогресс обработки с этапами виден
6. Результат: текст с участниками, темами, решениями, задачами
7. Аудиоплеер работает (локальный файл)
8. В детальном режиме тайм-коды кликабельные
9. Запись сохранена в БД, видна в списке
10. Аудио удалено из Vercel Blob после обработки
11. **Визуальный стиль строго по `docs/design-system.md`**
