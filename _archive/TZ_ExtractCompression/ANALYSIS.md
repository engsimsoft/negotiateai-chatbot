# Анализ ТЗ-ExtractCompression

## Резюме

Simply Chat накапливает сообщения в контексте, но факты не попадают в MIND (extract отключён с v3.77.0). Нужен механизм: при приближении к лимиту контекстного окна → batch-извлечение фактов → пометка сообщений как обработанных → следующий запрос грузит меньше.

## Рекомендации разработчика (Код-ревью)

> Ниже — технические рекомендации на основе анализа кодовой базы.
> Все рекомендации согласованы с архитектором (2026-04-08).

### Согласен с ТЗ
- Поле `extractedAt` в message — ОК, минимальная миграция
- batchExtractFacts рядом с extractAndStoreFacts — ОК, не ломает существующий код
- Два порога (80% + пауза / 95% без паузы) — разумная эвристика
- Fire-and-forget — паттерн уже отработан (`void fn().catch(...)`)
- Ночной cron в memory-profile — логичное место
- Модель Sonnet для batch extraction — ОК

### Решения разработчика (утверждены)

| # | Тема | Решение | Обоснование |
|---|------|---------|-------------|
| 1 | Safety-cap на загрузку | maxTokens: 180K для simply (вместо "без бюджета") | Защита от бесконтрольного роста при сбоях extraction |
| 2 | Новая константа | SIMPLY_CONTEXT_LIMIT = 200_000 | Реальный лимит модели (min MiniMax 204K, Sonnet 200K) |
| 3 | Параметр excludeExtracted | Добавить в getMessagesByChatId (опциональный, default false) | Не создавать отдельную функцию, минимум дублирования |
| 4 | Batch prompt | Отдельный extract-batch.md | Текущий extract.md заточен под одну пару, batch нужен свой |
| 5 | Определение паузы | Из messagesFromDb (уже загружены) | Не делать отдельный запрос к БД |
| 6 | Race condition | Допускаем, dedup поймает | Serverless = нет in-memory state, вероятность низкая |
| 7 | Compaction для simply+think | НЕ включать | Один механизм (Extract) для всего simply, без усложнений |

## Потенциальные риски

1. **Токен-оценка для MiniMax** — `estimateMessageTokens()` может быть неточной для MiniMax (другой токенизатор). Но при safety-cap 180K и порогах 160K/190K — запас достаточный
2. **Стоимость batch extraction** — Sonnet для 50 сообщений = ~80K input tokens = ~$0.24 за batch. Приемлемо, т.к. amortized (раз в много сообщений)
3. **Первый запуск** — все существующие сообщения extractedAt=NULL → загрузятся все. Safety-cap 180K защищает
