## Цель

Три связанные фичи для инструмента "Стенограмма":

**А. Дополнительные инструкции** — перед генерацией документа пользователь может добавить контекст и указания для AI.

**Б. Повторная генерация** — из экрана результата можно создать новый документ по тому же транскрипту с другими инструкциями или уровнем.

**В. Экспорт PDF** — скачать документ как профессионально оформленный PDF.

Главный юзкейс: одна встреча — несколько отчётов для разных получателей. Для себя, для партнёра, для инвестора. Каждый со своим фокусом, каждый можно отправить как PDF.

## Фича А: Дополнительные инструкции

### Что делаем

На экране выбора формата (Сводка / Протокол / Детальный), между карточками формата и кнопкой "Создать документ" — опциональное сворачиваемое текстовое поле.

### UX

- Ссылка-триггер: **"+ Добавить контекст встречи"**
- По нажатию — плавно раскрывается textarea
- Высота: 3-4 строки, растягивается по содержимому
- Поле необязательное. Не раскрыл — работает как раньше.

**Placeholder:**
```
Необязательно. Примеры:

"Это собеседование на позицию маркетолога. Оцени компетенции кандидата."

"Этот отчёт для моего партнёра Алексея. Фокус на его задачах и зоне ответственности."

"Встреча с инвестором. Выжимка: прогресс, цифры, риски."
```

### Backend

В вызове Claude API — пользовательские инструкции в user message перед транскриптом:

```typescript
const userMessage = userInstructions
  ? `Дополнительные инструкции от участника встречи:\n${userInstructions}\n\n---\n\n${transcript}`
  : transcript;

const { text, usage } = await generateText({
  model: claudeSonnet,
  system: systemPrompt,        // .md файл без изменений
  prompt: userMessage,          // инструкции + транскрипт
  temperature: 0.3,
  maxOutputTokens: 8192,
});
```

System prompt не меняется. Инструкции идут в user message.

### API route

В `POST /api/meeting/process` добавить необязательное поле `userInstructions: string | null` в body запроса.

### База данных

В таблицу `MeetingRecord` добавить поле:

```
userInstructions TEXT NULL  -- инструкции пользователя (если были)
```

## Фича Б: Повторная генерация

### Что делаем

На экране результата (готовый документ) — кнопка "Создать другой отчёт". Открывает модальное окно с выбором формата и инструкциями. Генерация без повторной транскрипции — транскрипт берётся из БД.

### UX

Кнопка **"🔄 Создать другой отчёт"** на экране результата.

По нажатию — **модальное окно** (не переход на другую страницу):

1. Выбор формата (Сводка / Протокол / Детальный) — текущий предвыбран
2. Поле инструкций — предзаполнено прошлыми (если были), можно изменить
3. Кнопка "Создать"

Модальное окно — потому что пользователь остаётся на экране результата и может сравнить старый документ с новым.

### Backend

Новый API route:

`POST /api/meeting/regenerate`

```json
{
  "recordId": "uuid",
  "summaryLevel": "detailed",
  "userInstructions": "..."
}
```

Flow:
1. Достать `transcript` из БД по recordId
2. Отправить в Claude с новым уровнем и инструкциями
3. Создать **новую запись** в `MeetingRecord` (не перезаписывать старую)
4. Связать с оригинальной записью

### База данных

В таблицу `MeetingRecord` добавить поле:

```
originalRecordId UUID NULL REFERENCES "MeetingRecord"("id")  -- ссылка на оригинал
```

Все версии — отдельные записи. Старые не удаляются. В списке записей для MVP — плоский хронологический список без группировки.

## Фича В: Экспорт PDF

### Что делаем

Кнопка "Скачать PDF" на экране результата. Конвертирует markdown-документ в профессионально оформленный PDF.

### UX — три кнопки на экране результата

```
📋 Копировать текст     📄 Скачать PDF     🔄 Создать другой отчёт
```

Плюс существующая кнопка "Удалить".

**"Копировать текст"** — текущее поведение, копирует markdown в буфер.

**"Скачать PDF"** — генерирует и скачивает PDF-файл. Имя файла: `{title}.pdf` (title из первой строки документа, транслитерация если нужно).

### Генерация PDF

**Подход: серверный API route.**

`POST /api/meeting/export-pdf`

```json
{
  "recordId": "uuid"
}
```

Flow:
1. Достать `summary` (markdown) и `title` из БД
2. Конвертировать markdown → PDF
3. Вернуть файл (Content-Type: application/pdf)

**Библиотека:** на усмотрение Claude Code. Варианты: puppeteer (markdown → HTML → PDF), или markdown-pdf, или jsPDF. Критерий — качество рендеринга кириллицы и markdown-элементов (заголовки, таблицы, bold, blockquote, списки).

### Оформление PDF

- **Шрифт:** с поддержкой кириллицы (обязательно)
- **Заголовок документа:** title из первой строки
- **Дата:** дата создания записи
- **Markdown → PDF:** заголовки, bold, italic, таблицы, blockquote (цитаты), нумерованные/ненумерованные списки — всё должно корректно рендериться
- **Колонтитул (footer):** "Создано в Simply" — мелким шрифтом внизу каждой страницы
- Без логотипа (пока нет утверждённого)
- Размер страницы: A4

### Ограничения

- Генерация PDF на сервере, не на клиенте (кириллица, шрифты, качество)
- Если puppeteer — проверить что работает на Vercel (или использовать библиотеку без headless browser)

## Чего НЕ делаем

- Экспорт в DOCX/Word
- Редактирование документа в UI
- Стриминг при регенерации
- Группировку версий в списке записей
- Удаление старых версий

## Критерии приёмки

### Фича А — Инструкции
1. Поле "Добавить контекст встречи" на экране выбора формата
2. Поле необязательное — без него работает как раньше
3. С инструкциями — результат учитывает контекст (проверить вручную)
4. Инструкции сохраняются в БД

### Фича Б — Регенерация
5. Кнопка "Создать другой отчёт" на экране результата
6. Модальное окно с выбором формата и полем инструкций
7. Предзаполнение прошлых параметров
8. Генерация без повторной транскрипции (~30 сек)
9. Новый документ — новая запись в БД, старый не пропадает

### Фича В — PDF
10. Кнопка "Скачать PDF" на экране результата
11. PDF корректно рендерит кириллицу
12. Все markdown-элементы отображаются (заголовки, таблицы, bold, цитаты, списки)
13. Футер "Создано в Simply" на каждой странице
14. Имя файла читаемое

### Общее
15. Визуальный стиль по `docs/design-system.md`
