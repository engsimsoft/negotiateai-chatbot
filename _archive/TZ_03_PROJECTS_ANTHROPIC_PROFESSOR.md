## 1. Цель

Создать полноценную систему Проектов — пространств для глубокой работы с контекстом. Внедрить Anthropic как провайдера для проектов с тремя уровнями моделей, включая режим Профессор (pipeline Opus → Haiku → Opus).

**Бизнес-цель:** 
- Чат = поболтать, быстрые вопросы
- Проект = серьёзная работа, профессиональный подход, решение задач

---

## 2. Система названий моделей

### 2.1. Философия

Пользователь не видит технических названий моделей. Видит понятные роли, разделённые по контексту.

### 2.2. Чат (Google) — повседневное общение

| Техническая модель | Название | Иконка | Использование |
|--------------------|----------|--------|---------------|
| Gemini 2.5 Flash | **Быстрый** | ⚡ | Бен, Prompt-агент, простые вопросы |
| Gemini 3 Pro | **Умный** | 💬 | Основной чат, сложные задачи |

### 2.3. Проекты (Anthropic) — профессиональная работа

| Техническая модель | Название | Иконка | Использование |
|--------------------|----------|--------|---------------|
| Haiku 4.5 | **Исполнитель** | ⚙️ | Выполнение подзадач в pipeline |
| Sonnet 4.5 | **Эксперт** | 💼 | Основная работа в проекте |
| Opus 4.5 | **Профессор** | 🎓 | Дирижёр pipeline, глубокий анализ |

## 3. Что делаем

### 3.1. База данных

#### Таблица `projects`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | uuid | Primary key |
| `userId` | uuid | FK → users.id |
| `name` | varchar(255) | Название проекта |
| `description` | text | Описание (опционально) |
| `instruction` | text | Инструкция для AI |
| `createdAt` | timestamp | Дата создания |
| `updatedAt` | timestamp | Дата обновления |

#### Таблица `project_files`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | uuid | Primary key |
| `projectId` | uuid | FK → projects.id |
| `name` | varchar(255) | Имя файла |
| `type` | varchar(50) | Тип: document, audio, image, other |
| `mimeType` | varchar(100) | MIME тип |
| `size` | integer | Размер в байтах |
| `url` | text | URL в Vercel Blob |
| `metadata` | jsonb | Доп. данные (транскрипт, страницы и т.д.) |
| `createdAt` | timestamp | Дата загрузки |

#### Изменение таблицы `chats`

Добавить поле:

| Поле | Тип | Описание |
|------|-----|----------|
| `projectId` | uuid | FK → projects.id (nullable) |

**Логика:**
- `projectId = null` → свободный чат (показывается в Sidebar → Chats)
- `projectId = <id>` → проектный чат (показывается только внутри проекта)

### 3.4. Режим Профессор (Pipeline)

Когда выбран Профессор, запускается pipeline:

```
Пользователь: "Разработай маркетинговую стратегию"
                         ↓
┌─────────────────────────────────────────────┐
│ 🎓 Профессор анализирует задачу...          │
│    • Понимает что нужно                     │
│    • Задаёт уточняющие вопросы (если нужно) │
│    • Разбивает на подзадачи                 │
│    • Пишет ТЗ для каждой подзадачи          │
└─────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────┐
│ ⚙️ Исполнитель: Анализ конкурентов ✓        │
│ ⚙️ Исполнитель: Целевая аудитория ✓         │
│ ⚙️ Исполнитель: Каналы продвижения ✓        │
│ ⚙️ Исполнитель: Бюджет и метрики ✓          │
└─────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────┐
│ 🎓 Профессор собирает результат...          │
│    • Проверяет качество                     │
│    • Объединяет в финальный документ        │
│    • Добавляет выводы и рекомендации        │
└─────────────────────────────────────────────┘
                         ↓
              Финальный результат
```

**UI во время pipeline:**

```

│                                                            │
│ Анализирую задачу...                                       │

│ ┌────────────────────────────────────────────────────────┐ │
│ │ Разбиваю на подзадачи:                                 │ │

│                                                            │
```

### 3.7. Загрузка файлов

**Поддерживаемые типы:**

| Категория | Расширения | Иконка |
|-----------|------------|--------|
| Документы | pdf, doc, docx, txt, md | 📄 |
| Таблицы | xls, xlsx, csv | 📊 |

**Хранение:** Vercel Blob Storage

**Лимиты:**
- Максимальный размер файла: 50 MB
- Максимум файлов в проекте: 100

**Примечание:** RAG-индексация файлов будет в ТЗ-04. Сейчас файлы просто хранятся и отображаются.

## 5. API Endpoints

### Проекты

| Метод | Путь | Описание |
|-------|------|----------|

## 7. Требования

### 7.1. Функциональные

1. Создание, редактирование, удаление проектов
2. Загрузка и удаление файлов в проекте
3. Инструкция проекта (текстовое поле)
4. Чаты привязанные к проекту
5. Выбор модели в проекте (Исполнитель / Эксперт / Профессор)
6. Pipeline режим Профессор работает
7. Sidebar разделяет свободные чаты и проектные
8. Два пути входа в проект (Dashboard и Sidebar)

### 7.2. UX

1. Создание проекта — максимально простое (название обязательно, остальное опционально)
2. Переключение между файловым видом и чатом — очевидное
3. Индикатор модели всегда виден
4. Pipeline показывает прогресс

### 7.3. Технические

1. Anthropic API через OpenRouter (уже подключён)
2. Vercel Blob для файлов
3. Транзакции при удалении проекта (удалить файлы, чаты, сообщения)
