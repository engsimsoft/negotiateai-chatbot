# Анализ ТЗ-SlidingWindow

## Резюме

Добавить жёсткий лимит по количеству сообщений (20) для Simply при отправке в API. Token-aware sliding window уже существует в `getMessagesByChatId()`, но работает по бюджету токенов (140K), а не по количеству — для коротких сообщений загружает все 200.

## Рекомендации разработчика (Код-ревью)

> Ниже — технические рекомендации на основе анализа кодовой базы.

### Согласен с ТЗ
- Скользящее окно 20 сообщений — ОК, 10 обменов достаточно для Simply
- Только Simply — ОК, expertise/create нуждаются в полной истории
- Snapshot оставить — ОК, страховка для edge case
- Extract не затронут — подтверждено: `extractAndStoreFacts()` получает текущую пару user+assistant из onFinish callback (`route.ts:1188-1198`), не из массива истории

### Реализация

**Где менять:** `app/(chat)/api/chat/route.ts:336-340` — передать `maxMessages: SIMPLY_SLIDING_WINDOW_SIZE` для chatMode=simply.

**Константа:** в `lib/ai/context-limits.ts` — рядом с `CONTEXT_BUDGET`. Файл уже содержит контекстные лимиты.

**Tool-call sanitization:** после обрезки по maxMessages проверить первое сообщение в окне — если это assistant/tool, сдвинуть начало до ближайшего user. Реализовать как утилиту `trimToUserStart()` в том же файле.

### Нет вопросов / рисков

Спек solid, объём минимальный. Единственный нюанс — tool-call пары, решение согласовано.
