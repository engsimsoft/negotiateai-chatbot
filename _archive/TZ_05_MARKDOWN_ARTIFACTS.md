## 📋 Контекст

### Проблема терминологии

| Термин | Понятность для пользователя 40+ |
|--------|--------------------------------|
| Артефакт | ❌ Непонятно, программистский термин |
| Документ | ✅ Понятно всем |
| Холст | ✅ Понятно (как в ChatGPT Canvas) |

**Решение:** 
- "Артефакт" → "Документ"
- Панель справа → "Холст"
- Весь процесс → "Создание документа в холсте"

### Проблема обнаруживаемости

Пользователь не знает что можно:
- Создавать документы и презентации
- Просматривать и редактировать в холсте
- Скачивать в разных форматах
- Делиться ссылкой

**Решение:** Расширить панель подсказок 💡 (уже есть для @-mentions).

### Текущие типы документов

| Тип | Описание | Скачивание | Public Share |
|-----|----------|------------|--------------|
| text | Plain text | .txt | ✅ Да |
| presentation-reveal | Reveal.js | HTML | ❌ Нет |
| presentation-pptx | PowerPoint | .pptx | ❌ Нет |

**Добавляем:** `markdown` — красивое форматирование + PDF экспорт.

### Часть 2: Переименование "артефакт" → "документ"

**Где менять:**

| Место | Было | Стало |
|-------|------|-------|
| UI панели справа | "Artifact" | "Документ" или название файла |
| Кнопки действий | — | "Скачать документ", "Поделиться" |
| Промпты агентов | "создам артефакт" | "создам документ в холсте" |
| Код (комментарии) | artifact | document (опционально) |

**Важно:** Имена переменных и таблиц в коде можно не менять (это внутренняя терминология). Меняем только то что видит пользователь.

### Часть 4: UI просмотр/редактирование Markdown

**Компонент:** `artifacts/markdown/client.tsx`

**Режим просмотра (по умолчанию):**

```tsx
import ReactMarkdown from 'react-markdown';
import remarkGfm from 'remark-gfm';

export function MarkdownViewer({ content }: { content: string }) {
  return (
    <div className="prose prose-slate max-w-none">
      <ReactMarkdown remarkPlugins={[remarkGfm]}>
        {content}
      </ReactMarkdown>
    </div>
  );
}
```

- Заголовки (H1-H6)

- Код (inline и блоки)
- Таблицы (GFM)
- Цитаты

**Режим редактирования:**
- Textarea с моноширинным шрифтом
- Переключение кнопкой 👁️/✏️

### Часть 5: Скачивание Markdown

**Меню скачивания:**

```
┌─────────────────────────┐
│ Скачать как:            │
│                         │
│ 📄 PDF                  │  ← для обычных пользователей
│ 📝 Markdown (.md)       │  ← для продвинутых
│                         │
└─────────────────────────┘
```

**PDF первым** — это то что нужно большинству.

**Генерация PDF (клиентская):**

```typescript
import html2pdf from 'html2pdf.js';

async function downloadAsPDF(markdown: string, filename: string) {
  // 1. Рендерим markdown в HTML
  const html = renderMarkdownToHTML(markdown);
  
  // 2. Создаём контейнер со стилями
  const container = document.createElement('div');
  container.innerHTML = html;
  container.className = 'prose prose-slate';
  container.style.padding = '40px';
  container.style.maxWidth = '800px';
  container.style.margin = '0 auto';
  container.style.fontFamily = 'system-ui, sans-serif';
  
  // 3. Генерируем PDF
  await html2pdf()
    .set({
      margin: 15,
      filename: `${filename}.pdf`,
      html2canvas: { scale: 2 },
      jsPDF: { unit: 'mm', format: 'a4', orientation: 'portrait' }
    })
    .from(container)
    .save();
}
```

## 📎 Сценарии для тестирования

### Сценарий 1: Панель подсказок

```
1. Новый пользователь открывает чат
2. Панель подсказок открыта автоматически
3. Видит 3 раздела: агенты, документы, файлы
4. Сворачивает раздел про файлы
5. Закрывает панель
6. Открывает новый чат — панель закрыта
7. Кликает на 💡 — панель открывается
8. Раздел про файлы всё ещё свёрнут (запомнилось)
```

### Сценарий 2: Создание markdown документа

```
1. Пишет: "Напиши маркетинговый план"
2. Агент создаёт документ в холсте
3. Видит красиво отформатированный текст
4. Кликает 👁️ → режим редактирования (видит исходный markdown)
5. Кликает обратно → режим просмотра
```

### Сценарий 3: Скачивание

```
1. Открывает markdown документ
2. Кликает ⬇️
3. Видит меню: PDF, Markdown
4. Выбирает PDF → скачивается файл
5. Открывает PDF → форматирование сохранено
```

### Сценарий 4: Публичная ссылка

```
1. Кликает 🔗 на документе
2. Копирует ссылку
3. Отправляет коллеге
4. Коллега (без аккаунта) открывает ссылку
5. Видит красиво отформатированный документ
6. Скачивает PDF
```

## 📝 Примечания

### Сравнение с ConsoleX

ConsoleX использует подход с явным toggle для включения Artifacts. Мы выбрали другой путь:

| ConsoleX | Simply |
|----------|--------|
| Надо вручную включить Artifacts | Всегда включено, агент сам решает |
| Термин "Artifacts" | Термин "Документ в холсте" |
| Список типов: Code, SVG, React... | Список типов: Документ, Презентация |
| Для разработчиков | Для бизнес-пользователей 40+ |

**Что взяли от ConsoleX:** Явный список типов документов в подсказках — помогает пользователю понять возможности.

### Когда агент создаёт markdown vs text?

**Агент решает сам:**
- Структурированный контент (планы, отчёты, инструкции) → markdown
- Короткие тексты (посты для соцсетей, сообщения) → text

**Обновить промпты агентов** с рекомендацией использовать markdown для документов.

### Порядок внедрения

1. Сначала: Панель подсказок (не зависит от markdown)
2. Потом: Терминология (простая замена текстов)
3. Потом: Markdown тип + рендеринг
4. В конце: PDF экспорт + публичные ссылки
