# ТЗ-BF5: Дедупликация контента между брифингами

**Цель:** Исключить повторение одних и тех же новостей при обновлении/генерации брифинга. Передавать контекст предыдущего выпуска в промпт Author.

**Версия:** 3.42.0 → 3.43.0

---

## Проблема

Текущий пайплайн в `route.ts`:
```
deleteOldBriefingHistory() → saveBriefingHistory(generating) → fetch → filter → author
```

`deleteOldBriefingHistory()` удаляет ВСЕ старые записи до начала генерации. Author (Claude Sonnet) не знает что было в предыдущем выпуске. Perplexity/RSS возвращают те же топовые новости → пользователь видит повтор.

---

## Решение: Sliding Window

Хранить предыдущий брифинг до завершения генерации нового. Извлечь заголовки тем → передать в промпт Author как контекст "уже показанного".

---

## Что сделать

### 1. Изменить `deleteOldBriefingHistory()` в `queries.ts`

Сейчас: удаляет ВСЕ записи пользователя.

Нужно: удалять все КРОМЕ последнего ready-брифинга. Параметр `keepLast: number = 1`.

Логика: отсортировать по `generatedAt DESC`, пропустить первые `keepLast` записей со статусом `ready`, удалить остальные.

### 2. Добавить функцию `getPreviousBriefingHeadlines()` в `queries.ts`

Входные параметры: `userId`.

Логика:
1. Загрузить последний ready-брифинг (`getBriefingHistory({ userId, limit: 1, status: "ready" })`)
2. Из `briefingJson` (тип `BriefingArticle`) извлечь для каждой секции:
   - `topicId`
   - `topicName`
   - `emoji`
   - Первый заголовок из `content` (## header или первая строка — паттерн уже есть в `extractHeadline()` в sidebar)

Возвращает: `{ generatedAt: string, topics: Array<{ topicId, topicName, emoji, headline }> } | null`

### 3. Интегрировать в `route.ts`

В `generate/route.ts`, ПЕРЕД `deleteOldBriefingHistory()`:

```
const previousHeadlines = await getPreviousBriefingHeadlines({ userId });
```

Затем `deleteOldBriefingHistory({ userId, keepLast: 1 })` — предыдущий останется жить до следующей генерации.

Передать `previousHeadlines` в вызов `generateBriefingArticle()` (briefing-author.ts).

### 4. Расширить `generateBriefingArticle()` в `briefing-author.ts`

Добавить опциональный параметр `previousBriefing` в функцию.

Если `previousBriefing` не null — вставить блок в промпт Author перед списком кандидатов. Формат блока — см. задание для PE ниже.

Если null (первая генерация) — ничего не добавлять.

### 5. Обновить промпт `briefing-author.md`

⚠️ **Промпт готовит PE.** Ниже — описание того, что нужно добавить в промпт. Финальную формулировку согласовать с PE.

В промпт Author добавить опциональную секцию "Предыдущий выпуск". Секция появляется только если есть данные о предыдущем брифинге.

**Семантика для PE:**
- Список тем и заголовков предыдущего выпуска
- Инструкция: не повторять эти темы, если нет существенного развития
- Если тема развивается — подать как обновление ("вчера X, сегодня Y"), не как новую новость
- Если по теме ничего нового — пропустить, найти другое
- Предпочтение свежим темам, которых не было в прошлом выпуске

---

## Формат данных для промпта

```
## Предыдущий выпуск ({дата})

Пользователь уже видел:
- {emoji} {topicName}: «{headline}»
- {emoji} {topicName}: «{headline}»
...
```

Точный промпт и формулировку правил определяет PE.

---

## Порядок работы

Промпт → код (PE должен согласовать формулировку до реализации):

1. PE согласует добавление в `briefing-author.md`
2. Claude Code реализует backend (queries + route + author)

---

## Что НЕ делаем

- ❌ Новые таблицы — используем существующую `briefingHistory`
- ❌ Миграции БД — не нужны
- ❌ RAG / векторный поиск — решается через промпт
- ❌ Полная история брифингов — только предыдущий выпуск

---

## Критерий готовности

- При генерации нового брифинга Author получает список тем предыдущего выпуска
- Новый брифинг не повторяет заголовки предыдущего (если нет развития темы)
- Если тема развивается — Author подаёт как обновление
- Предыдущий брифинг не удаляется до завершения генерации нового
- Первая генерация (нет предыдущего) работает как раньше
