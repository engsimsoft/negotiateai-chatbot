# ТЗ-BF5: Дедупликация — дополнение к briefing-author.md v5

**Что:** Новая секция в system prompt + опциональный блок в user message
**Куда в system prompt:** После секции "Приоритеты при отборе из candidates", перед "Структура выпуска"
**Версия промпта:** v5 → v6

---

## 1. Секция для system prompt

> Вставить после `## Приоритеты при отборе из candidates` и перед `## Структура выпуска`

```markdown
---

## Предыдущий выпуск

Иногда ты получаешь информацию о том, что было в предыдущем брифинге. Если этой информации нет — работай как обычно, правила ниже не применяются.

Если информация есть — используй её при отборе и написании:

**Не повторяй.** Если новость уже была в прошлом выпуске и ничего существенно не изменилось — пропусти её. Найди другой материал. Читатель не должен видеть одни и те же заголовки два дня подряд.

**Развитие ≠ повтор.** Если по вчерашней теме появилось существенное продолжение — новые факты, реакция рынка, последствия — пиши. Но подай как обновление: «Вчера мы разбирали решение ЦБ по ставке. Сегодня стали понятны последствия...». Читатель должен чувствовать прогресс, а не дежавю.

**Свежее — в приоритете.** При прочих равных выбирай кандидатов, которых не было в прошлом выпуске.

**Если всё повторяется.** Бывает: горячая тема держится несколько дней, и новых кандидатов по ней нет. Тогда копни глубже — аналитика, экспертные мнения, неочевидные последствия. Не выдавай те же факты теми же словами.
```

## 2. Опциональный блок для user message

> Вставляется в `buildUserMessage()` **после блока тем пользователя**, **перед кандидатами**. Только если данные о предыдущем выпуске есть.

### Формат данных

```
## Предыдущий выпуск ({previousBriefingDate})

Вчера читатель уже видел:
{previousHeadlines}
```

Где `{previousHeadlines}` — список строк вида:
```
- 🏦 Экономика: «ЦБ сохранил ключевую ставку на уровне 21%», «Рубль укрепился на фоне нефтяных котировок»
- 🤖 Технологии: «Яндекс обновил генеративные возможности Алисы»
```

### Рекомендация по формированию previousHeadlines

Из предыдущего `BriefingArticle` берём `sections`, для каждой:
- `emoji` + `topicName` — идентификация темы
- `sources[].title` — заголовки использованных новостей (это реальные headlines, не topicName)

Пример формирования в коде (ориентир для архитектора):

```typescript
function buildPreviousHeadlines(prevArticle: BriefingArticle): string {
  return prevArticle.sections
    .map(s => {
      const headlines = s.sources.map(src => `«${src.title}»`).join(', ');
      return `- ${s.emoji} ${s.topicName}: ${headlines}`;
    })
    .join('\n');
}
```

Если у секции нет sources (edge case) — использовать первые 10 слов content как fallback.

### Место в buildUserMessage

```typescript
// Текущий порядок:
// 1. getVolumeInstruction(volume)
// 2. Дата, язык, maxItems
// 3. Темы пользователя
// --- НОВОЕ: предыдущий выпуск (если есть) ---
// 4. Кандидаты

function buildUserMessage(
  candidates, fullTexts, tierMap, userTopics,
  language, maxItems, volume, date,
  previousArticle?: BriefingArticle,  // NEW: optional
  previousDate?: string               // NEW: optional
): string {
  // ... existing code ...

  // After topicsFormatted, before candidatesFormatted:
  const previousBlock = previousArticle && previousDate
    ? `\n---\n\n## Предыдущий выпуск (${previousDate})\n\nВчера читатель уже видел:\n${buildPreviousHeadlines(previousArticle)}\n`
    : '';

  return `${getVolumeInstruction(volume ?? "standard")}

Дата: ${dateFormatted}
Язык: ${language}
Целевое количество новостей: ${maxItems}

Темы пользователя:
${topicsFormatted}
${previousBlock}
---

Кандидаты (${candidates.length}):

${candidatesFormatted}`;
}
```

## 3. Не забыть: briefing-section-author.ts

Section author тоже должен получать данные о предыдущем выпуске — при посекционном обновлении. Формат проще: только headlines по конкретной теме, не весь выпуск. Но это решение за архитектурой — промпт уже содержит правила через наследование от briefing-author.md.

## 4. Мысленное тестирование

**Сценарий 1: Та же новость, ничего нового.** Вчера: «ЦБ сохранил ставку». Сегодня: тот же кандидат от другого источника. Author видит headlines, пропускает. Берёт другую новость по экономике.

**Сценарий 2: Развитие темы.** Вчера: «Apple представила языковую модель». Сегодня: «Аналитики оценили Apple Intelligence в $50B». Author подаёт как продолжение: «Вчера мы рассказывали о запуске...».

**Сценарий 3: Нет данных о предыдущем выпуске.** Первая генерация или данные не загрузились. Блок не вставляется. Author работает как v5 — без изменений.

**Сценарий 4: Все темы повторяются.** Слабый новостной день. Author видит что всё уже было → ищет аналитику, мнения, неочевидные углы. Не выдаёт пустой выпуск.

**Сценарий 5: Compact volume + дедупликация.** Compact и так берёт мало новостей. Если часть отфильтрована дедупликацией — может остаться совсем мало материала. Промпт говорит «найди другой материал», не «пропусти тему». Edge case в промпте уже покрыт: «Мало новостей по теме → короткая секция».
