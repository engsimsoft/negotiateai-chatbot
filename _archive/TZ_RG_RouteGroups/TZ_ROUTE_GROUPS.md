# ТЗ: Route Groups — отдельные маршруты для каждого режима

**Версия:** 1.0  
**Дата:** 2026-02-18  
**Зависимости:** Этапы 1-2 UX Navigation (терминология + breadcrumbs) завершены

---

## Задача

Перевести три режима чатов (chat, expertise, create) на отдельные маршруты с помощью Next.js Route Groups. Каждый режим получает свой URL и свой layout с контекстным sidebar.

## Зачем

Сейчас все чаты живут на `/chat/[id]`, а sidebar пытается "угадать" контекст из chatMode в БД. Это создаёт UX-конфликт: breadcrumbs говорят "Экспертиза", а sidebar показывает "Чаты", кнопку "+ Новый чат" и смешанную историю. Для аудитории 40-60+ — это потеря доверия к интерфейсу.

Route groups решают проблему структурно: каждый маршрут знает свой контекст, sidebar не вычисляет ничего.

## Целевая структура

```
app/
  (chat)/chat/[id]/page.tsx           → ChatLayout + ChatSidebar
  (expertise)/expertise/[id]/page.tsx → ExpertiseLayout + ExpertiseSidebar  
  (create)/create/[id]/page.tsx       → CreateLayout + CreateSidebar
```

Все три page.tsx используют **один и тот же** компонент Chat. Различия только в layout/sidebar.

## Что должен делать каждый sidebar

| | Chat | Expertise | Create |
|---|---|---|---|
| Заголовок секции | Чаты | Запросы | Задания |
| Кнопка создания | + Новый чат | + Новый запрос | + Новое задание |
| Ссылка "Все..." | Все чаты → /chats | Все запросы → /expertise | Все задания → /create |
| История | Только chatMode=chat | Только chatMode=expertise | Только chatMode=create |

Верхняя навигация (Главная, иконки) — одинаковая во всех трёх.

## Ключевые требования

1. Компонент Chat — без дублирования. Один shared компонент, три layout-обёртки
2. Breadcrumbs — упростятся: маршрут сам определяет режим, не нужно лезть в БД за chatMode
3. Создание нового чата: кнопка "+ Новый запрос" на ExpertiseSidebar создаёт чат с chatMode=expertise и редиректит на `/expertise/[newId]`
4. Старые ссылки `/chat/[id]` — должны работать. Если chatMode в БД = expertise → redirect на `/expertise/[id]`. Это гарантирует что закладки и история браузера не сломаются
5. Списковые страницы `/chats`, `/expertise`, `/create` — без изменений, они уже работают (Этап 1)

## ADR

**Записать в `docs/adr/` (создать директорию если нет):**

**ADR: Переход от единого /chat/[id] к route groups**

- **Контекст:** Все режимы (chat/expertise/create) использовали один маршрут `/chat/[id]`, различаясь только полем chatMode в БД. Sidebar был единый и не знал контекста режима.
- **Проблема:** UX-конфликт — breadcrumbs показывали "Экспертиза", а sidebar показывал "Чаты" с кнопкой "+ Новый чат" и смешанной историей. Для целевой аудитории (40-60+) это критичная проблема доверия к интерфейсу.
- **Решение:** Next.js Route Groups — три маршрута с отдельными layouts. Shared компонент Chat, контекстный sidebar определяется структурой, не вычислениями.
- **Альтернатива (отклонена):** Деривация chatMode в sidebar из данных текущего чата. Отклонено из-за: мерцания при навигации, зависимости от загрузки данных, сложности cleanup при уходе со страницы.
- **Последствия:** URL стали осмысленными (`/expertise/abc123`), sidebar стабилен, layout не перемонтируется при навигации между чатами одного режима.

## Чего НЕ делать

- Не менять компонент Chat
- Не менять правую боковую панель
- Не менять списковые страницы
- Не менять бэкенд/API
