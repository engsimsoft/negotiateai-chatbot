# Анализ ТЗ-BF1: Привязка контента по itemId

## Резюме

`fullTextsMap` в briefing pipeline строится по `item.url`, но фильтр (Gemini Flash) возвращает кандидатов с выдуманными URL для web/jina источников. Lookup всегда `undefined` → автор пишет без полного текста. Решение: привязка через уникальный `itemId`, присваиваемый при сборке.

## Рекомендации разработчика (Код-ревью)

> Ниже — технические рекомендации на основе анализа кодовой базы.
> Все рекомендации согласованы с архитектором.

### ✅ Согласен с ТЗ
- Подход с `itemId` — минимальный и правильный
- Изменения только в 4 файлах, ~20 строк
- Обратная совместимость через опциональное поле в типе
- Zod-валидация `sourceItemId` как обязательное поле безопасна (generateObject)

### ⚠️ Согласованные изменения
| # | Было (ТЗ) | Решение | Обоснование |
|---|-----------|---------|-------------|
| 1 | Упрощённый формат промпта `[src-0] Source \| URL \| "300 символов..."` | Сохранить богатый формат, только заменить `[${i+1}]` → `[${item.itemId}]` | Текущий формат содержит Title, URL, Published, Content — потеря структуры ухудшит фильтрацию |
| 2 | Нет логирования | Добавить `console.log` для hit rate | 2 строки, радикально упрощает отладку |
| 3 | Контент 300 символов | Оставить 6000 (MAX_CONTENT_LENGTH) | Архитектор подтвердил: иллюстрация, не инструкция |

### ❓ Зафиксировано (не в скоупе)
- Фабрикованные URL в `FilteredItem.url` для web/jina — решится в Этапе 2 (дофетчивание)
- Множественные кандидаты из одного листинга получают один и тот же текст — ожидаемо

## Потенциальные риски
- **Минимальные.** Изменения точечные, не затрагивают структуру pipeline.
- Единственный риск — LLM может вернуть невалидный `sourceItemId`. Но при `generateObject` + Zod schema это маловероятно, а fallback — `undefined` (текущее поведение).

- Нет изменений в БД
