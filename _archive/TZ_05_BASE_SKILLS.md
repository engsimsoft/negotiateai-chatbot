## Цель

Создать skills, которые учат агентов правильно использовать существующие tools в Simply.

**Важно:** Skills в Simply — это НЕ Python код (как у Anthropic). Это инструкции для агентов: когда и как вызывать готовые tools.

---

## Содержимое Skills

### 1. document/create-presentation/SKILL.md

```markdown
---
name: create-presentation
description: >
  Создание презентаций и слайдов. Используй когда пользователь просит 
  сделать презентацию, питч, слайды для выступления, отчёт в формате 
  слайдов. Поддерживает веб-формат (Reveal.js) и PowerPoint (PPTX).
tools:
  - createDocument
---

# Создание презентаций

## Когда использовать

- Пользователь просит "сделай презентацию", "нужны слайды"
- Требуется питч для инвесторов
- Нужен отчёт в формате слайдов
- Визуализация идеи или концепции

## Процесс работы

### 1. Уточни детали

Перед созданием спроси:
- **Цель:** Для чего презентация? (продать, обучить, отчитаться)
- **Аудитория:** Кто будет смотреть? (инвесторы, коллеги, клиенты)
- **Объём:** Сколько примерно слайдов? (5-7 коротко, 10-15 стандарт)
- **Формат:** Веб или PowerPoint?
- **Стиль:** Деловой, креативный, минималистичный?

### 2. Выбери формат

| Формат | Когда использовать |
|--------|-------------------|
| `presentation-reveal` | Показ онлайн, шеринг по ссылке |
| `presentation-pptx` | Скачать, редактировать, отправить по email |

### 3. Создай структуру

**Стандартная структура:**
1. Титульный слайд (название, автор)
2. Проблема / Контекст (зачем это нужно)
3. Решение / Основная часть (3-5 слайдов)
4. Результаты / Доказательства (если есть)
5. Выводы / Следующие шаги
6. Контакты / Call to action

### 4. Вызови tool

createDocument({
  type: 'presentation-reveal' или 'presentation-pptx',
  title: 'Название презентации',
  content: '... контент слайдов ...'
})

## Правила хороших слайдов

### Делай
- Один главный message на слайд
- Крупный читаемый текст
- Визуальная иерархия (заголовок → подзаголовок → текст)
- Пустое пространство — это хорошо

### Не делай
- Стены текста
- Мелкий шрифт "чтобы всё влезло"
- Больше 5-7 пунктов на слайде
- Читать слайды вслух дословно

## Примеры запросов

**Простой:**
> "Сделай презентацию про наш новый продукт"

**Детальный:**
> "Нужна презентация для инвесторов на 10 слайдов. Тема — приложение для доставки еды. Стиль деловой, формат PowerPoint."

## Частые ошибки

1. **Не спросил про аудиторию** → Презентация не попадает в цель
2. **Слишком много слайдов** → Аудитория устаёт
3. **Нет структуры** → Непонятно к чему ведёт
4. **Забыл call to action** → Что делать после просмотра?
```

```markdown
  формулы, форматирование, графики.
tools:
  - createDocument
---

# Создание таблиц Excel

## Когда использовать

- Пользователь просит "сделай таблицу", "нужен Excel"
- Требуется бюджет, смета, калькуляция
- Нужен план с датами и ответственными
- Отчёт с числовыми данными
- Любые структурированные данные

## Процесс работы

### 1. Уточни детали

Перед созданием спроси:
- **Цель:** Для чего таблица? (учёт, планирование, анализ)
- **Данные:** Какие колонки нужны?
- **Расчёты:** Нужны ли формулы? (суммы, проценты, средние)
- **Визуализация:** Нужен ли график?

### 2. Определи структуру

**Типичные структуры:**

| Тип | Колонки |
|-----|---------|
| Бюджет | Статья, План, Факт, Разница |
| План задач | Задача, Ответственный, Дедлайн, Статус |
| Продажи | Дата, Товар, Количество, Сумма |
| Контакты | Имя, Компания, Email, Телефон |

### 3. Вызови tool

createDocument({
  type: 'excel',
  title: 'Название таблицы',
  content: {
    headers: ['Колонка 1', 'Колонка 2', ...],
    rows: [
      ['Значение 1', 'Значение 2', ...],
      ...
    ],
    formulas: { 'B10': '=SUM(B2:B9)' }
  }
})

## Правила хороших таблиц

### Делай
- Понятные заголовки колонок
- Единый формат данных в колонке
- Итоговые строки с формулами
- Форматирование для читаемости

### Не делай
- Объединение ячеек без необходимости
- Смешивание типов данных в одной колонке
- Ручные расчёты вместо формул
- Слишком много колонок (больше 10-12)

## Доступные формулы

| Формула | Что делает |
|---------|------------|
| =SUM(A1:A10) | Сумма диапазона |
| =AVERAGE(A1:A10) | Среднее значение |
| =COUNT(A1:A10) | Количество чисел |
| =MAX(A1:A10) | Максимум |
| =MIN(A1:A10) | Минимум |
| =A1*B1 | Умножение |
| =A1/B1*100 | Процент |

## Примеры запросов

**Простой:**
> "Сделай таблицу расходов на месяц"

**Детальный:**
> "Нужна таблица для учёта продаж: дата, товар, количество, цена, сумма. Внизу итого по сумме. Добавь график продаж по дням."
```

```markdown
# Создание текстовых документов

## Когда использовать

- Пользователь просит "напиши документ", "создай отчёт"
- Нужна статья, пост, письмо
- Требуется инструкция, регламент, описание
- Любой структурированный текст

## Процесс работы

### 1. Уточни детали

Перед созданием спроси:
- **Тип:** Что это? (статья, письмо, отчёт, инструкция)
- **Аудитория:** Кто будет читать?
- **Тон:** Формальный, дружелюбный, нейтральный?
- **Объём:** Примерный размер?
- **Формат:** Нужно ли форматирование? (заголовки, списки)

### 2. Выбери формат

| Формат | Когда использовать |
|--------|-------------------|
| text | Простой текст без форматирования |
| markdown | С заголовками, списками, выделением |

### 3. Вызови tool

createDocument({
  type: 'markdown',
  title: 'Название документа',
  content: '... текст документа ...'
})

## Структуры по типам документов

### Статья / Пост
1. Заголовок (цепляющий)
2. Вступление (о чём и зачем)
3. Основная часть (разбить на секции)
4. Заключение (выводы, call to action)

### Деловое письмо
1. Приветствие
2. Суть вопроса (первый абзац)
3. Детали (если нужны)
4. Просьба / Предложение
5. Подпись

### Инструкция
1. Цель (что получим в результате)
2. Требования (что нужно для начала)
3. Шаги (пронумерованные)
4. Частые ошибки (опционально)
5. Контакты для вопросов

### Отчёт
1. Резюме (главное в 2-3 предложениях)
2. Контекст (что делали и зачем)
3. Результаты (с цифрами)
4. Проблемы (если были)
5. Следующие шаги

## Правила хороших документов

### Делай
- Начинай с главного
- Короткие абзацы (3-5 предложений)
- Подзаголовки для навигации
- Списки вместо перечислений в тексте

### Не делай
- Длинные вступления "ни о чём"
- Стены текста без разбивки
- Канцелярит и штампы
- Повторение одного и того же
```

### 4. document/analyze-document/SKILL.md

```markdown
---
name: analyze-document
description: >
  Анализ загруженных документов. Используй когда пользователь загрузил 
  файл и просит его проанализировать, извлечь данные, найти информацию, 
  сделать выводы.
tools:
  - readDocument
  - parseExcel
---

# Анализ документов

## Когда использовать

- Пользователь загрузил файл и просит "посмотри", "проанализируй"
- Нужно извлечь данные из документа
- Требуется найти конкретную информацию
- Нужны выводы на основе данных

## Процесс работы

### 1. Определи тип файла

| Расширение | Tool | Что получишь |
|------------|------|--------------|
| .txt, .md, .pdf | readDocument | Текст |
| .xlsx, .xls, .csv | parseExcel | Структурированные данные |
| .docx | readDocument | Текст |

### 2. Прочитай файл

readDocument({ documentId: '...' })
// или
parseExcel({ documentId: '...' })

### 3. Проанализируй содержимое

**Для текстовых документов:**
- Выдели ключевые тезисы
- Найди запрошенную информацию
- Сделай краткое резюме

**Для таблиц:**
- Посмотри структуру (колонки, строки)
- Посчитай базовую статистику (сумма, среднее, мин/макс)
- Найди аномалии или паттерны

### 4. Представь результат

- Сначала краткий вывод (1-2 предложения)
- Потом детали (если нужны)
- Предложи следующие шаги

## Типичные запросы

| Запрос | Что делать |
|--------|------------|
| "Что тут написано?" | Краткое резюме |
| "Найди все даты" | Извлечение конкретных данных |
| "Сколько всего?" | Подсчёт, суммирование |
| "Что не так?" | Поиск ошибок, аномалий |
| "Сравни с..." | Сравнительный анализ |

## Ограничения

- Максимальный размер файла: 50KB на файл
- Изображения в документах не анализируются
- Сложное форматирование может теряться
```

```markdown
# Поиск информации в интернете

## Когда использовать

- Нужны актуальные данные (цены, курсы, новости)
- Вопрос о недавних событиях
- Требуется проверить факт
- Пользователь явно просит "найди", "погугли"

## Когда НЕ использовать

- Общие знания (столица Франции)
- Исторические факты (когда была война)
- Базовые определения

## Процесс работы

### 1. Сформулируй запрос

**Хороший запрос:**
- Конкретный (не "про машины", а "цены Tesla Model 3 2024")
- Без лишних слов ("купить iPhone 15 цена Москва")
- На языке ожидаемых результатов

### 2. Выполни поиск

webSearch({ query: 'конкретный запрос' })

### 3. Обработай результаты

- Проверь актуальность (дата публикации)
- Сравни несколько источников
- Выдели главное

### 4. Представь ответ

- Ответь на вопрос (не пересказывай всё найденное)
- Укажи источники
- Отметь если информация противоречивая

## Примеры хороших запросов

| Плохо | Хорошо |
|-------|--------|
| "новости" | "новости технологий сегодня" |
| "погода" | "погода Москва сегодня" |
| "сколько стоит" | "iPhone 15 Pro цена официальный" |

## Ограничения

- Поиск только текстовый (не изображения)
- Результаты могут быть не на русском
- Некоторые сайты недоступны
```

```markdown
# Помощь в формулировке запросов

## Когда использовать

- Пользователь говорит "не знаю как спросить"
- Результаты не соответствуют ожиданиям
- Явная просьба "помоги сформулировать"

## Процесс работы

### 1. Пойми цель

Спроси:
- Что ты хочешь получить в результате?
- Для чего это нужно?
- Есть ли примеры похожего?

### 2. Определи проблему

**Частые проблемы:**

| Проблема | Признак | Решение |
|----------|---------|---------|
| Слишком общо | "Напиши текст" | Уточнить тип, объём, аудиторию |
| Слишком много сразу | "Сделай сайт с..." (10 требований) | Разбить на шаги |
| Непонятный контекст | "Как в прошлый раз" | Описать что именно |
| Противоречия | "Коротко, но подробно" | Выбрать приоритет |

### 3. Предложи улучшенный вариант

Покажи:
- Оригинальный запрос
- Улучшенный вариант
- Почему так лучше

## Формула хорошего запроса

[Действие] + [Что именно] + [Контекст/Ограничения] + [Формат результата]

**Примеры:**

| Плохо | Хорошо |
|-------|--------|
| "Напиши письмо" | "Напиши деловое письмо партнёру с предложением о сотрудничестве. Тон дружелюбный но профессиональный. 3-4 абзаца." |
| "Сделай презентацию" | "Сделай презентацию для инвесторов про наше приложение. 10 слайдов, стиль минималистичный, формат PowerPoint." |
| "Проанализируй" | "Проанализируй эту таблицу продаж. Найди топ-5 товаров по выручке и тренд по месяцам." |

## Шаблоны для типичных задач

### Текст
> "Напиши [тип текста] на тему [тема]. Аудитория: [кто]. Тон: [какой]. Объём: [сколько]."

### Анализ
> "Проанализируй [что]. Найди [что именно искать]. Результат представь в виде [формат]."

### Презентация
> "Сделай презентацию про [тема]. Цель: [зачем]. Аудитория: [кто]. Количество слайдов: [сколько]. Формат: [какой]."
```
