# Анализ ТЗ-SaveFact

## Резюме
Новый AI-tool `saveFact` для гарантированной записи фактов в MIND по явному запросу пользователя. Только для Simply Chat. Переиспользует существующую инфраструктуру RAG (embedding, dedup, storage).

## Вопросы для уточнения
Нет — ТЗ исчерпывающее, кодовая база изучена.

## Рекомендации разработчика (Код-ревью)

> Ниже — технические рекомендации на основе анализа кодовой базы.

### Согласен с ТЗ
- Tool только в Simply — ОК, паттерн условного включения через `chatMode` уже есть в `getStandardTools()`
- Переиспользование Extract-инфраструктуры — ОК, функции `embedText()`, `searchSimilarMemories()`, `verifyDuplicatesWithLLM()`, `insertMemoryEntry()`, `supersedeMemoryEntry()` экспортируются и готовы к использованию
- 7 категорий — ОК, совпадают с `MEMORY_CATEGORIES` в `types.ts`
- Дедупликация через существующий двухуровневый механизм — ОК
- `confidence: 1.00` для explicit — ОК, default в схеме уже `1.00`

### Рекомендую изменить
| # | Было (ТЗ) | Рекомендация | Обоснование из кода |
|---|-----------|--------------|-------------------|
| 1 | Поле `source` с values "extracted"/"explicit" | Назвать колонку `source` (varchar(32)), default `'extracted'`. Не путать с `sourceType` (chatMode) | В схеме (`schema.ts:773`) уже есть `sourceType` = chatMode. Новая ось — способ получения факта. Две разные колонки |

### Требует уточнения
Нет открытых вопросов.

## Потенциальные риски
- **Минимальный:** Race condition saveFact + Extract на один и тот же факт. Mitigation: дедупликация RAG-2 обрабатывает оба пути одинаково.
