# ТЗ-CacheAudit: Аудит подключения провайдеров Anthropic + MiniMax и prompt caching

**Автор:** Владимир Анатольевич (Product Owner)
**Дата:** 2026-04-12
**Статус:** В работе
**Целевая версия:** 3.85.0

---

## Цель

Провести комплексный аудит подключения двух LLM-провайдеров в проекте Simply (Anthropic Claude + MiniMax) на предмет:

1. **Соответствия официальной документации** — подключение сделано «идеально», без костылей и заплаток.
2. **Правильного выбора стандарта подключения** для MiniMax (OpenAI-compat vs Anthropic-compat) — один раз, чтобы не переделывать. Проверить, не ограничивает ли выбранный стандарт какие-то фичи моделей.
3. **Работы prompt caching** у обоих провайдеров — реально ли кэшируются запросы, видно ли экономию в метриках DevPanel и UsageLog.

Если в процессе аудита будут найдены проблемы — **устранить их в рамках этого же ТЗ**. В конце — дать рекомендации по улучшению.

---

## Входные условия

- Оба провайдера уже подключены напрямую (без промежуточных шлюзов типа OpenRouter или AI Gateway — валидировано в предыдущих ТЗ-1 и ТЗ-2).
- Модели работают, переключение между ними делается через Dev Switchboard (`/dev/models`) без правки кода (ТЗ-1/ТЗ-2).
- **Что НЕ проверяем:** сам факт подключения (работает), факт переключения моделей (работает).
- **Что проверяем:** корректность реализации подключения и работу prompt caching.

---

## Измерительная площадка

**Simply Chat** (`/simply`) — там уже встроено переключение text → MiniMax / «Думать» → Sonnet (через ТЗ-SimplyToolsMinimax v3.79.0), что позволяет тестировать оба провайдера в одном чате.

---

## Результат (Definition of Done)

1. Подключение обоих провайдеров соответствует официальной документации — подтверждено цитатами из неё.
2. MiniMax подключён через оптимальный стандарт с обоснованием выбора (feature matrix OpenAI-compat vs Anthropic-compat).
3. Prompt caching работает у обоих провайдеров, метрики видны в DevPanel tokens-section и попадают в `UsageLog`.
4. Найденные проблемы устранены (или задокументированы как follow-up ТЗ).
5. Два ADR: выбор стандарта MiniMax и стратегия cache breakpoints.
6. Рекомендации по улучшению зафиксированы в `SIMPLY_STATUS.md`.

---

## Ограничения scope

**В объёме этого ТЗ:**
- Chat routes: `api/chat`, `api/service-chat`, `api/projects/[id]/tasks/[taskId]/chat`
- Pipelines smoke-тест: briefing, podcast, MIND extract (подтверждение что переключение провайдера их не ломает)
- DevPanel метрики и UsageLog

**Вне объёма (отдельные ТЗ при необходимости):**
- Explicit cache control в pipelines (briefing-author, podcast-script, memory/extract) — не трогаем, получат автокэш бесплатно
- Рефакторинг `retryWithLogging` — это намеренный паттерн (ТЗ-PIPELINE1), не костыль
- Миграция на новые модели — переключение идёт через `/dev/models`, не требует кода
