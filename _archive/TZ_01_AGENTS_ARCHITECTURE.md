# ТЗ-1: Архитектура агентов и миграция в БД

**Проект:** Simply (на базе Family AI Assistant)
**Версия:** 1.0
**Дата:** 2026-01-28
**Этап:** 1 из 3

---

## 🎯 Цель

Перенести систему агентов из хардкода в базу данных. Создать фундамент для каталога агентов, персонализации и масштабирования на 1000+ пользователей.

---

## 📋 Контекст

### Текущее состояние

- Агенты хранятся в `lib/ai/agents/index.ts` — массив `AGENTS`
- Промпты агентов в отдельных `.md` файлах (9 штук)
- В таблице `Chat` есть поле `agentId` (varchar) — привязка к чату работает
- `User.role` (engineer/marketer) фильтрует доступные агенты — устаревшая логика
- Проект пустой, данные можно удалять без сохранения

### Целевое состояние

- Агенты хранятся в БД (таблица `agents`)
- Персональные копии пользователей — в таблице `user_agents`
- Поле `User.role` удалено
- UI показывает каталог агентов и "Мои агенты"
- Чат привязывается к агенту через uuid

## 🗄️ Схема БД

### Таблица `agents` (каталог)

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| id | uuid | да | PK, auto-generated |
| slug | varchar(64) | да | Уникальный идентификатор ("marketer", "helper") |
| type | enum | да | "system" / "catalog" |
| name | varchar(100) | да | "Маркетолог", "Агент-Помощник" |
| icon | varchar(10) | да | Эмодзи "📊" |
| description | text | да | Описание для каталога |
| systemPrompt | text | да | Системный промпт агента |
| greeting | text | да | Приветственное сообщение при старте чата |
| defaultModel | varchar(50) | да | "gemini-3-pro" / "gemini-2.5-flash" |
| toolAccess | jsonb | нет | Список доступных инструментов. null = все инструменты |
| capabilities | jsonb | да | Структурированные данные для страницы агента (см. ниже) |
| isActive | boolean | да | Default true. Позволяет скрыть без удаления |
| sortOrder | integer | да | Порядок отображения в каталоге |
| createdAt | timestamp | да | |
| updatedAt | timestamp | да | |

**Индексы:**
- UNIQUE на `slug`
- INDEX на `type`
- INDEX на `isActive`

### Таблица `user_agents` (персональные копии)

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| id | uuid | да | PK, auto-generated |
| userId | uuid | да | FK → User.id |
| sourceAgentId | uuid | да | FK → agents.id (родительский агент) |
| name | varchar(100) | да | Кастомное имя ("Мой юрист Виктор") |
| customizations | jsonb | нет | Настройки персонализации (см. структуру ниже) |
| isActive | boolean | да | Default true |
| createdAt | timestamp | да | |
| updatedAt | timestamp | да | |

**Индексы:**
- INDEX на `userId`
- INDEX на `sourceAgentId`
- UNIQUE на `(userId, name)` — у одного пользователя не может быть двух агентов с одинаковым именем

### Структура `customizations` (jsonb)

```typescript
type AgentCustomizations = {
  // Стиль общения
  communicationStyle?: "formal" | "friendly" | "brief";
  
  // Обращение к пользователю
  userAddress?: "ты" | "вы" | string; // string для имени
  
  // Специализация (контекст для промпта)
  specialization?: string; // "Договоры аренды", "IT-контракты"
  
  // Контекст пользователя
  userContext?: string; // "Я ИП в Москве", "Работаю в B2B"
  
  // Переопределение промпта (если нужно полное переопределение)
  systemPromptOverride?: string | null;
};
```

### Структура `capabilities` (jsonb)

```typescript
type AgentCapabilities = {
  // Суперсилы — что агент умеет делать лучше всего
  superpowers: string[];
  // Пример: ["Анализ целевой аудитории", "Разработка стратегии", "Позиционирование"]
  
  // Примеры задач — конкретные запросы для вдохновения
  exampleTasks: string[];
  // Пример: ["Проанализируй ЦА для приложения доставки", "Разработай стратегию выхода на B2B"]
  
  // Ограничения — честно о том, что агент НЕ делает
  limitations: string[];
  // Пример: ["Не заменяет профессиональную консультацию", "Требует проверки данных"]
};
```

### Изменения в существующих таблицах

**User:**
- УДАЛИТЬ поле `role` (enum "engineer" | "marketer")

**Chat:**
- ИЗМЕНИТЬ `agentId`: varchar(64) → uuid
- ДОБАВИТЬ FK constraint на `agents.id` или `user_agents.id`

> **Примечание:** `agentId` в Chat может ссылаться как на каталожного агента, так и на персонального. Решение по реализации (два поля или union type) — на усмотрение разработчика.

## 🤖 Миграция агентов

### Агенты для переноса

**Оставляем (type: "catalog"):**

| slug | name | icon | defaultModel | Примечание |
|------|------|------|--------------|------------|
| marketer | Маркетолог | 📊 | gemini-3-pro | Стратегия, аналитика |
| copywriter | Копирайтер | ✍️ | gemini-3-pro | Тексты для соцсетей |
| translator | Переводчик | 🌐 | gemini-3-pro | Перевод с контекстом |
| mentor | Наставник | 📚 | gemini-3-pro | Личностный рост |
| universal | Универсальный | 💬 | gemini-2.5-flash | Общий ассистент |
| presenter | Презентатор | 🎯 | gemini-3-pro | PPTX и веб-презентации |

**Удаляем полностью:**
- Кулинар (🍳) — не нужен для бизнес-платформы
- Астролог (⭐) — не нужен для бизнес-платформы
- Одессит (😄) — не нужен для бизнес-платформы

**Добавляем (type: "system"):**

| slug | name | icon | defaultModel | Примечание |
|------|------|------|--------------|------------|
| helper | Агент-Помощник | 🤝 | gemini-3-pro | Системный, роутер. Реализация в ТЗ-2 |

### Порядок сортировки (sortOrder)

1. helper (системный, всегда первый)
2. universal
3. marketer
4. copywriter
5. translator
6. mentor
7. presenter

### Индикация и смена агента в чате

В шапке чата показывать:
- Иконку агента
- Имя агента
- Кнопка/селектор смены агента

**Смена агента в чате — обязательная функция.**

При смене агента:
- История сообщений сохраняется
- Новые сообщения используют промпт нового агента
- `Chat.agentId` обновляется в БД
- Визуально показать что агент сменился (опционально: разделитель в чате)

**Кейсы использования:**
- Начал с Универсальным → переключился на Презентатора для создания презентации
- Работа в связке: агент для промптов → агент для генерации изображений
- Уточнение задачи: начал общий разговор → понял что нужен специалист

### Создание нового чата

**Из страницы агента:**
1. Клик "Начать чат"
2. Создаётся чат с `agentId` = id агента
3. Редирект в чат
4. Показывается `greeting` агента

**Из sidebar (Агент-Помощник):**
1. Клик на "Агент-Помощник"
2. Создаётся чат с системным агентом
3. Помощник помогает выбрать нужного агента (реализация в ТЗ-2)

## 🔧 Технические требования

### API endpoints

**GET /api/agents**
- Возвращает список активных агентов из каталога
- Сортировка по `sortOrder`
- Для карточек: id, slug, name, icon, description
- Кэширование приветствуется

**GET /api/agents/:slug**
- Возвращает полную информацию об агенте по slug
- Включая `capabilities`, `toolAccess`, `systemPrompt`
- Для страницы `/agents/[slug]`

**GET /api/user-agents**
- Возвращает персональных агентов текущего пользователя
- Требует авторизации

**PATCH /api/chats/:id/agent**
- Меняет агента в существующем чате
- Body: `{ agentId: uuid }`
- Требует авторизации, проверка владельца чата

### Загрузка промпта агента

При отправке сообщения в чат:
1. Получить `agentId` из чата
2. Загрузить агента из БД (agents или user_agents)
3. Если user_agent — проверить `systemPromptOverride`, иначе загрузить промпт родительского агента
4. Применить `customizations` к промпту (если есть)
5. Использовать промпт в запросе к AI

### Seed данные

Создать seed скрипт который:
1. Создаёт всех каталожных агентов с промптами из текущих .md файлов
2. Заполняет `capabilities` для каждого агента
3. Создаёт системного агента helper (промпт пока заглушка)

**Пример заполнения capabilities для Маркетолога:**

```typescript
{
  superpowers: [
    "Анализ целевой аудитории и сегментация",
    "Разработка маркетинговой стратегии",
    "Позиционирование продукта на рынке",
    "Конкурентный анализ"
  ],
  exampleTasks: [
    "Проанализируй целевую аудиторию для приложения доставки еды",
    "Разработай стратегию выхода на рынок B2B",
    "Сравни позиционирование конкурентов в нише фитнес-приложений"
  ],
  limitations: [
    "Не заменяет профессиональную маркетинговую консультацию",
    "Требует проверки данных для принятия важных решений"
  ]
}
```

> **Примечание:** Конкретное содержимое capabilities для каждого агента — на усмотрение разработчика, исходя из промптов и назначения агентов.
