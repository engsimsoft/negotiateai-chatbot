## Философия

Все AI-продукты копируют модель email: много тредов, ищи нужный, создавай новый. Это костыль — компенсация отсутствия памяти. Simply имеет MIND — долговременную память. AI помнит всё между чатами. Множественные чаты не нужны.

**Один ассистент. Один разговор. Всегда.**

Аналогия: KITT из Knight Rider. Не "открываешь новый тред" — просто говоришь с партнёром, который всегда рядом и всё помнит.

## Scope этого ТЗ

Из полной концепции (5 этапов) реализуем **Этап 1: Core** + подготовку к Этапу 2.

### Что входит

1. **Маршрут `/simply`** — один постоянный чат на пользователя
2. **`getOrCreateSimplyChat(userId)`** — детерминистическое создание/получение чата
3. **Главная страница** — ввод ведёт в `/simply`, не создаёт новый чат
4. **Sidebar** — пункт "Simply" вместо "Новый чат" для основного режима
5. **Отключение auto-naming** для chatMode="simply"
6. **Скрытие истории чатов** для chatMode="simply" (оставить для expertise/create)
7. **Категория `idea` в MIND** — новая категория + быстрые команды в промпте
8. **Карточка "Мой контекст"** на главной вместо "История чатов"

### Что НЕ входит (будущие ТЗ)

- Медиатека (правый sidebar с вкладками Документы/Медиа/Ссылки)
- Dashboard "Мой контекст" (7 карточек MIND)
- "Сохранить в Библиотеку" (RAG-4)
- Фокусы по карточкам
- Smart Routing

## Технические решения

### Persistent Chat ID

При первом обращении к `/simply` создаётся один чат с `chatMode: "simply"`. При всех последующих — возвращается тот же чат. Поиск: `WHERE userId = :id AND chatMode = 'simply' LIMIT 1`.

### Хранение сообщений

Без изменений. Message_v2 — отдельная таблица, Token-Aware Sliding Window (200 сообщений, 140K токенов). Compaction API сжимает контекст. Lazy-load для UI скролла — в будущем ТЗ.

### Категория `idea` в MIND

Добавить `idea` в `MEMORY_CATEGORIES`. Обновить промпт извлечения. Быстрые команды в system prompt: "идея: ..." → мгновенное сохранение с подтверждением.
