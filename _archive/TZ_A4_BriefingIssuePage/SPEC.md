# ТЗ-А4: Страница выпуска брифинга

**Цель:** Полноценный UI для чтения статьи — левая панель с навигацией, центр со статьёй, раскрываемые источники, заглушка плеера.

**Версия:** 3.31.0 → 3.32.0

---

## Суть

Заменить минимальный рендер `BriefingActivePage` (из А3) на полноценную страницу чтения. Два маршрута:

- `/briefing` — последний выпуск (или лендинг если нет профиля)
- `/briefing/[date]` — конкретный выпуск по дате

Оба используют один layout и одни компоненты. Разница только в том, какой выпуск загружается.

## Что сделать

### 1. Новый маршрут `/briefing/[date]`

`app/(dashboard)/briefing/[date]/page.tsx` — Server Component.

- Параметр `date` в формате `YYYY-MM-DD`
- Загружает выпуск из `getBriefingHistory({ userId })` по дате (фильтр по `createdAt`)
- Если выпуска за эту дату нет → 404 или redirect на `/briefing`
- Рендерит общий layout с sidebar + article

**Нужен новый query:** `getBriefingByDate({ userId, date })` — возвращает одну запись из briefingHistory по дате.

### 2. Обновить `/briefing` (page.tsx)

Текущая логика (профиль не активен → лендинг, активен → последний выпуск) — сохраняется. Но вместо `BriefingActivePage` рендерит те же компоненты, что и `/briefing/[date]`.

Если есть готовый выпуск → показать его. Если нет выпусков → empty state с кнопкой "Сгенерировать первый брифинг".

### 3. Левая панель — `BriefingSidebar`

Два блока:

**Блок "Сегодня" (навигация по секциям):**
- "Полный брифинг" (скролл в начало)
- Список тем текущего выпуска: `{emoji} {topicName}` — клик → smooth scroll к секции в центре
- Активная тема подсвечивается по мере скролла (IntersectionObserver)

**Блок "Прошлые выпуски" (история):**
- Список дат прошлых выпусков из `getBriefingHistory({ userId, limit: 10 })`
- Каждая дата — ссылка на `/briefing/[date]`
- Текущий выпуск подсвечен

**Внизу панели:**
- "Настройки" — ссылка на `/briefing/setup`

### 4. Центральная область — `BriefingArticleView`

Рендерит `BriefingArticle` как статью для чтения:

**Заглушка плеера (sticky, сверху):**
- Компонент `BriefingPlayerPlaceholder`
- Сообщение: "🎧 Скоро: аудиоподкаст. Плеер появится в следующем обновлении"
- Визуально оформлен, но не функционален. Готовит пользователя к Фазе Б

**Intro:**
- Текст `article.intro` — обычный параграф, чуть крупнее

**Секции:**
- Для каждой `section` в `article.sections`:
  - Заголовок: `{emoji} {topicName}` (с `id` для скролла из sidebar)
  - Контент: `section.content` — markdown → React. Используй `react-markdown` (уже в проекте?) или аналог. Нужна поддержка: абзацы, `**bold**`, `*italic*`, `[ссылки](url)`, заголовки `##` `###`
  - Источники: раскрываемый блок "📰 Источники ({n})" под каждой секцией

**Блок источников (collapsible):**
- По умолчанию свёрнут
- При раскрытии — карточки источников: `sourceName` · `tier badge` · `title` · `summary` · ссылка на оригинал
- Простой дизайн, без лишних украшений

**Outro:**
- Текст `article.outro` — завершающий параграф

**Meta (внизу статьи или в header):**
- "{totalNews} новостей · {topicsCount} тем · {readingTimeMinutes} мин чтения"

### 5. Header

Паттерн из дашборда:

- Кнопка ⚙️ → `/briefing/setup`

## Ключевые UX-решения

**Markdown → React.** Контент секций — markdown с inline-ссылками. Нужен рендерер. Если `react-markdown` уже в проекте — использовать его. Если нет — добавить. Минимальный набор: абзацы, bold, italic, ссылки, заголовки.

**Scroll-to-section.** Клик по теме в sidebar → smooth scroll к секции. Каждая секция имеет `id={section.topicId}`. `IntersectionObserver` на секциях обновляет активную тему в sidebar.

**Источники свёрнуты.** Основной контент — статья. Источники — дополнение для тех кто хочет нырнуть глубже. Свёрнуты по умолчанию.

**Responsive.** На мобильных — sidebar скрыт, только статья. Sidebar доступен через hamburger или sheet.
