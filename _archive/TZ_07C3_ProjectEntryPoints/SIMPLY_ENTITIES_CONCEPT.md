**Версия:** 1.0  
**Дата:** 2026-02-04  
**Статус:** Утверждено (мозговой штурм)  
**Источники:** Итоги #1–4, SIMPLY_PROMPTS_ARCHITECTURE, SIMPLY_PROMPT_PIPELINE, SIMPLY_SKILLS_EXPLAINED, сессия 2026-02-04

## Главная идея

Simply — приложение для работы, не для общения. У Simply три сущности, и каждая **визуально и функционально отличается**. Пользователь чувствует разницу через сам интерфейс, а не через объяснения.

Проблема конкурентов (Claude, ChatGPT): всё выглядит как чат. Проект — чат. GPT — чат. Помощник — чат. Пользователь 55 лет не понимает зачем ему три одинаковых "чата".

В Simply каждая сущность имеет **свой язык взаимодействия**.

---

## Три сущности

### 1. Чат — мессенджер

**Метафора из жизни:** Погуглить вопрос. Спросил — получил — забыл.

**Назначение:** Быстрые вопросы, одноразовые запросы, не требующие глубины и контекста.

**Характер интерфейса:** Классический мессенджер. Поле ввода → сообщение → ответ. Знакомо всем.

**Модели:** Google (Gemini 3 Pro — умная, Gemini 2.5 Flash — быстрая). Дёшево.

**Точка входа:** Поле ввода на Главной. Начал печатать → Enter → попал в чат.

**Что нет:** Нет документов, нет контекста проекта, нет специализации. Чат не знает о пользователе ничего кроме базового профиля.

**Ценность:** Мгновенность. Ноль настройки, ноль подготовки.

---

### 2. Помощник — консультация у специалиста

**Метафора из жизни:** Пришёл в кафе, встретил друга-маркетолога. Он уже эксперт — не нужно объяснять ему что такое маркетинг. Но он не знает деталей твоего бизнеса.

**Назначение:** Экспертная консультация в конкретной области. Мгновенная точка входа без необходимости настраивать контекст.

**Ключевое отличие от чата:** Помощник **уже настроен**. Маркетолог знает российский рынок, инструменты, термины. Копирайтер знает форматы текстов, tone of voice. Пользователь пришёл — сразу работает.

**Аналогия с реальным миром:** У Claude/ChatGPT — один "универсальный специалист", которому сначала нужно объяснить задачу, загрузить документы, настроить контекст. Это как прийти к врачу и начать объяснять ему медицину. В Simply ты идёшь к **конкретному** специалисту: к терапевту, к маркетологу, к юристу. Он уже знает свою область.

**Характер интерфейса:** Консультация (не чат). Выбор темы или формулировка запроса. Визуально отличается от мессенджера.

**Модели:** Anthropic Claude. Два режима работы:
- 🎯 **Эксперт (Sonnet)** — по умолчанию. Слушает, помогает, наводит на мысли, решает задачи
- 🎓 **Профессор (Opus)** — критик и контролёр. Проверяет работу Эксперта, указывает слабые места, утверждает финальный результат

Gemini используется **только** в универсальном чате. Всё остальное — Anthropic. Simply отвечает за качество результата.

**Количество:** Мало, но каждый вылизан. 5 максимум 10 предустановленных. Apple-подход: не магазин из 500 GPTs где 490 мусор.

**Предустановленные помощники (примерный список):**
- 📣 Маркетолог — стратегия, анализ рынка, позиционирование
- ✍️ Копирайтер — тексты, посты, рассылки
- 🌍 Переводчик — переводы с контекстом и адаптацией
- 📊 Аналитик — данные, отчёты, выводы
- 🎓 Наставник — обучение, объяснения, менторство

**Кастомные помощники:** Создаются через Конструктор (отдельный помощник). Пользователь никогда не редактирует промпты напрямую — только через диалог.

**Что нет:** Нет документов проекта, нет RAG. Помощник работает с тем что пользователь сказал в разговоре + загрузил в конкретный чат.

**Ценность:** Скорость входа. Не нужно ничего настраивать, объяснять основы, загружать документы. Пришёл — работаешь.

---

### 3. Проект — офис

**Метафора из жизни:** Ты нанял маркетолога (и копирайтера, и блогера) работать над твоим кафе. Они сидят в офисе, видят все документы, знают контекст, решают конкретные задачи.

**Назначение:** Долгосрочное рабочее пространство с документами, базой знаний, и командой помощников.

**Ключевое отличие от помощника:** В проекте есть документы. Помощники в проекте **видят весь контекст** — инструкцию проекта, загруженные файлы, историю предыдущих задач. Когда маркетолог работает в проекте "Кофейня на Арбате" — он знает что это за кофейня, кто клиенты, какой бюджет. За кофе этого контекста нет.

**Характер интерфейса:** Задачи, не чаты. Пользователь ставит задачу: "Написать контент-план на март", "Проанализировать конкурентов в районе", "Подготовить текст для Instagram". Каждая задача — это по сути диалог с AI, но **названный и оформленный** как задача. Это язык бизнеса, не язык мессенджера.

**Модели:** Claude (Anthropic) через OpenRouter. Три уровня:
- ⚡ Исполнитель (Haiku) — быстрые простые задачи
- 🎯 Эксперт (Sonnet) — баланс, по умолчанию
- 🎓 Профессор (Opus) — сложный reasoning, pipeline

**Что есть:**
- Документы и файлы (загрузка, просмотр, RAG в будущем)
- Паспорт проекта (генерируемый файл с целью, контекстом, помощниками)
- Несколько помощников с доступом к контексту
- Задачи (вместо чатов)

**Ценность:** Глубина. Всё в одном месте: документы, контекст, команда, результаты.

## Связь между помощником и проектом

Помощник на Главной и помощник в проекте — **один и тот же специалист**, но с разным уровнем контекста.

| | Помощник на Главной | Помощник в проекте |
|---|---|---|
| **Метафора** | Друг-маркетолог за кофе | Маркетолог нанятый на проект |
| **Контекст** | Только то что сказано в разговоре | Все документы проекта + инструкция + история |
| **Документы** | Нет | Есть, видит всё |
| **RAG** | Нет | Да (когда реализуем) |
| **Глубина** | Общие советы | Конкретные решения для этого бизнеса |

**Воронка вовлечения:**

```
Чат → "Это серьёзная задача, обратись к Маркетологу"
  ↓
Помощник → "Мне нужно больше информации, давай создадим проект"
  ↓
Проект → глубокая работа с документами и контекстом
```

Переход естественный: помощник сам предлагает создать проект когда видит что задача переросла формат разговора.

## Pipeline качества: Эксперт → Профессор

### Проблема всех AI-сервисов

Модель соглашается с пользователем. Не критикует, не указывает на слабые места, льстит. Пользователь получает ответ который "звучит хорошо", но может быть поверхностным, неполным, или содержать ошибки.

### Решение Simply: двухуровневая проверка

В Simply два уровня работы — и в помощниках, и в проектах:

**🎯 Эксперт (Sonnet)** — рабочая лошадка. Работает по умолчанию. Слушает пользователя, фиксирует идеи, наводит на мысли, выполняет задачи. Комфортный, поддерживающий стиль общения.

**🎓 Профессор (Opus)** — критик и контролёр. Совсем другие инструкции. Должен быть критичным, указывать на недостатки, слабые места, риски. Но не просто критиковать — предлагать как исправить и давать конкретные задания Эксперту.

### Как работает

```
Пользователь ↔ Эксперт (Sonnet)
│   Диалог, консультация, решение задачи.
│   Эксперт помогает, фиксирует, наводит на мысли.
│
↓ Готов результат (план, стратегия, документ, отчёт)
│
Эксперт: "Результат готов. Рекомендую отправить
          на проверку Профессору для критического анализа."
│
↓ Пользователь соглашается
│
Профессор (Opus): Критический анализ
│   — Указывает слабые места и недостатки
│   — Объясняет почему это проблема
│   — Предлагает конкретные решения
│   — Даёт задания Эксперту на доработку
│
↓
│
Эксперт: Исправляет по замечаниям Профессора
│
↓
│
Профессор: Финальная проверка → Утверждение ✅
│
↓
│
Результат идёт в работу
```

### Что видит пользователь

Пользователь видит как два специалиста работают над его задачей. Не просто получил ответ — получил **проверенный** ответ. Для аудитории 40-60+ это понятно и ценно: эксперт сделал работу, профессор проверил.

### Выбор режима работы

Выбор происходит не в настройках, а через диалог с Менеджером проекта или Секретарём помощника при первом обращении:

```
Менеджер: "Как хотите организовать работу?

Вариант 1 — С проверкой Профессором:
Эксперт выполняет задачу, Профессор проверяет и утверждает.
Максимальное качество, стоит дороже.

Вариант 2 — Только Эксперт:
Эксперт работает самостоятельно.
Хорошее качество, экономичнее."
```

Пользователю не нужно разбираться в моделях — ему объясняют на языке ценности результата.

### Позиционирование

**Simply отвечает за результат.** Это не дешёвый доступ к AI. Это сервис, где консультация должна быть на самом высоком уровне, который возможен на сегодняшний день. Хочешь дёшево без гарантий — есть универсальный чат. Хочешь качество — Эксперт. Хочешь гарантию — Профессор.

## Сервисные персонажи

Кроме помощников-специалистов в Simply есть два сервисных персонажа. Они не решают задачи пользователя — они помогают пользоваться платформой.

### Бен — консьерж платформы

**Метафора из жизни:** Консьерж в отеле. Знает всё про отель: где бассейн, как заказать такси, во сколько завтрак. Не решает бизнес-задачи.

**Назначение:** Говорящий мануал Simply. Объясняет что где, помогает разобраться в платформе, проводит онбординг новых пользователей.

**Модель:** Gemini Flash. Дешёвая, быстрая, работает по жёстким сценариям. Бену не нужно думать — нужно быстро найти ответ из базы знаний о Simply.

**Где появляется:** Кнопка ❓ на Главной и в header. Модальное окно (drawer).

**Что знает:**
- Все функции Simply
- Разницу между чатом, помощником и проектом
- Как создать проект, как работать с помощниками
- Рекомендации по первым шагам для новичков

**Что НЕ делает:** Не даёт экспертных советов, не анализирует документы, не пишет тексты.

**Онбординг нового пользователя:**

```
Бен: "Привет! Я Бен, помогу разобраться в Simply."
Бен: "Как тебя зовут?"
→ displayName
Бен: "На ты или на вы удобнее?"
→ pronouns
Бен: "Чем занимаешься?"
→ occupation
Бен: "С чего начнём?"
→ Направляет в нужное место
```

---

### Менеджер проекта — секретарь проекта

**Метафора из жизни:** Секретарь в офисе. Организует пространство, ведёт документацию, помогает навести порядок. Не делает работу специалистов, но без него офис не работает.

**Назначение:** Помочь создать проект (интервью), внести изменения в инструкцию, разобраться с документами, предложить подвести итоги, сделать финальный отчёт из кучи задач.

**Почему нужен отдельный персонаж:** В проекте теперь задачи, а не чаты. Редактирование инструкции проекта, добавление документов, реорганизация — это мета-уровень, не задача. Нужен отдельный канал для "организационных" вопросов.

**Модель:** Claude Sonnet (думающий). Менеджер проекта проводит интервью при создании проекта — нужно понять бизнес пользователя, задать правильные вопросы, уловить суть расплывчатого запроса. Это серьёзная задача, Flash не справится.

**Где появляется:** Кнопка ⚙️ в header проекта. Модальное окно без истории (одноразовые диалоги).

**Что делает:**
- Проводит интервью при создании проекта (вместо формы)
- Вносит изменения в инструкцию и паспорт проекта
- Предлагает подвести итоги когда чатов/задач становится много
- Помогает разобраться с файлами и сделать финальный отчёт
- Критически важен для будущего RAG — организует базу знаний проекта

**Что НЕ делает:** Не решает задачи проекта. Не пишет тексты, не анализирует конкурентов, не делает презентации. Это делают помощники.

**Формат взаимодействия:** Модальное окно, розовые (одноразовые) чаты без истории. Открыл → поговорил → изменения внесены → закрыл.

---

### Секретарь помощника — настройка помощников

**Метафора из жизни:** Когда приходишь к врачу — встречает медсестра. К юристу — секретарь. Они не решают твою проблему, но организуют приём.

**Назначение:** Помочь настроить кастомного помощника. Через диалог (2-3 вопроса) подбирает навыки, пишет инструкцию, даёт название и иконку.

**Где появляется:** При первом клике на помощника (начальная настройка), или по кнопке настройки у кастомного помощника.

**Модель:** Claude Sonnet или Gemini Pro (нужно понять задачу пользователя и правильно сконфигурировать помощника).

**Что делает:**
- Проводит короткое интервью: какая задача, какая ниша, какой стиль
- Подбирает навыки (skills) из библиотеки
- Формирует инструкцию для помощника
- Пользователь никогда не видит и не редактирует промпты напрямую

## Архитектура под капотом

### Skills — книги со знаниями

Атомарные навыки в формате SKILL.md. Инструкции **что делать**: как анализировать конкурентов, как составить контент-план, как работать с Excel.

Skills сами по себе не разговаривают. Они хранят знания.

**Откуда берутся:**
- Готовые от Anthropic (Excel, PowerPoint, PDF) — уже отточены
- Свои для российского рынка (маркетинг, бизнес-консультирование) — уникальность Simply

### Agents (Помощники) — консультанты

Персонажи-дирижёры с набором skills. Определяют **как общаться**: личность, стиль, экспертиза.

Помощник **использует** skills, но добавляет своё общение. Маркетолог берёт skill "competitor-analysis", но ведёт диалог, задаёт уточняющие вопросы, адаптирует результат под конкретную ситуацию пользователя.

### Progressive Disclosure

Помощник не загружает все skills сразу — видит только описания (метаданные). Когда нужен конкретный навык — загружает полное содержимое. Экономия токенов и стоимости.

### Prompt Pipeline

Для сложных задач в проекте:

```
Пользователь → задача
    ↓
Opus-дирижёр (интервью, анализ, декомпозиция)
    ↓
Исполнители (Flash, Perplexity, Plus AI — по ТЗ от Opus)
    ↓
Opus (сборка, проверка качества)
    ↓
Результат
```

Принцип: **умный думает — дешёвый делает**. Opus планирует и проверяет, специализированные модели исполняют.

### Сборка промпта

```
Финальный промпт =
    core/ (базовые правила: base.md, safety.md, formatting.md, russian-market.md)
  + промпт сущности (чат / помощник / проект)
  + динамические контексты (профиль, chat memory, RAG)
  + инструкции к доступным tools
```

| **Чат** | Погуглил вопрос | Быстрый ответ, без контекста | "Это серьёзная задача, обратись к Маркетологу" |
| **Помощник** | Друг-маркетолог за кофе | Экспертная консультация, знает область | "Мне нужно больше информации, давай создадим проект" |
| **Проект** | Нанял команду в офис | Глубокая работа, документы, RAG, задачи | — |

## Ключевые принципы

**Философия продукта:**
- Simply — приложение для работы, не для общения
- Apple-подход: мало элементов, каждый идеален
- "Одна кнопка = решённая проблема"
- Целевая аудитория: 40–60+, без технического фона

**Принципы интерфейса:**
- Каждая сущность визуально отличается (мессенджер / консультация / задачи)
- "Диалог вместо формы" — формы заменяются диалогом с AI
- Пользователь не любит скролл — всё важное на одном экране
- Один паттерн ввода — печатаешь → попадаешь в работу

**Принципы архитектуры:**
- Разделение чатов по контекстам — общие, проектные, помощниковые никогда не смешиваются
- Best-in-Class API — интегрируем лучшие решения, не изобретаем
- Умный думает — дешёвый делает (Opus планирует, Flash исполняет)
- Agent as Translator — помощник переводит с человеческого на язык AI-моделей
- Промпты = контент, Логика = код. Разделены, независимы

## Стоимость и модели

| Персонаж/Сущность | Модель | Провайдер | Обоснование |
|---|---|---|---|
| Чат (универсальный) | Gemini Flash / Pro | Google | Быстрые ответы, дёшево. Единственное место где Google |
| Помощник (Эксперт) | Claude Sonnet | Anthropic | Рабочая лошадка. Качественная работа |
| Помощник (Профессор) | Claude Opus | Anthropic | Критический анализ, утверждение результата |
| Проект (задачи) | Claude Sonnet / Opus | Anthropic | Sonnet по умолчанию, Opus для проверки |
| Бен | Gemini Flash | Google | Жёсткие сценарии, FAQ. Не нужна глубина |
| Менеджер проекта | Claude Sonnet | Anthropic | Интервью, понимание бизнеса |
| Секретарь помощника | Claude Sonnet | Anthropic | Настройка, подбор навыков |

**Принцип распределения моделей:**
- **Google Gemini** — только универсальный чат и Бен. Дёшево, быстро, достаточно для простых задач
- **Anthropic Claude Sonnet** — вся серьёзная работа. Помощники, проекты, сервисные персонажи
- **Anthropic Claude Opus** — только Профессор. Критический анализ и утверждение финального результата

Simply отвечает за качество. Экономия — на чате. Качество — на помощниках и проектах.
