**Дата анализа:** 2026-02-05

## Резюме

Переосмысление точек входа на странице проекта. Проект — это офис, не мессенджер. Вместо поля ввода пользователь видит три осознанных действия: посмотреть историю задач, создать новую задачу, обратиться к Менеджеру проекта (секретарю офиса).

---

## Контекст (из SIMPLY_ENTITIES_CONCEPT)

**Менеджер проекта** — секретарь офиса:
- Не решает задачи пользователя (это делают помощники-специалисты)
- Организует пространство: документы, инструкции, итоги
- Модель: Claude Sonnet
- Формат: модальное окно, "розовые чаты" без истории

**Проект** — язык задач, не мессенджера:
- Пользователь ставит задачу, не "пишет сообщение"
- Каждая задача — диалог с AI, но оформленный как рабочий процесс

## Вопросы для уточнения

1. **[История задач]:** Сейчас карточка показывается только если `tasksCount > 0`. В новом дизайне:
   - **А)** Всегда показывать все 3 карточки (История задач с "0 задач")
   - **Б)** Скрывать "История задач" если задач нет (показывать 2 карточки)

2. **[Мобильная адаптация]:** На мобильных 3 карточки в ряд не поместятся:
   - **А)** Вертикальный стэк (друг под другом)
   - **Б)** Горизонтальный скролл
   - **В)** 2+1 (две сверху, одна снизу)

3. **[Иконка Менеджера]:** В ТЗ написано "👤 Менеджер". Использовать:
   - **А)** Эмодзи 👤
   - **Б)** Lucide icon (UserCog, Settings, Briefcase?)
   - **В)** Свою иконку

## План реализации (черновик)

### Этап 1: Карточки действий
1. Создать `NewTaskCard` — Link на `/projects/${projectId}/chat`
2. Создать `ManagerCard` — открывает Dialog
3. Обновить страницу проекта — убрать ProjectInput, добавить карточки

### Этап 2: Модалка Менеджера
1. Создать `ManagerDialog` с 4 карточками действий (заглушка)
2. Карточки визуально кликабельны но неактивны (opacity/disabled)
3. Поле ввода внизу заблокировано
4. Текст "Менеджер проекта появится в ближайшем обновлении"
