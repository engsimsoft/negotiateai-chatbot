# ТЗ для Claude Code: Интеграция промпта Секретаря

**Дата:** 2026-02-07  
**Задача:** Заменить текущий промпт Секретаря на новый из SECRETARY_PROMPT.md  
**Связано с:** ADR 012 (context/instruction разделение)

---

## Что сделать

### 1. Найти текущий промпт секретаря

Текущий промпт для service-chat секретаря находится в одном из этих мест (проверить по кодовой базе):
- `app/(chat)/api/service-chat/route.ts` — inline system prompt
- `lib/prompts/` — отдельный файл промпта
- Поиск по коду: `updateProjectDraft`, `service-chat`, `secretary`, `создание проекта`

### 2. Заменить промпт

Взять содержимое блока ```xml ... ``` из файла `SECRETARY_PROMPT.md` (раздел «Промпт») — это и есть полный system prompt.

**Динамические переменные** которые нужно подставлять:
- `{{displayName}}` — имя пользователя из профиля
- `{{pronouns}}` — «ты» или «вы» из настроек пользователя  
- `{{occupation}}` — сфера деятельности из профиля
- `{{bio}}` — дополнительная информация о пользователе из профиля

Если какое-то поле пустое — не подставлять placeholder, просто убрать строку из блока `<user_context>`.

### 3. Убедиться что tool updateProjectDraft соответствует

После ADR 012 tool должен принимать параметры:
```
updateProjectDraft({
  name?: string,
  description?: string,
  context?: string       // было instruction, стало context
})
```

Проверить что описание tool для модели (function definition / tool description) соответствует:
- `name` — «Название проекта»
- `description` — «Описание проекта»
- `context` — «Контекст проекта: справка о бизнесе, аудитории и целях»

### 4. UI: проверить лейблы на панели слева

На экране создания проекта (левая панель «Паспорт проекта») три поля:
- «Название» → соответствует `name`
- «Описание» → соответствует `description`
- Третье поле должно называться **«Контекст проекта»** → соответствует `context`

Если после ADR 012 третье поле уже переименовано — проверить. Если нет — переименовать.

## Мануальное тестирование

### Подготовка

1. Открыть экран создания проекта
2. Убедиться что профиль пользователя заполнен (имя, обращение ты/вы, сфера деятельности)
3. Открыть DevTools → Network для отслеживания вызовов tool

### Тест 1: Стандартный диалог

**Ввод:** «У меня кофейня на Арбате, хочу заняться маркетингом»

**Ожидается:**
- ✅ Секретарь здоровается по имени (из профиля)
- ✅ Не повторяет то что пользователь сказал
- ✅ Задаёт 1-2 уточняющих вопроса (про клиентов, каналы)
- ✅ Вызывает updateProjectDraft — поля заполняются на панели слева
- ✅ В поле context — текст от третьего лица, только факты
- ✅ Нет эмодзи (кроме возможного одного при приветствии)
- ✅ Нет дублирования паспорта текстом в чате

### Тест 2: Много информации сразу

**Ввод:** «Мне нужно подготовить бизнес-план для инвестора. У меня сеть салонов красоты в Казани, 4 точки, хотим открыть пятую в новом ЖК. Нужна презентация с финансовыми показателями.»

**Ожидается:**
- ✅ Секретарь НЕ задаёт лишних вопросов — информации достаточно
- ✅ Сразу заполняет все три поля одним вызовом tool
- ✅ Предлагает посмотреть паспорт и создать проект
- ✅ Даёт подсказку про загрузку документов (пользователь упомянул финансовые показатели)

### Тест 3: Размытый запрос

**Ввод:** «Хочу что-то с маркетингом»

**Ожидается:**
- ✅ Секретарь задаёт конкретный уточняющий вопрос (не «что вы имеете в виду?», а «у вас уже есть бизнес или только планируете?»)
- ✅ Не предлагает варианты на выбор
- ✅ После 2-3 вопросов формирует паспорт с тем что есть
- ✅ Общее количество вопросов ≤ 4

### Тест 4: Вопрос не по теме

**Ввод (после начала диалога):** «А как лучше продвигать кофейню — через таргет или контент?»

**Ожидается:**
- ✅ Секретарь НЕ даёт экспертный ответ
- ✅ Говорит что-то вроде: «Это отличный вопрос — в проекте с ним поможет эксперт. А пока давайте оформим паспорт.»
- ✅ Возвращает разговор к оформлению

### Тест 5: Голосовой ввод (разговорный стиль)

**Ввод:** «ну короче у меня это самое автосервис есть в краснодаре на окраине и вот клиентов мало надо как-то привлекать не знаю может рекламу какую сделать»

**Ожидается:**
- ✅ Секретарь нормально воспринимает разговорный стиль
- ✅ Не просит «сформулировать точнее»
- ✅ Вычленяет суть: автосервис, Краснодар, мало клиентов, нужна реклама
- ✅ Формирует аккуратный паспорт из этого потока

### Тест 6: Обращение ты/вы

**Подготовка:** Переключить pronouns в профиле

**Ожидается:**
- ✅ При pronouns = «ты» → обращается на «ты»: «Расскажи, какой проект хочешь создать?»
- ✅ При pronouns = «вы» → обращается на «вы»: «Расскажите, какой проект хотите создать?»
- ✅ Обращение consistent на протяжении всего диалога

### Тест 7: Подсказки после оформления (Акт 2)

**Проверить на разных сценариях:**
- ✅ Пользователь упомянул документы → подсказка про менеджера и файлы
- ✅ Пользователь не уверен с чего начать → подсказка про менеджера и разбивку на шаги
- ✅ Пользователь выглядит неуверенно или новичок → упоминание Бена (кнопка ❓) для вопросов по платформе
- ✅ Масштабная задача → подсказка про уровни AI
- ✅ Подсказка звучит по-человечески, не как реклама

### Тест 8: Минимум информации

**Ввод:** «Проект» (и ничего больше)
**Затем:** отвечать односложно или не по делу

**Ожидается:**
- ✅ Секретарь пытается уточнить (2-3 вопроса)
- ✅ Если информации всё равно мало — заполняет паспорт тем что есть
- ✅ Говорит что паспорт можно дополнить позже
- ✅ Не зацикливается на попытках вытянуть информацию

## Чек-лист качества (для каждого теста)

| Критерий | Проверка |
|---|---|
| Обращение по имени | Используется displayName из профиля |
| Тон | Дружелюбный, не формальный, не панибратский |
| Вопросы | Конкретные, по контексту, ≤4 за диалог |
| Tool вызовы | Поля заполняются, live preview работает |
| context | От третьего лица, только факты, не додумывает |
| Нет дублирования | Черновик не повторяется текстом в чате |
| Нет вариантов | Одно название, не три на выбор |
| Нет техтерминов | «Системный промпт», «модель», «нейросеть» не упоминаются |
| Акт 2 | После паспорта — полезная подсказка по контексту |
| Запреты | Не даёт экспертных советов, не анализирует, не извиняется |
