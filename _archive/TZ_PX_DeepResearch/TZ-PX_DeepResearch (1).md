**Версия:** 3.28.0  
**Зависимости:** нет  
**Приоритет:** 🔴 Блокирует ТЗ-А2 (онбординг брифинга)

## Цель

Подключить Perplexity Sonar как новый инструмент платформы `deepResearch`. Два режима глубины: Pro (быстрый мультишаговый поиск) и Deep Research (исчерпывающий ресёрч). В dev-режиме — UI-переключатель для ручного тестирования обоих вариантов. В продакшне переключатель скрыт, логика выбора определится по результатам тестов.

Инструмент нужен не только для брифинга — это core capability для режима Экспертиза, Проектов и Создать.

---

## Архитектура

### Один tool, два режима

```
deepResearch({ query, depth: "pro" | "deep" })
```

**Sonar Pro** (`depth: "pro"`):
- 3-5 поисковых шагов, multi-step reasoning
- Время ответа: 5-15 секунд
- Стоимость: ~$0.02/запрос
- Для: поиск источников, анализ темы, фактчекинг

**Sonar Deep Research** (`depth: "deep"`):
- 20-30 поисковых шагов, исчерпывающий ресёрч
- Время ответа: 30-120 секунд
- Стоимость: ~$0.80/запрос
- Для: нишевые темы, сравнительный анализ, глубокое исследование

### API

Perplexity API совместим с форматом OpenAI Chat Completions:

```
POST https://api.perplexity.ai/chat/completions
Authorization: Bearer <PERPLEXITY_API_KEY>

{
  "model": "sonar-pro" | "sonar-deep-research",
  "messages": [{ "role": "user", "content": "..." }]
}
```

Ответ содержит:
- `choices[0].message.content` — текст ответа
- `citations` — массив URL-источников
- `search_results` — результаты поиска с title, url, snippet
- `usage` — токены, количество search queries, стоимость

### Env variable

```
PERPLEXITY_API_KEY=pplx-...
```

## Реализация tool

### Файл: `lib/ai/tools/deep-research.ts`

По паттерну существующего `web-search.ts`:
- Vercel AI SDK `tool()` с `wrapToolExecution`
- inputSchema: `query` (string) + `depth` ("pro" | "deep")
- Таймаут: 30 сек для Pro, 180 сек для Deep Research
- Возвращает: текст ответа, массив цитат (url + title), usage stats
- Авто-детект языка запроса (кириллица → ru)

### Регистрация

В `chat-tools.ts` → `getStandardTools()`:
- Добавить `deepResearch` в общий набор инструментов
- Добавить в `getActiveToolNames()`

### Доступность по режимам

| Режим | deepResearch |
|-------|-------------|
| Chat (Haiku) | ❌ Не доступен |
| Экспертиза (Sonnet) | ✅ |
| Создать (Sonnet) | ✅ |
| Проекты (Sonnet/Opus) | ✅ |
| Service chats (онбординг брифинга) | ✅ |

Фильтрация по `chatMode` в `getActiveToolNames()` — deepResearch исключается для `chatMode: 'chat'`.

## Dev-режим: переключатель глубины

### Что делаем

В dev-режиме (`NODE_ENV === 'development'` или feature flag) в UI чата появляется переключатель, позволяющий вручную задать глубину deep research для следующего запроса.

### Где в UI

Рядом с полем ввода сообщения (input area) — компактный переключатель или dropdown:
```
[Pro ▾]  или  [Pro | Deep]
```

Видим только в dev-режиме. В продакшне — скрыт, значение по умолчанию (Pro или авто).

### Как передаётся

Клиент передаёт `depth` preference как часть запроса (например в metadata или через отдельный header/param). Tool получает этот preference и использует соответствующую модель Perplexity.

Конкретная реализация передачи — на усмотрение Claude Code. Важно: значение должно доходить до tool и переключать модель Perplexity.

## Tool description (от PE)

Текст для `description` в `tool()` — модель по нему решает вызывать или нет:

```
Глубокое исследование темы через Perplexity. Используй вместо webSearch когда:
- Нужен мультишаговый анализ (не один факт, а картина целиком)
- Тема требует синтеза из множества источников
- Пользователь просит "исследовать", "проанализировать рынок", "сравнить варианты"
- Простой поиск не даст достаточно глубокого ответа

НЕ используй для: простых фактов, погоды, курсов валют, быстрых справок — для этого webSearch.

Параметр depth:
- "pro" — быстрый мультишаговый поиск (5-15 сек). По умолчанию.
- "deep" — исчерпывающее исследование (30-120 сек). Только когда пользователь явно просит глубокий анализ или тема нишевая/сложная.
```

## Связка с fetchUrl (ТЗ-FU)

`deepResearch` работает в паре с `fetchUrl` (отдельный tool, отдельное ТЗ). Вместе они закрывают полный цикл исследования:

- `fetchUrl` — заходит по ссылке, читает содержимое страницы, возвращает текст. Анализ содержимого делает сама модель — отдельный `analyzeWebsite` tool не нужен, это лишняя сущность.
- `deepResearch` — ищет и синтезирует информацию по теме из множества источников.

### Цепочка работы (пример: онбординг брифинга)

```
Пользователь даёт ссылку на f1news.ru
        ↓
fetchUrl → агент читает сайт, понимает что это агрегатор
        ↓
deepResearch("лучшие аналитики Формулы-1 первоисточники")
        ↓
fetchUrl → агент проверяет найденные источники (реальные? живые? качественные?)
        ↓
Предлагает пользователю: "Вот что нашёл, это лучше потому что..."
```

Когда оба tool подключены — PE пишет промпт онбординга.
