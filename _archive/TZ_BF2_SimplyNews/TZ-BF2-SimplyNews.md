# ТЗ-BF2: Новости Simply — встроенный канал коммуникации

**Приоритет:** Средний (после ТЗ-BF1)  
**Зависимость:** ТЗ-BF1 (sidebar уже обновлён)  
**Оценка:** 1 ТЗ, лёгкая сложность

---

## Зачем

Нужен канал связи с пользователями без email-рассылок и Telegram. Брифинг — идеальное место: пользователь уже читает его каждое утро. Одна механика решает три задачи:
- **Changelog** — пользователь узнаёт о новых фичах
- **Онбординг** — знакомство с платформой в привычном формате article reader
- **Промо брифинга** — даже пользователь без настроенного брифинга увидит индикатор на карточке, зайдёт и познакомится с форматом

## Что делаем

### 1. Два markdown-файла — источники контента

**`lib/briefing/simply-overview.md`** — обзор платформы Simply:
- Что такое Simply, как пользоваться, что умеет
- Живёт постоянно, обновляется редко
- Формат: обычный markdown, рендерится тем же article reader

**`lib/briefing/simply-news.md`** — текущее обновление:
```markdown
---
version: "3.39.0"
date: "2026-02-22"
hasUpdate: true
title: "Сохраняйте интересные темы"
---

Теперь в брифинге можно сохранять отдельные темы закладкой...
```

Обновил файл → задеплоил → все видят. Без CMS, без БД, без админки.

### 2. Секция «Simply» в sidebar брифинга

Постоянная секция внизу sidebar (после «Сохранённые» из BF1):

```
SIMPLY
  📋 Обзор платформы
  🆕 Что нового в v3.39.0    ← только когда hasUpdate: true
```

Клик → article reader с контентом из соответствующего markdown-файла.

### 3. Индикатор на карточке дашборда

Для **всех** пользователей, включая тех, кто не настраивал брифинг:

- `hasUpdate: true` в simply-news.md + пользователь не видел эту версию → бейдж/точка на карточке брифинга
- Клик → страница брифинга → сразу видит новость Simply
- После просмотра индикатор гаснет

**Хранение состояния:** поле `lastSeenSimplyVersion` в `briefingSettings`. Для пользователей без briefingSettings — считать что не видели (показывать индикатор).

### 4. Инъекция в генерацию брифинга

При генерации обычного брифинга:
- Если `hasUpdate: true` → добавить новость Simply как **последнюю секцию** статьи автоматически
- Секция с особым topicId (например `simply_news`), emoji 🔔, не участвует в фильтрации/AI
- Контент берётся напрямую из markdown-файла
- Если у пользователя нет своих тем — брифинг = только новость Simply

---

## Чего НЕ делаем

- Не создаём CMS или админку для новостей — markdown в репозитории
- Не делаем push-уведомления
- Не трогаем существующую логику генерации (только добавляем секцию в конец)
