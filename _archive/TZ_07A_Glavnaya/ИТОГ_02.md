# Итог #2 — Universal Dialog Component и архитектура Dashboard

**Дата:** 2026-02-03  
**Чат:** Проработка интерфейса: Dashboard, создание проектов, помощники  
**Предыдущий итог:** Итог #1 (Новая архитектура интерфейса Simply)  

---

## Контекст

Продолжение мозгового штурма по UI. Отталкивались от Итога #1 (Dashboard как хаб, воронка Чат→Помощник→Проект, "диалог вместо формы"). Задача — превратить принципы в конкретную архитектуру: как именно пользователь создаёт проект, как настраивает помощников, как это всё выглядит в интерфейсе. Анализировали референс Anthropic Cowork.

---

## Принятые решения

### 1. Simply — сущность платформы, не персонаж

Simply — это сама платформа, говорящая с пользователем в ключевых моментах. Не путать с Беном.

| Сущность | Роль | Аналогия |
|---|---|---|
| **Бен** | Консьерж, говорящий мануал | Консьерж в отеле — объясняет где что |
| **Simply** | Управляющий, создаёт и настраивает | Управляющий отелем — подбирает номер и сервисы |

Simply используется для: создания проектов, настройки помощников, редактирования проекта. Модель — Opus (для создания проектов, где нужно понять сложный запрос и подобрать навыки).

### 2. Universal Dialog Component — ключевое архитектурное решение

**Один компонент**, который появляется везде, где раньше была форма или экран настроек. Внутри — всегда чат с Simply. Снаружи — визуально одинаков. Компонент знает контекст вызова через проп `context`.

| Откуда вызван | Simply знает | Результат |
|---|---|---|
| "+ Новый проект" на Dashboard | Профиль пользователя | Создан проект + паспорт |
| ⚙️ на странице проекта | Текущий проект, его файлы, помощников | Обновлён паспорт |
| Первый клик на помощника | Какой помощник, профиль пользователя | Настроен помощник |
| "Подключи аналитика" из чата | Проект + контекст разговора | Помощник добавлен |

**Принцип:** Пользователь выучивает один паттерн ("открылось окно — говорю что нужно") и использует его везде. Человек 60 лет понимает с первого раза.

**Это архитектурное решение, а не фича.** Компонент закладывается в фундамент сразу, даже если в MVP используется только для одного сценария. Иначе — переписывание потом.

### 3. Создание проекта — Вариант 2 (полноэкранный диалог)

Рассмотрены три варианта:

| Вариант | Описание | Вердикт |
|---|---|---|
| 1. Slide-over (drawer) | Панель справа 40-50% экрана | Тесно для сложного диалога |
| **2. Полноэкранный диалог** | Отдельный чистый экран, фокус на разговоре | **✅ MVP** |
| 3. Гибрид (внутри проекта) | Чат внутри пустого проекта, панели наполняются live | Цель для v2, сложная реализация |

**Flow Варианта 2:**
1. Пользователь на Dashboard нажимает "+ Новый проект"
2. Плавный переход на полноэкранный диалог (минимум UI: кнопка "← Dashboard", надпись "Новый проект")
3. Simply задаёт 2-3 вопроса (уже знает имя и сферу из профиля — не переспрашивает)
4. По завершении — карточка-резюме: название проекта, инструкция, подключённые помощники, паспорт проекта (файл)
5. Две кнопки: "Открыть проект →" и "На Dashboard"
6. Возврат на Dashboard, новая карточка проекта появилась

**Создан интерактивный прототип** (React/JSX артефакт) демонстрирующий полный flow.

### 4. Паспорт проекта — генерируемый файл

По аналогии с Project Memory в Claude (скриншот из claude.ai). Simply создаёт файл-документ и размещает его в проекте. Содержит: цель, контекст, подключённые помощники, инструкцию. Обновляется при изменениях через Universal Dialog.

### 5. Два типа генерируемых документов

| Документ | Где живёт | Что содержит |
|---|---|---|
| Паспорт проекта | Внутри проекта | Цель, контекст, помощники, инструкция |
| Профиль помощника | Глобально | Специализация, навыки, настройки пользователя |

### 6. Три точки входа в диалог

- **"+ Новый проект"** на Dashboard → полноэкранный диалог → проект создан
- **Первый клик на помощника** на Dashboard → короткий диалог настройки (страна, ниша, специфика)
- **Помощник предлагает проект** из чата → "Создать проект?" → одна кнопка

### 7. Scope для MVP

| Сценарий | MVP | Позже |
|---|---|---|
| Создание проекта через диалог | ✅ Universal Dialog + Opus | — |
| Настройка помощника | Короткий wizard (2-3 экрана) | Universal Dialog |
| Редактирование проекта | Карточка-резюме + ✏️ | Universal Dialog |
| Добавление помощника в проект | Из чата текстом | Universal Dialog |

## Ключевые идеи

- **Universal Dialog Component** — один паттерн для всего. Форма заменяется диалогом. Компонент один, контексты разные. Закладывается в архитектуру сразу
- **Разница с Cowork:** у Anthropic пользователь должен разобраться в интерфейсе (папки, контексты, прогресс, Working folder). У Simply пользователь говорит что нужно, Simply разбирается сам
- **Knowledge Bases** — новая фича Anthropic (обнаружена в ходе обсуждения). Topic-specific persistent repositories, которые Claude обновляет автоматически. Валидирует направление Simply (RAG + Chat Memory). Пока не выкатили полностью, баннер "not enabled" виден в UI
- **Проверка инструкции "Подведи итог"** — работает корректно, новый чат точно определил следующий шаг (страница проекта), а не ушёл в sidebar/кнопки как раньше

## Критический анализ (выявленные риски)

| Риск | Описание | Митигация |
|---|---|---|
| **Стоимость Opus** | Universal Dialog на каждый чих = дорого | Opus только для создания проекта. Настройка помощников — Sonnet/Haiku |
| **Диалог медленнее формы для опытных** | Пятый проект — пользователь знает что хочет, диалог раздражает | Нужен escape hatch "быстрое создание" в будущем |
| **Качество промпта** | Весь UX зависит от того, что Simply спрашивает правильные вопросы | Месяцы итераций. Один из самых сложных промптов в системе |
| **Откат в диалоге** | Передумал на полпути — как вернуться? | Нужен механизм "давай сначала" внутри диалога |
| **Устаревание паспорта** | Проект меняется, паспорт — нет | Автообновление (сложно) или напоминание пользователю |

## Отклонённые варианты

| Вариант | Почему отклонён |
|---|---|
| Slide-over drawer для создания проекта | Мало места для полноценного диалога и карточки-резюме |
| Диалог внутри пустого проекта (Вариант 3) | Слишком сложная реализация для MVP. Цель для v2 |
| Cowork-подобный подход (папки, Working folder) | Слишком сложный для целевой аудитории 40-60+. Мы сами не разобрались |
| Opus для всех контекстов Universal Dialog | Дорого. Разные контексты — разные модели |
| Universal Dialog для всего в MVP | Риск качества промпта. В MVP только создание проекта |
