# ТЗ-07A: Главная + Навигация + Sidebar + Universal Dialog

**Версия:** 1.1 (обновлено по результатам ревью Claude Code)  
**Дата:** 2026-02-03  
**Для:** Claude Code (VS Code)  
**Базовая версия проекта:** 3.3.3  

---

## Цель

Перестроить интерфейс Simply: новая Главная страница, линейная навигация, контекстный sidebar без табов, и Universal Dialog Component для создания проектов через диалог с AI.

**Результат:** пользователь открывает Simply → видит Главную с полем ввода → начинает печатать и попадает в чат → или кликает на проект/помощника → внутри видит sidebar с чатами текущего контекста.

---

## Контекст

### Что не так сейчас
- Dashboard слишком простой (две карточки)
- Sidebar с тремя табами (Search, Chats, Projects) — избыточен, Search не работает
- Projects непоследовательно между layout-ами
- Нет единого паттерна входа в чат
- Создание проекта — обычная форма вместо диалога

### Что должно быть
- Главная как хаб: поле ввода + проекты + помощники + инструменты
- Один паттерн: печатаешь → попадаешь в чат (работает на Главной и на странице проекта)
- Sidebar показывает только чаты текущего контекста, без табов
- Проект создаётся через диалог с Simply (AI на Opus)

### Референсы
- Прототип Главной: `simply-glavnaya-wireframe.jsx` (приложен к проекту)
- Прототип страницы проекта: `simply-project-page.jsx` (приложен к проекту)
- Итоги мозговых штурмов: `ИТОГ_02.md`, `ИТОГ_03.md`

## Часть 1. Главная

### Переименование
Dashboard → **Главная**. Во всех местах: роутинг, компоненты, тексты, breadcrumbs.

### Layout Главной

Сверху вниз, по приоритету внимания:

**1. Приветствие + поле ввода**
- "Добрый день/вечер, [Имя]!" — с учётом времени суток
- Под ним: "Чем могу помочь?"
- Поле ввода с кнопками: 🎤 (голос), 📎 (файлы), → (отправить)
- Начал печатать → Enter → переход в `/chat` с текстом как первым сообщением
- Это **главный элемент страницы** — крупный, с фокусом

**2. Секция "Проекты"**
- Заголовок "ПРОЕКТЫ" + счётчик
- Карточки существующих проектов: эмодзи, название, кол-во чатов, когда обновлён
- Карточка "+ Новый проект" (dashed border) → запускает Universal Dialog (Часть 4)
- Если проектов нет — только кнопка создания с подсказкой

**3. Секция "Помощники"**
- Заголовок "ПОМОЩНИКИ" + счётчик
- Сначала кастомные помощники (с тегом "свой", выделенный фон)
- Потом предустановленные: Маркетолог, Копирайтер, Переводчик, Аналитик, Наставник (+ остальные из БД)
- Карточка "🛠️ Конструктор" — создание кастомного помощника
- Клик на помощника → переход в чат с этим помощником (предустановленный промпт и навыки)

**4. Секция "Инструменты"**
- Заголовок "ИНСТРУМЕНТЫ"
- Карточки: 🎙️ Диктофон, 🔍 Исследование, ☀️ Брифинг
- Пока неактивные инструменты можно показать с пометкой "Скоро"

### Карточка "💬 Чат" — убирается
Поле ввода на Главной полностью заменяет отдельную карточку чата.

### Header Главной
- Лого "Simply" слева
- Кнопка "❓ Бен" + аватар пользователя справа
- Sidebar на Главной **отсутствует**

## Часть 2. Навигация

### Модель
Линейная цепочка. Каждый экран знает одного родителя. Кнопка "← Назад" всегда ведёт к родителю.

```
Главная
├── Чат (Gemini)                    ← через поле ввода на Главной
├── Проект → Чат в проекте (Claude) ← два уровня
├── Помощник → Чат с помощником     ← два уровня
└── Инструмент                      ← каждый своё
```

### Breadcrumbs
В header каждого экрана — путь с кликабельными сегментами:

| Экран | Breadcrumb |
|---|---|
| Универсальный чат | `← Главная` |
| Страница проекта | `← Главная / 📊 Стратегия 2026` |
| Чат в проекте | `← Главная / 📊 Стратегия 2026 / Анализ конкурентов` |
| Чат с помощником | `← Главная / 📣 Маркетолог / Стратегия Q2` |
| Настройки | `← Главная / Настройки` |

Клик на любой сегмент — переход на тот уровень.

### Маршруты

Рекомендуемая структура (можно адаптировать под текущий роутинг):

```
/                     → Главная
/chat                 → Новый чат (Gemini)
/chat/[id]            → Существующий чат
/projects/[id]        → Страница проекта
/projects/[id]/chat   → Новый чат в проекте
/projects/[id]/chat/[chatId] → Существующий чат в проекте
/helpers/[id]         → Чаты помощника (или сразу новый чат)
/helpers/[id]/chat/[chatId]  → Существующий чат с помощником
/settings             → Настройки
```

### Помощник = чат с предустановкой
Помощник — не отдельная сущность. Это вход в чат с фиксированной инструкцией и навыками. У помощника:
- Список его чатов (отображается в sidebar)
- Возможность начать новый чат
- Загрузка файлов в чат (стандартный функционал)

Решение по хранению и модели данных помощников — на усмотрение, но учесть: предустановленные (из файловой системы, как agents/skills) и кастомные (из БД, созданные через Конструктор).

> **Примечание:** Конструктор кастомных помощников не входит в скоуп этого ТЗ, но архитектуру под него (таблица Helper в БД, helperId в Chat) заложить сейчас.

## Часть 3. Sidebar

### Принцип
Sidebar присутствует **только в рабочих пространствах** (чат, проект-чат, помощник-чат). На Главной, на странице проекта и в настройках sidebar **отсутствует**.

### Без табов
Текущие три таба (Search, Chats, Projects) и компонент `sidebar-tabs.tsx` — убираются. Sidebar содержит **один список чатов текущего контекста**.

### Контекстное содержимое

| Где пользователь | Sidebar показывает |
|---|---|
| Универсальный чат `/chat/*` | Общие чаты (Gemini) |
| Чат в проекте `/projects/[id]/chat/*` | Чаты этого проекта |
| Чат с помощником `/helpers/[id]/*` | Чаты этого помощника |

### Элементы sidebar
- **Кнопка "+ Новый чат"** сверху — создаёт чат в текущем контексте
- **Список чатов** — название, дата обновления
- **Меню чата** (⋯ или правый клик): "Переименовать", "Удалить"
- Удаление — с подтверждением ("Удалить чат? Это действие нельзя отменить")
- Sidebar сворачивается/разворачивается (текущее поведение сохранить)

### Автонейминг чатов

| Момент | Название чата |
|---|---|
| Создан | "Новый чат" |
| После 2-3 обменов сообщениями | AI генерирует название по теме разговора |
| Пользователь переименовал вручную | Его название навсегда, автонейминг отключается |

Модель для нейминга — Gemini Flash или Haiku (дешёвая операция, не блокирует UI). Инструкция: "Прочитай диалог. Дай короткое название на русском (2-4 слова), отражающее суть задачи. Без глаголов. Примеры: 'Анализ конкурентов', 'Бюджет Q1', 'Контент-план VK'."

Автонейминг вызывается **после получения 2-го ответа AI** (к этому моменту тема ясна). Не блокирует чат — работает в фоне, обновляет название в sidebar.

Поле в БД (или где хранятся чаты): флаг `isRenamed` (boolean) — если true, автонейминг не срабатывает.

## Часть 4. Universal Dialog Component

### Что это
Единый компонент, который появляется везде, где раньше была форма или экран настроек. Внутри — всегда чат с Simply (AI-сущность платформы, не путать с Беном). Компонент знает контекст вызова.

**Это архитектурное решение.** Компонент закладывается в фундамент как переиспользуемый, даже если в MVP используется только для одного сценария.

### MVP scope: создание проекта

В этом ТЗ реализуется **только один сценарий** — создание проекта через диалог:

1. Пользователь на Главной нажимает "+ Новый проект"
2. Переход на **полноэкранный диалог** (отдельный чистый экран)
3. Минимум UI: кнопка "← Главная", надпись "Новый проект"
4. Simply задаёт 2-3 вопроса о проекте (уже знает имя и сферу из профиля — не переспрашивает)
5. По завершении — **карточка-резюме**: название проекта, инструкция, подключённые помощники, паспорт
6. Две кнопки: "Открыть проект →" и "На Главную"
7. Проект создан, карточка появилась на Главной

### Simply — сущность платформы

| Сущность | Роль | Когда используется |
|---|---|---|
| **Бен** | Консьерж, объясняет где что | Вопросы о платформе, онбординг |
| **Simply** | Управляющий, создаёт и настраивает | Создание проектов, настройка помощников |

Simply для создания проектов работает на **Opus** (нужно понять сложный запрос и подобрать навыки).

### Компонент Universal Dialog

Проп `context` определяет поведение:

```typescript
// Пример API (реализацию определить на месте)
type UniversalDialogContext = 
  | { type: 'create-project'; userProfile: UserProfile }
  | { type: 'edit-project'; project: Project }     // будущее
  | { type: 'setup-helper'; helper: Helper }        // будущее
```

Компонент должен быть переиспользуемым: один и тот же чат-интерфейс, разные контексты, разные промпты.

### Паспорт проекта

По завершении диалога Simply генерирует **паспорт проекта** — файл-документ, размещаемый в проекте. Содержит:
- Название проекта
- Цель
- Контекст
- Подключённые помощники
- Инструкция для AI

Паспорт используется как часть system prompt при работе в чатах проекта.

### Маршрут

```
/projects/new         → Полноэкранный диалог создания проекта (Universal Dialog)
```

### Стартовый промпт Simply (для создания проекта)

```markdown
# Simply — Управляющий платформой

Ты — Simply, AI-сущность платформы. Твоя роль — помогать пользователю 
создавать рабочие пространства (проекты).

## Что тебе известно
- Имя пользователя: {{userName}}
- Сфера деятельности: {{userOccupation}}
- Контекст из профиля: {{userBio}}

## Правила диалога
- НЕ переспрашивай то, что уже знаешь из профиля
- Задай 2-3 коротких вопроса, чтобы понять задачу
- Говори на "ты" или "вы" в зависимости от {{userPronouns}}
- Будь конкретным, не расплывчатым

## Что нужно выяснить
1. Какую задачу пользователь хочет решить?
2. Есть ли дедлайн, контекст или ограничения?
3. Какие помощники будут полезны? (предложи из доступных)

## Результат
После сбора информации сгенерируй:
- Название проекта (2-4 слова, с эмодзи)
- Цель (1-2 предложения)
- Контекст (что важно учитывать)
- Инструкция для AI (как работать в рамках этого проекта)
- Рекомендуемые помощники (из доступных)

Покажи карточку-резюме и спроси подтверждение.
```

> Это стартовый промпт. Качество будет доводиться итерациями после обкатки.

## Ограничения и требования

### Обязательно
- Сохранить работающий функционал: чаты, проекты, артефакты, голосовой ввод, модальные помощники
- Все существующие чаты должны быть доступны после миграции
- Breadcrumbs на каждом экране
- Sidebar только в чатах, без табов
- Поле ввода на Главной как вход в чат

### На усмотрение Claude Code
- Организация компонентов и файлов
- Точная структура маршрутов (предложенная выше — рекомендация)
- Анимации и переходы

### Архитектурные решения (утверждены)

**Передача первого сообщения (Главная → Чат):**
- Использовать URL search params: `/chat?message=encoded_text`
- В chat page: читать param, отправлять как первое сообщение, очищать URL
- Поддерживает deep links и работает после refresh страницы

**Определение контекста sidebar:**
- Парсинг URL в layout компоненте
- `/chat/*` → контекст "general" (общие чаты)
- `/projects/[id]/chat/*` → контекст "project", id из params
- `/helpers/[id]/*` → контекст "helper", id из params

**Модель данных помощников:**
- Предустановленные: статичные данные в `lib/helpers/presets.ts` (Маркетолог, Копирайтер, Переводчик, Аналитик, Наставник). Промпты и навыки для каждого — заглушки, будут прописаны отдельно
- Кастомные: таблица `Helper` в БД (id, userId, name, emoji, instruction, skills, createdAt)
- Связь с чатами: поле `helperId` в таблице `Chat` (nullable)
- Флаг автонейминга: поле `isRenamed` (boolean, default false) в таблице `Chat`

**Инструменты на Главной:**
- Показывать карточки с пометкой "Скоро", не скрывать. Пользователь должен видеть что платформа развивается

**Проекты без помощников:**
- Можно создать проект без подключённых помощников. Помощники — опционально

### Не входит в это ТЗ
- Страница проекта (двухколоночный layout) → ТЗ-07B
- Превью файлов в canvas → ТЗ-07B
- Конструктор кастомных помощников → отдельное ТЗ
- Инструменты (Диктофон, Исследование, Брифинг) → показать карточки, но функционал не реализовывать
- Помощники — показать карточки с переходом в чат, но промпты и навыки для каждого помощника — отдельная задача

## Порядок работы (рекомендация)

1. **Схема БД** — миграция: таблица Helper, поля helperId и isRenamed в Chat
2. **Helpers presets** — статичные данные предустановленных помощников (с заглушками промптов)
3. **Навигация и маршруты** — перестроить роутинг, убрать непоследовательность
4. **Sidebar** — убрать табы, сделать контекстным, добавить управление чатами
5. **Главная** — новый layout с полем ввода и секциями
6. **Автонейминг** — фоновая генерация названий чатов
7. **Universal Dialog** — компонент + промпт Simply + сценарий создания проекта
8. **Тестирование** — все переходы, breadcrumbs, sidebar в разных контекстах

## Критерий готовности

- Открываю Simply → вижу Главную с полем ввода, проектами, помощниками, инструментами
- Печатаю на Главной → попадаю в чат, мой текст уже отправлен
- В чате sidebar показывает только общие чаты, без табов
- Захожу в проект → в чате проекта sidebar показывает только чаты этого проекта
- Нажимаю "+ Новый проект" → полноэкранный диалог с Simply → проект создан
- На каждом экране breadcrumbs, кнопка назад работает
- Могу переименовать и удалить чат из sidebar
