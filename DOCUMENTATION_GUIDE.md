# Руководство по ведению документации проекта

> **Важно:** Этот документ описывает правила и принципы ведения документации.
> При любых изменениях в проекте следуй этим правилам!

---

## 🚨 ОБЯЗАТЕЛЬНОЕ ПРАВИЛО ДЛЯ ВСЕХ ИЗМЕНЕНИЙ

### После ЛЮБЫХ значительных изменений документация ОБЯЗАНА быть обновлена!

**Что считается "значительными изменениями":**
- ✅ Создание новых компонентов, хуков, API routes
- ✅ Изменение архитектуры проекта
- ✅ Добавление или удаление зависимостей (npm packages)
- ✅ Изменение API эндпоинтов или AI tools
- ✅ Изменение структуры папок
- ✅ Добавление новых функций/фич
- ✅ Изменение переменных окружения (.env.local)
- ✅ Изменение схемы БД (Drizzle migrations)
- ✅ Изменение system prompts или AI capabilities
- ✅ Добавление новых возможностей AI-агентам (tools, vision, etc.)

**Что нужно сделать:**
1. ✅ Обновить все файлы документации согласно правилам SSOT
2. ✅ Пройти чек-лист (см. раздел "Чек-лист при изменениях")
3. ✅ Проверить, что нигде нет дублирования информации
4. ✅ Обновить CHANGELOG.md
5. ✅ Обновить SIMPLY_STATUS.md (если изменилось состояние)

**Это НЕ рекомендация, это ОБЯЗАТЕЛЬНОЕ требование!**

> 💡 Неактуальная документация хуже, чем отсутствие документации.
> Всегда обновляй документы после изменений!

## 🎯 Принципы документации

### 1. Single Source of Truth (SSOT)
- Каждая информация живёт в ОДНОМ месте
- Остальные файлы ссылаются на неё
- Обновил в одном месте → везде актуально

**Пример:**
- ❌ Неправильно: Писать список AI tools в README, CLAUDE.md и docs/ai-tools.md
- ✅ Правильно: Написать в docs/ai-tools.md, остальные файлы ссылаются на него

### 2. README.md = Точка входа
- **Размер:** 80-150 строк (не больше!)
- **Содержание:** Только быстрый старт и ссылки
- **Детали:** Ссылки на docs/ для подробностей
- **Назначение:** Дать понять что это за проект и как быстро запустить

### 3. CLAUDE.md = Навигация для AI
- Быстрый контекст для Claude/Copilot
- Структура проекта
- Ключевые файлы и паттерны
- Ссылки на детальную документацию

### 4. docs/ = Детали
- Детальная установка → `docs/setup.md`
- Архитектура → `docs/architecture.md`
- AI-агенты → `docs/ai-agents.md`
- Артефакты → `docs/ai-artifacts.md`
- Инструменты → `docs/ai-tools.md`
- Deployment → `docs/deployment.md`
- Troubleshooting → `docs/troubleshooting.md`

### 5. Не дублируй информацию!
- Если нужно повторить — сделай ссылку
- Один источник правды = легче обновлять

## 📝 Что где хранить

### README.md (80-150 строк)

**Что ДОЛЖНО быть:**
- Название проекта + 1-2 предложения что это
- Быстрый старт (Quick Start): 3-5 команд для запуска
- Основные команды (npm run dev, npm run build)
- Ссылки на docs/ для деталей
- Технологии (список с версиями)

**Что НЕ ДОЛЖНО быть:**
- ❌ Детальная установка (→ docs/setup.md)
- ❌ Описание AI (→ docs/ai-agents.md, ai-artifacts.md, ai-tools.md)
- ❌ Архитектура проекта (→ docs/architecture.md)
- ❌ Troubleshooting (→ docs/troubleshooting.md)

## ✅ Чек-лист при изменениях

### Когда меняешь проект:

**1. Обновил код?**
- [ ] Обновил SIMPLY_STATUS.md (если изменилось состояние)
- [ ] Добавил запись в CHANGELOG.md
- [ ] Проверь, нужно ли обновить docs/

**2. Добавил новую фичу?**
- [ ] Опиши в README (если важная)
- [ ] Добавь в docs/architecture.md (если меняет архитектуру)
- [ ] Обнови docs/ai-tools.md (если новый AI tool)
- [ ] Создай ADR если принял важное решение (docs/decisions/)

**3. Добавил новый компонент/хук?**
- [ ] Обнови CLAUDE.md (структура проекта)
- [ ] Добавь JSDoc комментарии в код

**4. Добавил зависимость (npm package)?**
- [ ] Обнови package.json ✅ (автоматически)
- [ ] Упомяни в docs/setup.md если требует настройки

**5. Изменил .env переменные?**
- [ ] Обнови .env.example
- [ ] Обнови docs/setup.md
- [ ] Обнови docs/deployment.md (production переменные)

**6. Изменил схему БД?**
- [ ] Создай миграцию (npm run db:migrate)
- [ ] Обнови docs/architecture.md (схема БД)

**7. Добавил/изменил AI tool или возможность агента?**
- [ ] **ОБЯЗАТЕЛЬНО** обнови соответствующий файл:
  - Агенты → docs/ai-agents.md
  - Артефакты → docs/ai-artifacts.md
  - Инструменты → docs/ai-tools.md
- [ ] Обнови system-prompt.md если нужно
- [ ] Добавь пример использования
- [ ] Укажи файл реализации (ссылка)

## ⚠️ Что НЕЛЬЗЯ делать

❌ **НЕ создавай дублирующие файлы:**
- Нет QUICKSTART.md (есть README)
- Нет PROJECT_SUMMARY.md (есть README + docs/)
- Нет отдельных README в подпапках

❌ **НЕ копируй информацию:**
- Вместо копирования делай ссылку
- Один источник правды!

❌ **НЕ делай README длинным:**
- Максимум 150 строк
- Детали → в docs/

❌ **НЕ забывай обновлять:**
- Изменил код → обнови документацию
- Нашел баг → добавь в troubleshooting.md

## 🔍 Как проверить SSOT

### Команда для поиска дублирования:

```bash
# Найти все упоминания (например, Gemini)
grep -r "Gemini" . --include="*.md"

# Найти все README файлы
find . -name "README.md"

# Найти дублирующие .md файлы в корне
ls *.md
```

### Признаки нарушения SSOT:
- ⚠️ Одна и та же информация в разных файлах
- ⚠️ Несколько README.md
- ⚠️ Числа/факты различаются в разных местах
- ⚠️ Версии технологий указаны в нескольких файлах
