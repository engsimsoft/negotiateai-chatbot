## Что делаем

Пользователь нажимает «Начать планирование» → backend вызывает Профессора (одним запросом) → Профессор анализирует проект и возвращает структурированный план → план сохраняется в БД → пользователь видит результат.

**Это ядро ценности Simply:** момент когда система *думает* за пользователя и декомпозирует хаос на конкретные шаги.

---

## Backend

### Endpoint: POST /api/projects/[id]/plan

**Вход:**
- passport (Project.name + description + context)
- manifest (Project.manifestJson)
- toolsManifest — **захардкоженный на MVP:**
```json
{
  "tools": [
    { "name": "web_search", "status": "connected", "capabilities": "Поиск информации в интернете" },
    { "name": "file_generation", "status": "connected", "capabilities": "Создание документов (docx, pptx, xlsx)" },
    { "name": "file_analysis", "status": "connected", "capabilities": "Анализ загруженных файлов" }
  ]
}
```
- userAnswers (опционально — ответы на уточняющие вопросы от предыдущего вызова)

**Процесс:**
1. Загрузить промпт Профессора из .md файла (паттерн как у Клерка-анализатора)
2. Подставить passport + manifest + toolsManifest + userAnswers в промпт
3. Вызвать модель (dev: Gemini 3 Pro; prod: Claude Opus через OpenRouter)
4. Распарсить structured JSON ответ
5. Сохранить в Project: planJson + planReport
6. Вернуть результат клиенту

**Ответ Профессора — два варианта:**

Вариант A — вопросы (данных недостаточно):
```json
{ "questions": ["Кто целевая аудитория?", "Какой бюджет?"] }
```

Вариант B — полный план:
```json
{
  "tasks": [{ "order": 1, "title": "...", "description": "...", "goal": "...", "input": "...", "expectedOutput": "...", "dependencies": [], "tools": ["web_search"], "needsReview": true, "reviewReason": "..." }],
  "risks": [{ "description": "...", "severity": "medium", "mitigation": "..." }],
  "recommendations": [{ "type": "upload_data", "description": "...", "impact": "..." }],
  "planReport": "## Полный анализ\n..."
}
```

**Обработка:**
- Если questions → сохранить в Project (поле planJson = { questions: [...] }), phase остаётся 'planning'
- Если план → сохранить planJson + planReport в Project, phase остаётся 'planning'
- Клиент различает по наличию `tasks` vs `questions` в planJson

### Промпт Профессора

Файл: `lib/prompts/professors/planning.md` (новая директория professors/)

Промпт от PE готов — Владимир предоставит .md файл. Если промпт ещё не передан, используй заглушку с фреймворком из MVP_ROLES_AND_CONTRACTS.md (6 шагов: аудит данных → аудит ресурсов → декомпозиция → зависимости → риски → финальный план).

**Формат ответа** — JSON в XML-тегах (как у Клерка):
```
<result>
{ "tasks": [...], "risks": [...], "recommendations": [...], "planReport": "..." }
</result>
```

## UI

### Кнопка «Начать планирование» (уже есть в welcome-state.tsx)

Клик → POST /api/projects/[id]/plan → phase = 'planning' → перерисовка work area.

**Phase transition:**
- Кнопка вызывает updateProjectPhase('planning') + запускает POST /plan
- Или: POST /plan сам обновляет phase на 'planning' в начале и возвращает результат

### WorkArea: PlanningState (новый компонент в phase-states/)

**Три состояния:**

**1. Профессор работает (planJson ещё нет, запрос в полёте):**
```
🧠 Глубокий анализ проекта...

✓ Аудит входных данных
✓ Анализ ресурсов и инструментов  
🔄 Декомпозиция на задачи...
○ Карта зависимостей
○ Анализ рисков
○ Финализация плана

Профессор анализирует ваш проект. Это займёт 1-2 минуты.
```

Прогресс — **имитация** (один API-вызов, шаги анимируются по таймеру). Каждый шаг появляется с интервалом ~10-15 секунд. Когда реальный ответ приходит — все шаги мгновенно завершаются.

**2. Профессор вернул вопросы (planJson.questions):**
```
🧠 Профессору нужна дополнительная информация

1. Кто целевая аудитория продукта?
   [текстовое поле]

2. Какой предполагаемый бюджет?
   [текстовое поле]

[Отправить ответы и продолжить планирование]
```

При отправке → повторный POST /plan с userAnswers → снова прогресс.

**3. План готов (planJson.tasks):**
```
✅ План проекта готов

📋 5 задач • ⚠️ 2 риска • 💡 1 рекомендация

1. Анализ рынка и конкурентов
   Цель: Понять конкурентную среду и спрос
   🔍 web_search • 🎓 с проверкой

2. Формирование услуг и ценообразования
   Цель: Определить линейку услуг и цены
   📄 file_generation

3. Финансовая модель
   ...

⚠️ Риски:
- ...

💡 Рекомендации:
- ...

[Подробный анализ ↓]    ← раскрывает planReport (Markdown)

[Утвердить план]  [Обсудить с Менеджером]
```

Кнопки «Утвердить» и «Обсудить» — **заглушки в B1.** Реальная логика утверждения — в ТЗ-B2. Кнопка «Утвердить» может показывать toast «Функция будет доступна в следующем обновлении» или быть неактивной.

### Пульс

В секции «План» при phase = 'planning':
- Пока работает: «🧠 Анализ...» (анимированная иконка)
- Когда план готов: превью задач (номер + название), без статусов (статусы — это B2)

## Что НЕ входит в B1

- Утверждение плана (кнопка → создание ProjectTask) — это B2
- Обсуждение плана с Менеджером (Менеджер уже видит plan в контексте, но активное обсуждение — B2)
- Редактирование плана — отложено
- Пересмотр Профессором — отложено

---

## Ожидаемый результат

1. Пользователь нажимает «Начать планирование»
2. Видит анимированный прогресс (6 шагов)
3. Через 30-90 секунд — структурированный план с задачами, рисками, рекомендациями
4. Может раскрыть подробный анализ (planReport)
5. В Пульсе появляется превью задач
6. planJson и planReport сохранены в БД
