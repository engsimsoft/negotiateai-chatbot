# ТЗ: Extract при сжатии + событийная обработка MIND (v3.78.0)

**Дата:** 2026-04-08
**Зависимость:** v3.77.0

---

## Проблема

1. Extract отключён (v3.77.0) — факты из сообщений не попадают в MIND
2. Консолидация и Opus-профиль запускаются каждую ночь независимо от активности — деньги списываются вхолостую
3. Используются дорогие модели (Sonnet для Extract/консолидации, Opus для профиля) при наличии MiniMax M2.7 который справляется не хуже

---

## Что делаем

### 1. Добавить поле `extractedAt` в таблицу message

Drizzle schema: `extractedAt: timestamp("extractedAt")` в таблицу message.
Миграция: все существующие сообщения остаются `extractedAt = NULL`.

### 2. Изменить загрузку истории для simply

Текущее: жёсткий бюджет `maxTokens: 140000`.

Новое: для chatMode=simply загружать все сообщения где `extractedAt IS NULL`. Добавить параметр `excludeExtracted?: boolean` в `getMessagesByChatId` (по умолчанию false — остальные chatMode не затронуты).

Safety-cap: 180K токенов. Если extractedAt IS NULL сообщений больше 180K — загрузить только последние 180K (от новых к старым). Страховка на случай если Extract сломался.

### 3. Extract — событийный триггер

В route.ts для chatMode=simply, перед `streamText`:

Посчитать общий контекст (механизм уже есть: `calcUsagePercent()`).
Лимит: `SIMPLY_CONTEXT_LIMIT = 200_000`.

| Порог | Условие | Действие |
|-------|---------|----------|
| 60% (120K) | контекст ≥ 120K **И** пауза ≥ 10 минут | Extract fire-and-forget |
| 80% (160K) | контекст ≥ 160K | Extract fire-and-forget **без паузы** |

Определение паузы: `Date.now() - createdAt последнего сообщения из загруженной истории` (отдельный запрос к БД не нужен).

Fire-and-forget: Extract не блокирует ответ пользователю.

### 4. batchExtractFacts — новая функция

В `lib/ai/memory/extract.ts`, рядом с существующей `extractAndStoreFacts`.

**Модель: MiniMax M2.7** (через `generateText` + `JSON.parse()` + Zod-валидация).

НЕ использовать `generateObject` — провайдер MiniMax не поддерживает. Вместо этого:
```
generateText → промпт требует строго JSON → JSON.parse() → zodSchema.parse()
```

**Логика:**
1. Взять сообщения с `extractedAt IS NULL`, самые старые, до 50 штук
2. Сформировать текстовый блок из пар user+assistant
3. MiniMax M2.7 `generateText` — «извлеки факты, верни строго JSON»
4. `JSON.parse()` → Zod-валидация → через существующий pipeline: embed → dedup → store
5. `UPDATE message SET extractedAt = NOW() WHERE id IN (...)`
6. Вернуть количество записанных фактов

**Промпт:** создать `lib/prompts/memory/extract-batch.md` — адаптировать текущий extract.md для batch из множества пар. Инструкция «верни строго JSON, никакого Markdown».

### 5. Консолидация — событийный триггер

**Триггер:** после Extract, если записано ≥ 10 новых фактов.

**Модель: MiniMax M2.7** (через `generateText` + `JSON.parse()` + Zod-валидация).

Заменить `generateObject` на тот же паттерн: `generateText` → `JSON.parse()` → Zod.

Перед консолидацией: логировать текущее количество фактов (аудит).
После консолидации: логировать сколько keep/supersede/merge/remove.

### 6. Профиль — событийный триггер

**Триггер:** после консолидации, если ≥ 10 фактов изменилось (добавлено + удалено + обновлено).

**Модель: MiniMax M2.7** (через `generateText` — профиль уже текст, generateObject не нужен).

Заменить `claudeOpus` на MiniMax M2.7 в profile.ts.

### 7. Ночной cron — только страховка

Существующий cron `memory-profile` (00:00 UTC) — переделать:

**Убрать:** безусловный запуск консолидации и профиля каждую ночь.

**Оставить:** проверка — есть ли сообщения `chatMode = "simply"`, `extractedAt IS NULL`, старше 24 часов? Если да → запустить цепочку Extract → Консолидация (если ≥10) → Профиль (если ≥10 изменений).

Если необработанных сообщений нет — cron ничего не делает, деньги не списываются.

---

## Цепочка событий (итого)

```
Сообщения копятся в контексте
  → 60% (120K) + пауза 10 мин → Extract (MiniMax, fire-and-forget)
  → 80% (160K) без паузы → Extract (MiniMax, принудительно)
    → если записано ≥10 фактов
      → Консолидация (MiniMax)
        → если ≥10 фактов изменилось
          → Профиль (MiniMax)

Страховка: cron 00:00 UTC → если extractedAt IS NULL старше 24ч → та же цепочка
```

---

## Что НЕ делать

- НЕ удалять сообщения из БД после Extract — нужны для UI
- НЕ трогать загрузку истории для chatMode ≠ simply
- НЕ использовать generateObject с MiniMax — не поддерживается провайдером
- НЕ запускать консолидацию/профиль без проверки порогов

---

## Критерии приёмки

1. **Загрузка истории:** для simply — только `extractedAt IS NULL` с safety-cap 180K
2. **Extract 60%:** набрать > 120K токенов → подождать 10+ мин → отправить сообщение → в логах batchExtractFacts → факты в MIND → extractedAt заполнен → контекст стал легче
3. **Extract 80%:** набрать > 160K → отправить сразу → Extract без паузы
4. **Консолидация:** после Extract с ≥10 фактами → в логах консолидация → факты ревизированы
5. **Профиль:** после консолидации с ≥10 изменениями → профиль пересобран MiniMax
6. **Ночной cron:** без новых сообщений → cron ничего не запускает (проверить логи)
7. **Модели:** все три задачи (Extract, консолидация, профиль) на MiniMax M2.7, не Sonnet/Opus
8. **DevPanel:** факты видны в /settings/memory после Extract
