# ТЗ-BF1: Рефакторинг UI брифинга + сохранение тем

**Приоритет:** Высокий (блокер перед Фазой Б — аудиоплеер)  
**Оценка:** 1 ТЗ, средняя сложность

---

## Зачем

Брифинг работает, но UI не доведён до стандартов Simply:
- Sidebar скроллится вместе с контентом (должен быть фиксирован, как в чате)
- Цвета расходятся с дизайн-системой (хардкоженные значения)
- Брифинги копятся в БД бесконтрольно — пользователь не видит и не управляет
- Нет механизма сохранить интересную тему — весь выпуск либо хранится, либо нет

## Что делаем

### 1. Fixed sidebar — независимый скролл

Sidebar брифинга (`BriefingSidebar`) должен быть фиксирован и скроллиться независимо от контента, как `AppSidebar` в `(chat)`.

**Требования:**
- Sidebar: `sticky top-14 h-[calc(100vh-3.5rem)] overflow-y-auto` (top-14 = высота header)
- Контент: собственный скролл, sidebar не двигается
- На мобильных: Sheet (как уже реализовано в других местах)
- Ориентир: поведение sidebar в `(chat)` layout

### 2. Аудит цветов

Все briefing-компоненты привести к дизайн-системе (`docs/design-system.md`).

**Действие:** Выполнить grep по всем файлам в `components/briefing/` и `app/(dashboard)/briefing/`:
```bash
grep -rn "bg-gray\|text-gray\|border-gray\|bg-slate\|bg-zinc\|bg-stone\|bg-neutral\|bg-white\|text-black\|#[0-9a-fA-F]" --include="*.tsx" --include="*.ts"
```

Заменить на семантические токены: `bg-background`, `bg-card`, `bg-muted`, `text-foreground`, `text-muted-foreground`, `border-border` и т.д.

Результат grep после замен = 0 строк.

### 3. Новая таблица `savedBriefingTopics`

Хранит сохранённые темы — автономные сущности, не зависящие от жизни брифинга.

```
savedBriefingTopics:
  id            uuid PK
  userId        text FK → user.id
  topicId       text           — ID темы из каталога (например "ai_ml")
  topicName     text           — "Разработки в области ИИ"
  emoji         text           — "🧠"
  title         text           — заголовок секции из статьи
  content       text           — markdown-контент секции
  sources       jsonb          — массив BriefingArticleSource[]
  briefingDate  date           — дата выпуска, из которого сохранено
  savedAt       timestamp      — когда пользователь нажал "Сохранить"
```

**Query:**
- `saveBriefingTopic({ userId, ...data })` — создать
- `getSavedBriefingTopics({ userId })` — получить все, sorted by savedAt desc
- `deleteSavedBriefingTopic({ id, userId })` — удалить

### 4. TTL: эфемерные брифинги

Брифинг живёт до следующей генерации. При нажатии «Сгенерировать»:

1. Удалить **все** записи в `briefingHistory` для этого userId (сохранённые темы уже автономны в отдельной таблице, зависимости нет)
2. Создать новый брифинг

**Миграция при деплое:** Удалить все записи из `briefingHistory` кроме самой свежей для каждого userId. Это одноразовая очистка тестовых данных.

### 5. UI: закладка на секции

В компоненте, который рендерит секцию статьи — добавить кнопку-закладку.

**Расположение:** Правый верхний угол блока секции, рядом с emoji и названием темы.

**Поведение:**
- Иконка `Bookmark` (lucide-react), по умолчанию незаполненная (`outline`)
- Клик → POST сохраняет тему в `savedBriefingTopics` → иконка становится заполненной (`fill`)
- Повторный клик → DELETE удаляет → иконка обратно outline
- Toast: «Тема сохранена» / «Тема удалена»

**API:**
- `POST /api/briefing/topics/save` — body: { topicId, topicName, emoji, title, content, sources, briefingDate }
- `DELETE /api/briefing/topics/save?id=xxx`
- `GET /api/briefing/topics/saved` — список сохранённых тем пользователя

### 6. Sidebar: новая структура

Вместо текущего:
```
СЕГОДНЯ
  📖 Полный брифинг
  🏎 Формула-1
  🧠 Разработки в области ИИ

ПРОШЛЫЕ ВЫПУСКИ
  20 февраля
```

Новая структура:
```
ТЕКУЩИЙ ВЫПУСК
  📖 Полный брифинг
  🏎 Формула-1
  🧠 Разработки в области ИИ

СОХРАНЁННЫЕ  (показывать только если есть)
  🧠 [заголовок темы] · 21 фев
  🧠 [заголовок темы] · 19 фев
```

- Секция «ПРОШЛЫЕ ВЫПУСКИ» удаляется полностью
- Секция «СОХРАНЁННЫЕ» показывает результат `getSavedBriefingTopics()`
- Клик по сохранённой теме — скролл к ней или отдельный вид (на выбор реализации)
- У каждой сохранённой темы — возможность удалить (иконка ✕ или dropdown)

## Чего НЕ делаем

- Не меняем route group (брифинг остаётся в `(dashboard)`)
- Не добавляем действия «Обсудить с экспертом» / «Изучить подробнее» — будущее
- Не трогаем логику генерации, фетчеры, фильтрацию
- Не трогаем онбординг `/briefing/setup`
- Не добавляем новости Simply — это ТЗ-BF2
