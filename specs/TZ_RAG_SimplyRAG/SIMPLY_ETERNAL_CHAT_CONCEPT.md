## Философия

Все AI-продукты (ChatGPT, Claude, Gemini) копируют модель email: много тредов, ищи нужный, создавай новый. Это костыль — компенсация отсутствия памяти. AI забывает → пользователь вынужден организовывать чаты вручную.

Simply имеет MIND — долговременную память. AI помнит всё между чатами. Значит множественные чаты не нужны.

**Один ассистент. Один разговор. Всегда.**

Пользователь открывает Simply → продолжает разговор. Не «создаёт новый чат», не «ищет вчерашний». Как с живым помощником — ты не «открываешь новый тред» с секретарём каждое утро.

**Аналогия:** Все делают email (много тредов). Simply делает личного помощника (один разговор, он сам знает контекст).

## Что меняется

### Главная страница (Dashboard)

Текущий вид сохраняется (скрин 1 — «Доброй ночи, Владимир»), но с изменениями:

**Было:** Карточка «История чатов · 1 чат» слева от ввода  
**Стало:** Карточка **«Мой контекст»** — при нажатии открывается dashboard MIND с 7 карточками

**Было:** Ввод текста → создаётся новый чат → auto-naming → открывается чат  
**Стало:** Ввод текста → продолжается единственный вечный чат. Визуально для пользователя ничего не меняется — он просто пишет и получает ответ

**Карточки Экспертиза / Создать / Проекты** — без изменений. Это осознанный переход в другой режим работы.

**Карточки Утренний брифинг / Запись встречи** — без изменений.

### Что удаляется

| Элемент | Почему |
|---------|--------|
| Страница «История чатов» (скрин 2) | Нет множественных чатов → нет списка |
| Auto-naming (`generate-title/route.ts`) | Нечего именовать. Экономия одного вызова Haiku на каждый чат |
| Кнопка «+ Новый чат» | Чат один, он вечный |
| Группировка чатов по датам (Сегодня, Вчера, 7 дней) | Нет чатов → нет группировки |
| Sidebar history для chatMode=chat | Заменяется карточками «Мой контекст» |

### Что остаётся без изменений

| Элемент | Почему |
|---------|--------|
| Экспертиза (Sonnet) | Отдельные серьёзные запросы, специальные промпты |
| Создание (Sonnet) | Отдельные задания, артефакты |
| Проекты | Изолированные рабочие пространства |
| Бен | Помощь по платформе |
| История Экспертизы и Создания | Множественные сессии остаются — каждый запрос/задание отдельный |

### Разделение

| Что | Как работает |
|-----|-------------|
| **Чат** | Один вечный разговор. MIND помнит всё. Compaction сжимает |
| **Экспертиза** | Отдельные запросы. Глубокий анализ, специальный промпт |
| **Создание** | Отдельные задания. Документы, артефакты |
| **Проекты** | Изолированные пространства с задачами, планом, экспертом |

Чистое разделение: **чат = общение**, **экспертиза/создание = работа**, **проекты = проектная работа**.

## «Мой контекст» — Dashboard MIND

При нажатии на карточку «Мой контекст» на главной странице открывается структурированный dashboard — визуализация того, что MIND знает о пользователе.

### 7 утверждённых карточек

| # | Карточка | MIND category | Иконка | Что внутри |
|---|----------|--------------|--------|------------|
| 1 | **Задачи** | `task` | ✓ (coral) | Что нужно сделать, дедлайны, статусы |
| 2 | **Календарь** | `calendar` | 📅 (pink) | Встречи, события, даты, напоминания |
| 3 | **Решения** | `decision` | ⚖ (blue) | Что решили, когда, обоснования |
| 4 | **Люди** | `person` | 👥 (purple) | Кого обсуждали, контекст по каждому |
| 5 | **Идеи** | `fact` (подтип) | 💡 (amber) | Мозговые штурмы, гипотезы, «а что если» |
| 6 | **Заметки** | `fact` (подтип) | 📝 (green) | Факты, цифры, ссылки, всё остальное |
| 7 | **Предпочтения** | `preference` | ⚙ (gray) | Стиль, вкусы, привычки пользователя |

### Расположение на экране

**Первый ряд** (action-oriented): Задачи · Календарь · Решения — что делать, когда, что решили  
**Второй ряд** (context-oriented): Люди · Идеи · Заметки — кто, что придумал, что запомнил  
**Третий ряд** (meta) или отдельная секция: Предпочтения — как Simply тебя понимает

### Принципы карточек

**Предустановлены, не настраиваемые.** Аудитория 40-60+ не будет создавать категории. Apple-подход: 7 карточек покрывают 95% бизнес-жизни.

**Пустые карточки скрываются.** Если пользователь никогда не обсуждал идеи — карточки «Идеи» нет. Появится автоматически когда MIND извлечёт первый факт соответствующего типа.

**Порядок по частоте.** Карточки с большим количеством фактов и частым обращением поднимаются выше. Автоматически, без настроек.

**Badge** — количество активных элементов на каждой карточке. Пользователь мгновенно видит: 3 задачи, 2 события, 7 решений.

**Preview** — два самых свежих/важных элемента внутри каждой карточки. Не нужно нажимать, чтобы увидеть главное.

### Что происходит при нажатии на карточку

Нажал на «Люди» → вечный чат открывается с фокусом на людей. MIND подтягивает контекст по людям в system prompt. Пользователь может спрашивать: «Когда мы последний раз обсуждали Петрова?» — и AI ответит с полным контекстом.

Нажал на «Решения» → чат с фокусом на решения. «Что мы решили по маркетингу?» — мгновенный ответ.

Карточки = **фильтры фокуса**, не отдельные чаты.

### Opus-профиль

Под карточками — секция «Профиль пользователя» (нарративный текст от Opus, 800-1200 слов). Обновляется ночным cron. Read-only. Прозрачность: пользователь видит как AI его понимает.

### Управление

Внизу dashboard — кнопки: «Настройки памяти» (вкл/выкл извлечение, категории) и «Удалить всё» (полная очистка). Контроль над данными — необходимость для премиум-аудитории.

## Вечный чат — структура интерфейса

### Три панели

| Панель | Содержимое | Аналог |
|--------|-----------|--------|
| **Левый sidebar** | Навигация: S logo, Главная, Чат (вечный), Экспертиза, Создание, Проекты, Настройки | Как сейчас, но без «История чатов» |
| **Центр** | Один поток сообщений с датами-разделителями. Input внизу | Как Telegram с одним контактом |
| **Правый sidebar** | Медиатека: Документы / Медиа / Ссылки. Поиск | Как в Telegram — профиль контакта → вложения |

### Центральная панель (вечный чат)

**Даты-разделители** — «вчера», «сегодня», «15 марта». Не чаты по датам, а разделители внутри одного потока. Как в Telegram/WhatsApp.

**Сообщения** — user (правое выравнивание), assistant (левое). Файлы inline. Tool calls inline. Артефакты inline. Всё как сейчас (скрин 3), но в одном бесконечном потоке.

**Input** — поле ввода внизу, всегда видимое:
- Кнопка «+» — вложить файл
- Микрофон — голосовой ввод (Deepgram/ElevenLabs)
- Кнопка отправки
- Без селектора модели (Smart Routing в будущем)

**Compaction** — для Sonnet/Opus чатов контекст сжимается автоматически через Anthropic Compaction API. Для Haiku — snapshot-система. Пользователь не знает об этом.

### Правый sidebar — Медиатека

Три вкладки (паттерн Telegram):

**Документы:**
- Созданные AI артефакты (Markdown, Excel, PPTX, PDF)
- Загруженные пользователем файлы (PDF, DOCX)
- Разделение: «Созданные» и «Вложения»
- Поиск по имени
- Клик → открывает file viewer или скроллит к сообщению

**Медиа:**
- Фото, скриншоты, изображения
- Сетка превью (thumbnails)
- Lightbox при клике

**Ссылки:**
- Все URL из deepResearch, fetchUrl
- Заголовок + домен
- Кликабельные

Каждый элемент:
- Иконка типа файла (PDF, XLSX, IMG, MD)
- Имя файла
- Размер + дата
- Клик → открытие или прокрутка к сообщению

### Левый sidebar

Минимальный. Иконки (как на скрине 3 — S, домик, чат, проекты):

| Иконка | Куда ведёт |
|--------|-----------|
| **S** | Лого Simply (на главную) |
| **Домик** | Dashboard (главная) |
| **Чат** | Вечный чат (всегда один и тот же) |
| **Экспертиза** | Список запросов экспертизы |
| **Создание** | Список заданий |
| **Проекты** | Список проектов |
| **Настройки** | Настройки (внизу) |

При раскрытии sidebar — текстовые лейблы рядом с иконками.

**Нет «Истории чатов»** в sidebar. Чат один — нечего показывать в списке.

## Файлы в чате → Библиотека

### Проблема
Пользователь вкладывает файл в чат. AI обсуждает его. Но файл не сохраняется в долговременную базу знаний.

### Решение
После обсуждения файла AI предлагает:

```
📚 Сохранить в Библиотеку? Он будет доступен во всех чатах.
[Сохранить] · [Нет, спасибо]
```

**Правильный момент — после обсуждения**, не до. Пользователь уже понял ценность файла.

Одна кнопка → файл уходит в RAG-4 pipeline (chunking → voyage-context-3 → pgvector). Не нажал — файл остался только в контексте этого разговора и в медиатеке (правый sidebar).

### Три способа наполнения Библиотеки

1. **Drag & drop** на странице `/library` — загрузка напрямую
2. **Предложение после обсуждения в чате** — AI спрашивает «сохранить?» (самый органичный)
3. **Интеграции** — Telegram, Google Drive, GitHub (автосинхронизация)

## Техническая архитектура изменений

### Что меняется в БД

**Таблица `chat`:**
- Новый флаг или тип: `isEternal: boolean` — помечает один вечный чат пользователя
- Или: при первом сообщении создаётся единственный чат с `chatMode: 'chat'` и он переиспользуется всегда
- Auto-naming (`title`) — больше не генерируется для вечного чата. Фиксированный title: «Simply» или имя пользователя

**Таблица `memory_entry`:**
- Без изменений. MIND уже работает cross-chat. Вечный чат = один chatId, но это не влияет на MIND — факты извлекаются из любого чата.

### Что меняется в коде

**Удалить:**
- `app/(chat)/api/chat/[id]/generate-title/route.ts` — auto-naming
- Страница истории чатов и связанные компоненты (для chatMode=chat)
- Логика создания нового чата при отправке сообщения с главной (вместо этого — продолжение вечного чата)

**Изменить:**
- `app/(chat)/chat/[id]/page.tsx` — для chatMode=chat всегда загружать один и тот же чат
- Dashboard: карточка «История чатов» → «Мой контекст» → открывает MIND dashboard
- `components/sidebar-history.tsx` — скрыть для chatMode=chat, оставить для expertise/create
- `components/chat-sidebar.tsx` — расширить: три вкладки (Документы / Медиа / Ссылки), поиск

**Добавить:**
- `app/(dashboard)/context/page.tsx` — страница «Мой контекст» с 7 карточками
- `components/context/context-cards.tsx` — сетка карточек MIND
- `components/context/context-card.tsx` — отдельная карточка с badge и preview
- `components/chat-sidebar-tabs.tsx` — вкладки медиатеки (Документы / Медиа / Ссылки)
- Предложение «Сохранить в Библиотеку» после обсуждения файла (компонент + логика)

### Как определить вечный чат

При первом сообщении пользователя в chatMode=chat — создаётся чат. При всех последующих — открывается тот же чат. Логика:

```typescript
// Вместо createChat() каждый раз:
const eternalChat = await getOrCreateEternalChat(userId);
// eternalChat — всегда один и тот же для данного пользователя
```

Можно реализовать через:
- Фиксированный chatId на уровне пользователя (FK в User)
- Или поиск `WHERE userId = :id AND chatMode = 'chat' AND isEternal = true LIMIT 1`

## Связь с другими концепциями

### MIND-2 (Граф знаний)
Карточки «Мой контекст» — это визуализация MIND-1 (факты по категориям). Когда появится MIND-2 (граф знаний), карточки обогатятся: «Люди» покажет связи между людьми, «Решения» покажет хронологию и зависимости.

### MIND-3 (Проактивность)
Вечный чат — идеальная площадка для проактивного AI. Simply может сам написать первым: «У вас встреча с Петровым через час. Вот ключевые моменты из последнего разговора.» Это появляется в том же вечном потоке — как сообщение от ассистента.

### Библиотека (RAG-4)
Предложение «Сохранить в Библиотеку?» в чате — мост между вечным чатом и базой документов. Пользователь не думает про «RAG» — он просто соглашается сохранить файл одной кнопкой.

### Smart Routing (будущее)
Один вечный чат на одной модели. В будущем — Smart Routing автоматически выбирает глубину ответа: простой вопрос → быстрый ответ (effort: low), сложный → глубокий анализ (effort: high). Пользователь не переключает модели.

## Конкурентное сравнение

| | ChatGPT | Claude | Simply |
|---|---------|--------|--------|
| Чаты | 50+ в sidebar | 50+ в sidebar | **Один вечный** |
| Память | Блокнот (базовая) | Проектная | **MIND (глубокая, автоматическая)** |
| Поиск по истории | Ctrl+F по сообщениям | Ctrl+F | **Семантический через MIND** |
| Организация | Вручную (папки, rename) | Вручную | **Автоматическая (7 карточек)** |
| Файлы в чате | Теряются между чатами | Теряются | **Медиатека + Библиотека** |
| «Что мы обсуждали?» | Ищи по 50 чатам | Ищи | **Спроси — MIND знает** |

**Simply — единственный AI-продукт, где пользователь НЕ организует свою информацию. AI делает это сам.**

## Ключевые принципы UX

1. **Один паттерн — пользователь выучивает один раз.** Открыл → написал → получил ответ. Всегда.
2. **Нет организации — AI делает это сам.** 7 карточек заполняются автоматически из MIND.
3. **Файлы всегда доступны.** Медиатека справа — как в Telegram. Поиск по всем файлам за всё время.
4. **Прозрачность.** «Мой контекст» показывает что AI знает. Пользователь контролирует.
5. **Меньше элементов — каждый идеален.** Нет sidebar с 50 чатами. Нет кнопки «Новый чат». Нет auto-naming. Чище, проще, фокус на разговоре.
