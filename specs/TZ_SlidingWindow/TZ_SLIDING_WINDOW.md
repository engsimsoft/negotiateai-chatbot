# ТЗ: Скользящее окно — стабильная стоимость вечного чата

**Версия:** v3.76.0
**Приоритет:** Критичный
**Одна цель:** Стоимость каждого сообщения в Simply стабильна — не растёт с длиной истории чата.

---

## Проблема

Каждое сообщение в Simply отправляет в API всю историю чата. Сообщение №200 стоит в 200 раз дороже сообщения №1. Для вечного чата (один чат навсегда) это критично — через месяц стоимость разговора становится неоправданно высокой. При этом MIND уже извлёк все ценные факты из старых сообщений — тащить их в API бессмысленно.

## Решение

Отправлять в API только последние N сообщений. Старые сообщения остаются в базе (пользователь видит их при скролле), но не отправляются в Anthropic API. MIND + Opus-профиль покрывают долговременную память.

Подтверждено индустрией: архитектура Mem0 (научная работа, ECAI 2025) показывает 90% экономию токенов при использовании memory layer + скользящего окна вместо полной истории.

---

## Что сделать

### 1. Скользящее окно для Simply (chatMode=simply)

В route Simply перед отправкой сообщений в `streamText` — обрезать массив messages, оставив только последние 20 сообщений (user + assistant).

**Что отправляется в API при каждом вызове:**

```
system prompt (с MIND-фактами + Opus-профиль)  ← без изменений, как сейчас
+ последние 20 сообщений                        ← НОВОЕ: обрезка
```

**Правила обрезки:**
- Считать парами: user + assistant = 1 обмен. 20 сообщений ≈ 10 обменов.
- Всегда начинать с сообщения user (не с assistant) — чтобы не было оборванного контекста
- System prompt не считается и не обрезается — он всегда отправляется полностью
- Tool-call сообщения (tool_use + tool_result) считаются частью того обмена, к которому относятся — не разрывать пары

**Константа:** `SIMPLY_SLIDING_WINDOW_SIZE = 20` — вынести в конфиг (не хардкодить в route). Место: рядом с другими константами Simply или в `lib/constants/`.

### 2. Только для Simply

Скользящее окно применяется ТОЛЬКО к chatMode=simply. Остальные режимы не трогать:
- **Экспертиза** (chatMode=expertise) — нужна полная история для глубокого анализа
- **Создание** (chatMode=create) — нужна полная история для итерации
- **Проекты** — своя логика, не трогать

Причина: Simply = органайзер, короткие обмены. Экспертиза и Создание = длинные задачи, контекст критичен.

### 3. Сообщения остаются в базе

Обрезка — ТОЛЬКО при отправке в API. В базе данных все сообщения сохраняются как раньше. Пользователь может скроллить вверх и видеть всю историю. AI просто не получает старые сообщения.

### 4. Взаимодействие со Snapshot

Сейчас Snapshot срабатывает при приближении к лимиту контекстного окна (≈150K токенов). С скользящим окном в 20 сообщений Snapshot скорее всего никогда не сработает для Simply — 20 сообщений далеко от 150K.

**Действие:** оставить Snapshot как есть, не удалять. Он остаётся страховкой на случай если одно сообщение окажется очень длинным (например, пользователь вставил большой текст). Но в обычном сценарии он просто не сработает.

### 5. Extract продолжает работать

Extract pipeline получает сообщения из базы данных (не из API-вызова). Скользящее окно не влияет на Extract — он продолжает извлекать факты из ВСЕХ сообщений как раньше.

Claude Code: убедись что Extract берёт сообщения из БД, а не из массива messages, который отправляется в API. Если из БД — всё ок. Если из API-массива — это баг, который нужно исправить.

---

## Чего НЕ делать

- НЕ удалять сообщения из базы — только не отправлять в API
- НЕ делать summary старых сообщений — MIND уже покрывает это
- НЕ применять к Экспертизе/Создание/Проекты — только Simply
- НЕ удалять Snapshot — оставить как страховку
- НЕ менять логику MIND retrieve — он уже инжектируется в system prompt

---

## Критерии приёмки (проверки в браузере)

1. **Стабильная стоимость:** отправить 25 сообщений в Simply. В DevPanel проверить: стоимость сообщения №5 и сообщения №25 примерно одинаковая (±10%)
2. **Скролл работает:** после 25 сообщений скролл вверх показывает все 25 сообщений в UI
3. **MIND работает:** в сообщении №1 сказать «запомни: мой кот Барсик». В сообщении №25 спросить «как зовут моего кота?». AI должен ответить через MIND retrieve (факт не в окне, но в памяти)
4. **Экспертиза не затронута:** в Экспертизе (chatMode=expertise) отправить 25 сообщений — стоимость должна расти как раньше (полная история)
5. **Константа:** в коде есть `SIMPLY_SLIDING_WINDOW_SIZE = 20`, легко изменить
6. **Extract не сломан:** после 25 сообщений проверить `/settings/memory` — факты из ранних сообщений извлечены
