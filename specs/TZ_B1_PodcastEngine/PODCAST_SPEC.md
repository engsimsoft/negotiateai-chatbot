# Simply Briefing — Фаза Б: Подкаст. Полная спецификация

**Дата:** 2026-02-22  
**Статус:** Утверждено, готово к нарезке на ТЗ  
**Источники:** Сессия проектирования 2026-02-22, BRIEFING_AUDIO_RESEARCH.md, PE контракт briefing-scriptwriter

---

## Философия

Подкаст — это **второй способ потребления** того же брифинга. Статья — чтение за столом. Подкаст — наушники в машине. Два ведущих обсуждают новости пользователя в формате живого диалога.

**Для текущего MVP** — подкаст ручной, пользователь запускает сам. Это «игрушка» — wow-эффект. Настоящая ценность — автодоставка в Telegram (Фаза Г).

**Стратегически** — TTS pipeline проектируется как переиспользуемый движок (Podcast Engine). Завтра клиентом станет отдельный инструмент «Подкаст» на дашборде (создание подкастов из любого текста, настройка голосов, хранение в папках). Движок тот же, UI и хранение другие.

---

## Архитектура: два слоя

### Слой 1 — Podcast Engine (переиспользуемый модуль)

Живёт в `/lib/podcast/`, не в `/lib/briefing/`.

**Что делает:**
- Принимает текст + настройки (голоса, количество спикеров, стиль)
- Генерирует сценарий через scriptwriter промпт
- Озвучивает через TTS provider
- Конвертирует PCM → MP3
- Возвращает готовые MP3 файлы (Buffer или URL)

**Абстракции:**
- `TTSProvider` интерфейс: Gemini (основной), ElevenLabs (fallback)
- `ScriptGenerator` — генерация сценария из текста
- `AudioConverter` — PCM → WAV → MP3

### Слой 2 — Интеграция с брифингом (тонкая обёртка)

- Берёт секции из BriefingArticle
- Вызывает Podcast Engine с параметрами
- Сохраняет MP3 URL в таблицу брифинга
- Удаляет MP3 из Blob при TTL cleanup
- UI: кнопка, popover, прогресс, плеер

## Пользовательский путь (полный flow)

### Состояние 1: Подкаст не создан

Пользователь видит текстовый брифинг (текущий вид). В header справа — кнопка **«🎙 Создать подкаст»** (на месте текущего бейджа «Скоро: подкаст»).

### Состояние 2: Выбор тем (popover)

Нажал кнопку → компактный popover прямо от кнопки:

```
┌───────────────────────────┐
│  Что озвучить?            │
│                           │
│  ● Полный выпуск          │
│  ○ Выбрать темы           │
│                           │
│  ☐ Формула-1              │  ← неактивны при "Полный"
│  ☐ Разработки в обл. ИИ  │
│                           │
│  [ Создать ]              │
└───────────────────────────┘
```

- По умолчанию «Полный выпуск», чекбоксы тем серые (disabled)
- Переключил на «Выбрать темы» → чекбоксы стали активны
- Основной путь: кнопка → Создать = **2 клика**
- Продвинутый путь: кнопка → Выбрать темы → отметить → Создать = **4 клика**

### Состояние 3: Генерация (storytelling-прогресс)

Контентная область **трансформируется** в экран прогресса. Статья исчезает — это другой опыт. Sidebar показывает статус по темам.

**Экран прогресса — контентная область:**
- Обложка (уменьшенная, 200px) со спиннером внутри
- Заголовок: «Создаём подкаст...»
- Подзаголовок: «Два ведущих готовятся к эфиру»
- Пошаговый прогресс с реальными цифрами:

```
✅ Сценарий: Формула-1              12 реплик
✅ Запись: Формула-1                 2:14
🎙 Запись: Разработки в обл. ИИ     ...
○  Финальный монтаж
```

Для каждой темы 2 шага: сценарий (scriptwriter) → запись (TTS). Плюс финальный монтаж.

**Sidebar в режиме прогресса:**
```
🎙 СОЗДАЁМ ПОДКАСТ
  ✅ Формула-1         Готово
  ⏳ Разработки в ИИ   Запись...
```

**Автопереход:** когда всё готово → автоматически переключается на подкаст-экран.

### Состояние 4: Подкаст готов — переключатель режимов

Кнопка «Создать подкаст» в header **превращается в переключатель:**

```
[ 📖 Читать | 🎧 Слушать ]
```

Сегментированная кнопка (pill toggle). Активный режим — терракотовый фон. Пользователь переключается одним кликом в любой момент. Один контент, два способа потребления, ноль навигации.

## Подкаст-экран (режим «Слушать»)

### Контентная область

Центрированный layout, вертикальная компоновка:

**1. Мета-строка**
«2 темы · 4 мин 32 сек» (адаптируется: в режиме чтения — «6 мин чтения»)

**2. Обложка (artwork)**
- Квадрат ~280px, border-radius 24px
- Градиент в терракотовых тонах (brand identity)
- Внутри: иконка 🎙, «Утренний брифинг», дата
- Звуковая визуализация (анимированные полоски эквалайзера)
- Анимация играет при воспроизведении, замирает на паузе
- Тень для глубины

**3. Информация о текущем треке**
- Иконка + название темы (например: «🏎 Формула-1»)
- Заголовок секции (например: «Зимние тесты 2026»)
- Меняется при переключении между темами

**4. Прогресс-бар**
- Полоса с кружком-ползунком
- Кликабельная для перемотки
- Текущее время слева, общее справа
- Табличные цифры (monospace) для стабильности

**5. Управление воспроизведением**
```
  ⏮    -15    ▶/❚❚    +15    ⏭
```
- ⏮ / ⏭ — предыдущая / следующая тема
- -15 / +15 — перемотка 15 секунд
- ▶/❚❚ — Play/Pause, большая круглая кнопка (64px), терракотовая, тень
- При «Полном выпуске» темы играют подряд автоматически

**6. Скорость и скачивание**
```
  [ 0.75× ]  [ 1× ]  [ 1.25× ]  [ 1.5× ]    [ ⬇ MP3 ]
```
- Кнопки скорости — pill buttons, активная с terracotta border
- «⬇ MP3» — скачивает текущий трек (или полный выпуск если играет всё)

### Sidebar в режиме «Слушать»

Sidebar трансформируется в треклист:

```
🎧 ТРЕКЛИСТ
  🏎 Формула-1          ▶ |||  (now playing indicator)
  🤖 Разработки в ИИ    2:18

  ┌─────────────────────────┐
  │ Полный выпуск           │
  │ 2 темы · 4 мин 32 сек  │
  └─────────────────────────┘
```

- Активная тема — с анимацией эквалайзера (3 полоски)
- Неактивные темы — показывают длительность
- Блок «Полный выпуск» — карточка внизу с общей длительностью
- Клик по теме в sidebar → плеер прыгает на эту тему

## Edge cases

### Ошибка генерации одной темы

Две темы записались, одна упала. **Не блокируем весь подкаст.** Показываем плеер с готовыми темами, рядом с упавшей в треклисте — кнопка «↻ Повторить».

### Обновление темы статьи

Пользователь обновил тему кнопкой ↻ (v3.42.0) после создания подкаста. Подкаст стал неактуальным. **Не удаляем молча** — показываем индикатор: «Текст обновлён, подкаст устарел» + кнопка «Пересоздать подкаст». Пользователь решает сам.

### Новый брифинг

Пользователь нажал «Сгенерировать» новый брифинг:
- Старый брифинг удаляется (эфемерная модель)
- MP3 файлы удаляются из Vercel Blob (cleanup job)
- Переключатель «Читать/Слушать» исчезает
- Кнопка «Создать подкаст» возвращается
- Чистое состояние

### Мобильная версия

- Sidebar скрыт (Sheet, как сейчас)
- Подкаст-экран занимает весь экран
- Кнопки управления крупнее (touch targets)
- Переключатель «Читать/Слушать» остаётся в header

## Хранение подкаста

### Модель: эфемерный, как брифинг

Подкаст живёт и умирает вместе с брифингом. Никакого архива, никакой библиотеки эпизодов.

- **MP3 файлы** → Vercel Blob
- **Ссылки на MP3** → поле `audioUrls` (JSONB) в таблице брифинга
- **Статус** → поле `audioStatus` в таблице брифинга
- **При удалении брифинга** → cleanup удаляет MP3 из Blob
- **Скачать MP3** → пользователь сохраняет себе, файл живёт у него

В будущем (Фаза Г): подкаст отправляется в Telegram → архив = Telegram.

### БД — расширение существующей таблицы

```sql
ALTER TABLE BriefingHistory ADD COLUMN audioUrls JSONB;
-- Формат: { "topic-1": "https://blob.vercel-storage.com/...", "topic-2": "..." }
-- Нет ключа "full" — полный выпуск = воспроизведение тем подряд

ALTER TABLE BriefingHistory ADD COLUMN audioStatus TEXT DEFAULT 'none';
-- Статусы: none | generating | ready | partial | outdated
-- partial = часть тем готова, часть упала
-- outdated = текст обновлён после генерации подкаста

ALTER TABLE BriefingHistory ADD COLUMN audioDurations JSONB;
-- Формат: { "topic-1": 134, "topic-2": 138 } (секунды)
-- Нужно для UI: показать длительность в треклисте до начала воспроизведения
```

## Технический пайплайн

### Two-step pipeline (per topic)

```
Для каждой выбранной темы (параллельно через Inngest):

1. ScriptGenerator
   Вход: секция статьи (content + title) + контекст (isFirst, isLast, sectionTitles)
   Модель: Gemini 2.5 Flash
   Промпт: briefing-scriptwriter (PE контракт v1)
   Выход: текст сценария "Host: ... Expert: ..."

2. TTSProvider
   Вход: сценарий + голоса (Kore=Host, Puck=Expert)
   Модель: gemini-2.5-flash-preview-tts
   SDK: @google/genai (напрямую, не через Vercel AI SDK)
   Выход: PCM buffer (16-bit, 24kHz, mono)

3. AudioConverter
   Вход: PCM buffer
   Обработка: PCM → WAV header → MP3
   Инструмент: lamejs (pure JS, без ffmpeg — Vercel Functions не имеют ffmpeg)
   Выход: MP3 buffer

4. Storage
   Вход: MP3 buffer
   Хранение: Vercel Blob
   Обновление: audioUrls[topicId] = blob URL, audioDurations[topicId] = seconds
```

### Модели

| Шаг | Модель | Стоимость |
|-----|--------|-----------|
| Сценарий | Gemini 2.5 Flash | ~$0.02/тема |
| TTS | gemini-2.5-flash-preview-tts | ~$0.08/тема |
| **Итого** | | **~$0.10/тема, ~$0.50/полный выпуск (5 тем)** |

### NPM зависимости

```
@google/genai     — Gemini TTS API (SDK)
lamejs            — pure JS MP3 encoder (без ffmpeg)
@vercel/blob      — хранение (уже в проекте)
```

## Шаринг

Полноценный шаринг (публичные ссылки) — не в MVP. Достаточные механизмы:

- **Подкаст:** кнопка «⬇ MP3» → отправить файл в Telegram/WhatsApp
- **Статья:** кнопка копирования 📋 на каждой секции (уже есть)
- **Показать другу:** переключатель «Читать/Слушать» работает всегда — можно показать оба режима на своём устройстве
