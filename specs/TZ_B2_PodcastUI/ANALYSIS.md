### ❓ Требует уточнения

1. **[Прогресс vs чтение]:** При генерации подкаста — статья полностью пропадает, или пользователь может продолжать читать? Рекомендую НЕ скрывать статью. Можно показать компактный прогресс в sidebar или как floating bar. Как решит архитектор?

2. **[Sidebar при «Слушать»]:** Sidebar полностью заменяется на треклист, или треклист — это дополнительная секция? Если полная замена — как вернуться к сохранённым темам и навигации?

3. **[Аудио при переключении режимов]:** ТЗ говорит «аудио продолжает играть при переключении Читать ↔ Слушать». Это значит `<audio>` элемент должен быть на уровне `BriefingPageClient`, а не внутри podcast-player view. Подтверждаю что так реализую — `<audio>` будет в корневом компоненте, а визуальные контролы — в podcast-player. ОК?

4. **[Per-section retry]:** «↻ Повторить» для одной упавшей темы — вызывает тот же `POST /api/briefing/podcast/generate` с `topicIds: [failed-topic]`? Бэкенд поддерживает. Но нужно ли мержить результат или перезаписать? Бэкенд мержит (`updateBriefingAudio` делает spread), так что дополнительная логика не нужна. Просто фиксирую.

5. **[Persistent playback state]:** Если пользователь уходит со страницы `/briefing` и возвращается — плеер должен помнить позицию? Или начинать с начала? Для MVP предлагаю начинать с начала (без localStorage persistence).

6. **[Анимация эквалайзера]:** 3-5 полосок CSS animation — это чисто декоративная анимация при isPlaying. Никакого реального Web Audio API анализа? Подтверждаю — CSS-only bars с `@keyframes`.

## Потенциальные риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Audio API ведёт себя по-разному в Safari vs Chrome (autoplay policies) | Высокая | Среднее | Использовать user gesture для первого play, тестировать Safari |
| Переключение треков при gapless playback — щелчки/паузы | Средняя | Низкое | Preload следующего трека, crossfade не нужен для MVP |
| Vercel Blob URLs могут быть медленными при первом запросе (cold) | Низкая | Низкое | Preload audio, показывать loading state |
| `maxDuration: 120` на endpoint — если 5+ тем, может не успеть | Средняя | Высокое | p-limit(2) уже есть, но 5 тем × 30-60s = может упереться в лимит. Мониторить |
| Audio не играет при фоновой вкладке (mobile browsers) | Средняя | Среднее | Использовать Media Session API для lock screen controls |
| Per-section refresh ломает аудио (текст обновлён, аудио нет) | Высокая | Среднее | Отмечать `audioStatus: 'outdated'` при refresh — реализовать в этом ТЗ |
