# ТЗ-Б2: Podcast UI

**Задача:** Фронтенд подкаста — кнопка, генерация, плеер, переключение режимов  
**Результат:** Пользователь создаёт подкаст из брифинга в 2 клика, слушает с полноценным плеером  
**Зависимость:** ТЗ-Б1 (нужны API endpoint и MP3 URL)  
**Спецификация:** `PODCAST_SPEC.md`, прототип `simply-podcast-prototype.html`

---

## Что нужно сделать

### 4 состояния страницы брифинга

Подкаст — не отдельный URL. Контентная область `/briefing` трансформируется. Одна страница, два режима потребления.

---

### Состояние 1: Подкаст не создан

В header страницы брифинга (справа) — кнопка **«🎙 Создать подкаст»**. Заменяет текущий бейдж «Скоро: подкаст». Видна только когда есть готовый брифинг (`audioStatus === 'none' || 'outdated'`).

Если `audioStatus === 'outdated'` — кнопка с индикатором: «🎙 Пересоздать подкаст» или визуальная метка что подкаст устарел.

---

### Состояние 2: Выбор тем (Popover)

Клик по кнопке → Popover (Radix UI / shadcn):

- **По умолчанию:** «Полный выпуск» (radio), чекбоксы тем disabled
- **Переключение на «Выбрать темы»** → чекбоксы тем активны
- **Кнопка «Создать»** → закрыть popover, вызвать API, перейти к генерации

Темы берутся из текущего `BriefingArticle.sections` (topicId, topicName, emoji).

Основной путь: кнопка → Создать = **2 клика**. Продвинутый: кнопка → Выбрать темы → отметить → Создать = **4 клика**.

---

### Состояние 3: Генерация (storytelling-прогресс)

Контентная область трансформируется в экран прогресса. Статья исчезает.

**Контентная область:**
- Обложка (уменьшенная, ~200px) со спиннером
- «Создаём подкаст...» / «Два ведущих готовятся к эфиру»
- Пошаговый прогресс по темам:
  - Для каждой темы 2 шага: сценарий (количество реплик) → запись (длительность)
  - Иконки: ○ ожидание, 🎙 в процессе, ✅ готово, ❌ ошибка
- Финальный шаг: «Финальный монтаж»

**Sidebar** трансформируется в мини-прогресс: список тем со статусом.

**Хук** `usePodcastGeneration()` — по паттерну существующего `useBriefingGeneration()`. Streaming fetch, парсинг JSON Lines, управление состоянием.

**Автопереход:** когда все темы готовы → переключение на подкаст-экран.

---

### Состояние 4: Подкаст готов — режим «Слушать»

Кнопка «Создать подкаст» **превращается в переключатель:**

```
[ 📖 Читать | 🎧 Слушать ]
```

Сегментированная кнопка (pill toggle). Активный режим — терракотовый фон. Появляется когда `audioStatus === 'ready' || 'partial'`.

---

### Подкаст-экран (режим «Слушать»)

Центрированный layout, вертикальная компоновка:

**1. Мета-строка:** «2 темы · 4 мин 32 сек»

**2. Обложка (artwork):** квадрат ~280px, border-radius 24px, градиент в терракотовых тонах, иконка 🎙, «Утренний брифинг», дата. Анимация эквалайзера при воспроизведении (3-5 полосок, CSS animation).

**3. Инфо текущего трека:** emoji + название темы, заголовок секции. Обновляется при переключении.

**4. Прогресс-бар:** кликабельный, ползунок, текущее/общее время (monospace цифры).

**5. Управление:**
```
⏮  -15  ▶/❚❚  +15  ⏭
```
- ⏮/⏭ — предыдущая/следующая тема
- -15/+15 — перемотка 15 секунд  
- ▶/❚❚ — Play/Pause, большая круглая кнопка (64px), терракотовая

**6. Скорость и скачивание:**
```
[ 0.75× ] [ 1× ] [ 1.25× ] [ 1.5× ]    [ ⬇ MP3 ]
```
Pill buttons, активная с terracotta border. Скачивание — текущий трек (или zip/все если полный выпуск).

**Темы играют подряд** при «Полном выпуске» — автопереход к следующей теме.

---

### Sidebar в режиме «Слушать»

Sidebar трансформируется в треклист:
- «🎧 ТРЕКЛИСТ» — заголовок
- Список тем: emoji, название, длительность или индикатор проигрывания (анимация эквалайзера)
- Карточка «Полный выпуск» внизу: общее количество тем + длительность
- Клик по теме → плеер переключается на неё
- Если тема с ошибкой → кнопка «↻ Повторить» (вызывает API для одной темы)

---

### Edge cases в UI

**Partial (часть тем с ошибкой):**
- Плеер показывает только готовые темы
- В треклисте упавшие темы — серые + «↻ Повторить»

**Outdated (текст обновлён после подкаста):**
- Переключатель видим, но с индикатором
- При переключении на «Слушать» — баннер: «Текст обновлён, подкаст может быть неактуален» + кнопка «Пересоздать»

**Мобилка:**
- Sidebar → Sheet (как сейчас)
- Подкаст-экран на весь экран
- Кнопки управления крупнее (touch targets ≥ 44px)
- Переключатель «Читать/Слушать» в header

---

## Ключевые ограничения

- **HTML5 Audio API** — стандартный `<audio>` элемент, никаких внешних плеер-библиотек
- **Состояние плеера** — React state + refs на `<audio>`. Не нужен глобальный store
- **Переключение режимов** — мгновенное, без перезагрузки. Аудио продолжает играть при переключении «Читать ↔ Слушать»
- **Данные из SSR** — `audioStatus`, `audioUrls`, `audioDurations` приходят с сервера при загрузке страницы (добавить в серверный запрос `getBriefingHistory`)
- **Дизайн-система** — «Тёплый интеллект»: Lora для заголовков, Source Sans 3 для текста, JetBrains Mono для цифр плеера, терракотовые акценты

## Структура компонентов (ожидаемая)

```
components/briefing/
  podcast-button.tsx          — кнопка «Создать подкаст» + popover выбора тем
  podcast-progress.tsx        — экран генерации (storytelling прогресс)
  podcast-player.tsx          — полноценный плеер (artwork, controls, progress bar)
  podcast-sidebar.tsx         — треклист для sidebar
  briefing-mode-toggle.tsx    — переключатель «Читать / Слушать»

hooks/
  use-podcast-generation.ts   — streaming хук (по паттерну use-briefing-generation)
  use-podcast-player.ts       — логика плеера (play/pause, seek, speed, track switching)
```

---

## Как проверить

1. Кнопка «Создать подкаст» видна при готовом брифинге
2. Popover показывает темы, дефолт «Полный выпуск», кнопка «Создать» запускает генерацию
3. Прогресс-экран показывает реальные шаги по каждой теме
4. После генерации — автопереход на подкаст-экран, переключатель появляется
5. Плеер: play/pause, перемотка, переключение тем, скорость, скачивание
6. Sidebar = треклист с навигацией
7. Переключатель «Читать/Слушать» — мгновенный, аудио не прерывается
8. Мобилка: адаптивный layout, Sheet вместо sidebar
