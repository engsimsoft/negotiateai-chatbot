# ТЗ: Tool Activity UX — визуализация работы инструментов

---

## Зачем

Когда AI вызывает инструмент (поиск, создание документа, анализ файла), пользователь видит паузу — ничего не происходит 5-30 секунд. Он думает приложение зависло. Нужно показать **что именно** делает AI прямо сейчас.

**Референс:** Как Claude.ai показывает "Using web search", "Reading file" — свёрнутый блок внутри сообщения с возможностью раскрыть детали по клику.

---

## Что делаем

Показываем tool activity **inline внутри сообщения AI** — компактный блок, который:
- В процессе: иконка + текст + анимация ("🔍 Поиск в интернете...")
- Завершён: иконка + текст + краткий результат ("✓ Поиск завершён · 5 результатов")
- Раскрывается **только по клику пользователя** — детали (запрос, результаты, имя файла)

---

## Техническая основа

### Что уже есть

Vercel AI SDK при streaming стримит tool invocations как части сообщения. В `message.parts` приходят объекты с `type: 'tool-invocation'` и свойством `state`:

- `'partial-call'` — аргументы ещё стримятся
- `'call'` — tool вызван, ждём результат execute()
- `'result'` — tool вернул результат

**Сейчас эти parts просто не рендерятся.** Нужно добавить их рендеринг.

### Где рендерить

В компоненте который проходит по `message.parts` и рендерит каждую часть. Нужно добавить case для `tool-invocation` type. Это работает и в обычном чате, и в Expert Task Chat — потому что tools общие (через `chat-tools.ts`).

## Компоненты

### 1. Конфиг: `lib/ai/tool-activity-config.ts`

Маппинг toolName → UI-представление. Один файл, один объект.

```typescript
type ToolActivityConfig = {
  hidden?: boolean;           // не показывать вообще (технические tools)
  icon: string;               // эмодзи или lucide-react иконка
  activeLabel: string;        // текст в процессе ("Поиск в интернете")
  doneLabel: string;          // текст после завершения ("Поиск завершён")
  showArgs?: boolean;         // показывать аргументы в раскрытом виде
  showResult?: boolean;       // показывать результат в раскрытом виде
  argsFormatter?: (args: any) => string | null;     // что показать из аргументов
  resultFormatter?: (result: any) => string | null;  // краткий текст результата ("5 результатов")
};
```

Маппинг по текущим tools:

| Tool | hidden | icon | activeLabel | doneLabel | Детали |
|------|--------|------|-------------|-----------|--------|
| `web_search` | — | 🔍 | Поиск в интернете | Поиск завершён | args: query, result: кол-во |
| `getWeather` | — | 🌤 | Проверяю погоду | Погода получена | — |
| `getCurrentDate` | ✅ | — | — | — | скрыть |
| `createDocument` | — | 📄 | Создаю документ | Документ создан | args: title/kind |
| `updateDocument` | — | ✏️ | Обновляю документ | Документ обновлён | — |
| `requestSuggestions` | ✅ | — | — | — | скрыть |
| `parseExcel` | — | 📊 | Анализирую таблицу | Таблица проанализирована | args: имя файла |
| `loadSkill` | ✅ | — | — | — | скрыть |
| `readProjectFile` | — | 📂 | Читаю файл проекта | Файл прочитан | args: имя файла |
| `createSnapshot` | ✅ | — | — | — | скрыть (есть SnapshotCard) |
| `read_document` | — | 📖 | Изучаю документ | Документ изучен | args: имя файла |

Принцип: скрываем технические tools (дата, skill, snapshot, suggestions). Показываем то что интересно пользователю.

### 2. Компонент: `ToolActivityIndicator`

Единственный новый UI-компонент.

**Состояние "в процессе"** (state = 'partial-call' или 'call'):
```
┌──────────────────────────────────────┐
│ 🔍  Поиск в интернете...        ⟳   │
└──────────────────────────────────────┘
```
- Иконка слева
- Текст `activeLabel` + "..."
- Анимация справа (спиннер или pulse-точки)
- Фон: `bg-muted`, скруглённые углы, компактный

**Состояние "завершён"** (state = 'result'):
```
┌──────────────────────────────────────┐
│ ✓  Поиск завершён · 5 результатов ▸ │
└──────────────────────────────────────┘
```
- Галочка вместо иконки (или иконка + галочка)
- Текст `doneLabel`
- Если есть `resultFormatter` — краткий результат через " · "
- Шеврон ▸ справа (индикатор что можно раскрыть)
- Клик по всему блоку → раскрытие

**Состояние "раскрыт"** (пользователь кликнул):
```
┌──────────────────────────────────────┐
│ ✓  Поиск завершён · 5 результатов ▾ │
│ ─────────────────────────────────── │
│ Запрос: "ценообразование кофейня"    │
│                                      │
│ • rbc.ru — Обзор рынка...            │
│ • vc.ru — Как открыть кофейню...     │
│ • ...                                │
└──────────────────────────────────────┘
```
- Шеврон ▾ (вниз)
- Разделитель
- Аргументы (если `showArgs`)
- Результат (если `showResult`)
- Повторный клик → сворачивает

### 3. Интеграция в рендеринг сообщений

В месте где рендерятся `message.parts` — добавить обработку `tool-invocation`:

```
if part.type === 'tool-invocation':
  config = TOOL_ACTIVITY_CONFIG[part.toolName]
  if config.hidden → пропустить
  else → <ToolActivityIndicator part={part} config={config} />
```

Это нужно сделать в **обоих** местах рендеринга сообщений:
- Обычный чат (главная)
- Expert Task Chat (задачи проекта)

Если рендеринг частей уже вынесен в общий компонент — достаточно одного места.

## Стилизация

Следовать `docs/design-system.md`:
- Фон блока: `bg-muted`
- Текст: `text-muted-foreground` (в процессе), `text-foreground` (завершён)
- Анимация: `animate-spin` на иконке или pulse-точки
- Шеврон: `lucide-react` → `ChevronRight` / `ChevronDown`
- Border: `border border-border rounded-lg`
- Padding: `px-3 py-2`
- Размер текста: `text-sm`

---

## Что НЕ делаем

- **Не трогаем backend** — данные уже стримятся
- **Не трогаем промпты** — tools работают как есть
- **Не трогаем БД** — ничего не сохраняем
- **Не показываем в Пульсе** — только inline в сообщении
- **Не авторазворачиваем** — только по клику пользователя
- **Не меняем поведение tools** — только визуализация

---

## Результат

- Пользователь всегда видит что AI делает прямо сейчас
- Нет ощущения "зависло" при вызове инструментов
- По клику можно посмотреть детали (что искал, что нашёл, какой файл читает)
- Работает одинаково в обычном чате и в Expert Task Chat
