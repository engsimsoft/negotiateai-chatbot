**Версия:** 2.0

## Суть

Simply строит два слоя персонального интеллекта:

| Слой | Что это | Откуда данные | Фаза |
|------|---------|---------------|-------|
| **MIND** | Память из разговоров | Автоматически из каждого чата | Фаза 1 |
| **Библиотека** | База знаний пользователя | Загрузка файлов, ссылок, видео | Фаза 2 |

Оба слоя живут в одном vector space (pgvector + Voyage AI). Один поисковый запрос находит и факт из разговора трёхмесячной давности, и абзац из загруженного документа.

**Для пользователя разделения не существует.** Он просто спрашивает — Simply знает. Откуда знает (из чата или из документа) — указывается в источнике, но пользователь не переключает режимы.

## Единый провайдер: Voyage AI

### Почему Voyage AI

Voyage AI — рекомендованный Anthropic провайдер для эмбеддингов. Принадлежит MongoDB (с февраля 2025). Simply работает в экосистеме Anthropic — Voyage AI является естественным выбором.

**Voyage AI закрывает ВСЁ, что нужно Simply:**

| Задача | Старый план (январь 2026) | Новый план (апрель 2026) |
|--------|--------------------------|--------------------------|
| Эмбеддинги | OpenAI text-embedding-3-small | **Voyage AI** (voyage-4, voyage-context-3) |
| Реранкинг | Cohere Rerank 3.5 | **Voyage AI** rerank-2.5 |
| Contextual enrichment | Gemini Flash (LLM-вызов на каждый чанк) | **Voyage AI** voyage-context-3 (на уровне модели) |

**Было 3 провайдера → стал 1.** Один API-ключ (`VOYAGE_API_KEY`), одно vector space, одна биллинг-система.

### Ключевые возможности Voyage AI для Simply

**1. Shared Embedding Space (Voyage 4)**

Все модели серии Voyage 4 создают эмбеддинги в одном пространстве. Документы индексируем через voyage-4-large (максимальное качество), запросы обрабатываем через voyage-4-lite (быстро, дёшево). Принцип «умный думает — дешёвый делает» на уровне эмбеддингов.

**2. Contextualized Chunk Embeddings (voyage-context-3)**

Модель для Библиотеки. Создаёт эмбеддинги чанков, которые содержат контекст полного документа — без отдельного LLM-вызова. Превосходит OpenAI-v3-large на 14%, Cohere-v4 на 12%, и даже Anthropic contextual retrieval на 7%.

Что это значит: чанк «ставка выросла с 15% до 18%» из середины договора будет найден по запросу «налоговые условия договора с ООО Ромашка», даже если название компании упоминается только на первой странице.

**3. Instruction-Following Reranker (rerank-2.5)**

Превосходит Cohere Rerank v3.5 на 8% в среднем. Поддерживает инструкции на естественном языке: можно говорить «приоритизируй пункты с рисками» или «ранжируй по хронологии». Контекстное окно 32K токенов (8× больше Cohere).

**4. Multimodal Embeddings (voyage-multimodal-3.5)**

Текст, изображения, видео — в одном vector space. Для будущей фазы Библиотеки: PDF-скриншоты, слайды, фотографии досок с совещаний — всё searchable.

**5. Batch API**

Асинхронная обработка больших объёмов со скидкой 33%. Окно — 12 часов. До 1 ГБ файлов, 100K входов на батч. Идеально для массовой индексации документов в Библиотеке.

**6. Matryoshka Embeddings**

Гибкая размерность: 256, 512, 1024, 2048. Можно оптимизировать хранение и скорость без переиндексации.

### API и конфиденциальность

| Параметр | Значение |
|----------|----------|
| API-ключ | `VOYAGE_API_KEY` (единственное новое подключение) |
| Data retention | Zero-day opt-out (включить при запуске) |
| Бесплатный tier | 200M токенов на аккаунт |
| SDK | TypeScript SDK (официальный, обновляется) |

В разделе конфиденциальности Simply: Voyage AI добавляется к Anthropic в описании обработки данных. Voyage не хранит входные данные после обработки (при opt-out). Это проверяемый факт из их ToS.

### Доменные модели — лучшее качество для каждого кейса

Voyage AI — единственный провайдер с полным набором доменно-специфичных моделей. Каждая обучена на триллионах токенов своей области и значительно превосходит universal-модели. Simply автоматически выбирает модель по типу контента.

| Модель | Домен | Преимущество | Кейс в Simply |
|--------|-------|-------------|---------------|
| **voyage-4-large** | Универсальная | Лучшая general-purpose на RTEB | MIND (факты из чатов), общие документы |
| **voyage-context-3** | Длинные документы | +14% vs OpenAI, контекст чанков | Библиотека (PDF, DOCX, учебники) |
| **voyage-law-2** | Юриспруденция | +15% vs OpenAI на юр. датасетах | Договоры, регламенты, чек-листы, НПА |
| **voyage-finance-2** | Финансы | +7% vs OpenAI, +12% vs Cohere | Сметы, финансовые отчёты, инвестиционные меморандумы |
| **voyage-code-3** | Программирование | +15% vs OpenAI на code tasks | GitHub-репозитории, техническая документация |
| **voyage-4-lite** | Быстрый поиск | Shared space с voyage-4 | Все запросы пользователя (retrieval) |
| **voyage-multimodal-3.5** | Текст + изображения + видео | Единое пространство модальностей | PDF-скриншоты, слайды, фото досок (будущее) |

**Как это работает для пользователя:**

Пользователь загружает файл → Simply определяет тип контента → автоматически выбирает оптимальную модель:

- Загрузил договор аренды → `voyage-law-2` (понимает юридические термины, находит нужный пункт)
- Загрузил финансовый отчёт → `voyage-finance-2` (понимает P&L, cashflow, налоговые термины)
- Подключил GitHub-репозиторий → `voyage-code-3` (понимает код, функции, зависимости)
- Загрузил книгу или статью → `voyage-context-3` (чанки с контекстом документа)
- Просто общается в чате → `voyage-4` для MIND-фактов

**Пользователь не выбирает модель.** Он загружает файл — Simply делает лучшее автоматически. Apple-подход.

**Все модели совместимы.** Один поисковый запрос через `voyage-4-lite` ищет по всем эмбеддингам — юридическим, финансовым, кодовым. Разные модели при индексации, единый поиск при retrieval.

**Кейс юриста (целевой пользователь Simply):**
Загрузил 50 договоров → voyage-law-2 проиндексировал с пониманием юридических конструкций. Загрузил сметы по проектам → voyage-finance-2 проиндексировал с пониманием финансовых метрик. Спрашивает: «В каком договоре есть пункт об индексации с привязкой к ИПЦ, и какой бюджет был по этому проекту?» → один запрос находит и юридический пункт, и финансовый документ.

**Кейс Harvey (референс):** Harvey — ведущий AI для юристов — использует именно Voyage для embeddings. Их кастомная модель на базе voyage-law-2 снизила количество нерелевантных результатов на 25%.

## Единая инфраструктура

### Что не меняется

| Компонент | Сервис | Статус |
|-----------|--------|--------|
| Хостинг | Vercel | ✅ Остаётся |
| БД | Neon PostgreSQL | ✅ Остаётся |
| Файлы | Vercel Blob | ✅ Остаётся |
| Фреймворк | Next.js 15 | ✅ Остаётся |
| ORM | Drizzle | ✅ Остаётся |

### Что добавляется (один раз, для обеих фаз)

**pgvector** — расширение PostgreSQL для векторного поиска. Neon поддерживает нативно. Одна SQL-команда: `CREATE EXTENSION IF NOT EXISTS vector`.

**HNSW-индекс** — быстрый approximate nearest neighbor search. Создаётся один раз, работает для обоих слоёв.

**Voyage AI API** — единственный новый внешний сервис.

### Единая размерность

Все эмбеддинги в Simply: **1024 dimensions**. Это дефолт для Voyage 4 и voyage-context-3. Один HNSW-индекс, один тип колонки `vector(1024)`, единый поиск.

При необходимости оптимизации — Matryoshka позволяет уменьшить до 512 без переиндексации.

## Фаза 1: MIND — Память из разговоров

### Цель

Чат, который никогда не забывает. Пользователь просто пишет — система запоминает автоматически. Никаких действий от пользователя.

### Что получает пользователь

- Написал в январе «встреча с Петровым 15 марта» → в марте AI помнит без просьбы
- Обсуждал стратегию 3 месяца назад → спрашивает «что мы решили по маркетингу?» → AI знает
- Никаких «новых сессий», никакого «повторите контекст»

### Три уровня памяти Simply

| Уровень | Механизм | Срок жизни | Что хранит |
|---------|----------|------------|------------|
| Оперативная | Контекстное окно (200K / 1M) | Текущая сессия | Последние сообщения |
| Кратковременная | Anthropic Compaction API | Текущий чат | Сжатая история разговора |
| Долговременная | MIND (pgvector + Voyage) | Вечно | Извлечённые факты, Opus-профиль |

**Ключевой момент:** Sonnet извлекает факты из КАЖДОГО сообщения — до того как Compaction сожмёт разговор. Даже если Compaction потеряет деталь — факт уже сохранён в pgvector навсегда.

### Архитектура извлечения

Два уровня (принцип «умный думает — дешёвый делает»):

| Уровень | Модель | Когда | Что делает |
|---------|--------|-------|------------|
| Извлечение | Claude Sonnet | Каждое сообщение, fire-and-forget | Извлекает факты, намерения, связи |
| Консолидация | Claude Opus | Каждые 5-10 сообщений + раз в сутки | Ревизия: противоречия, устаревшее, синтез |

> Никакого Haiku. Для аудитории Simply экономия $0.5 на сообщении — ноль. Потеря нюанса — катастрофа.

### Бесконечный разговор: Anthropic Compaction API

Compaction API (`compact-2026-01-12`) — серверная суммаризация контекста. Когда разговор подходит к лимиту окна, API автоматически сжимает старую часть. Бесконечный разговор без «начните новый чат».

Compaction заменяет самодельную snapshot-систему (ТЗ-C3).

**Но Compaction не заменяет MIND.** Compaction сжимает, но теряет детали. MIND извлекает факты ДО сжатия — ничего не теряется.

### Стек MIND

| Компонент | Технология | Роль |
|-----------|-----------|------|
| Embedding | Voyage AI voyage-4 (1024 dim) | Векторизация фактов |
| Query embedding | Voyage AI voyage-4-lite (1024 dim) | Быстрый поиск (shared space) |
| Vector DB | pgvector в Neon PostgreSQL | Хранение и поиск |
| Index | HNSW (cosine similarity) | Быстрый approximate search |
| Hybrid search | vector + SQL WHERE (userId, category, дата) | Фильтрация |
| ORM | Drizzle | Уже в проекте |
| Извлечение фактов | Claude Sonnet (fire-and-forget) | Понимание нюансов |
| Консолидация | Claude Opus (периодически + ночью) | Ревизия и профиль |
| Бесконечный чат | Anthropic Compaction API | Серверная суммаризация |

### Таблица `memory_entry`

```
memory_entry:
  id            uuid PK
  userId        FK → User
  content       text (текст факта)
  embedding     vector(1024)
  category      enum: fact | task | preference | calendar | person | decision
  confidence    float (0.0-1.0)
  source        FK → Chat (откуда извлечено)
  supersededBy  FK → memory_entry (если заменён новым фактом)
  accessCount   int (сколько раз использован в retrieval)
  decayScore    float (затухание со временем)
  createdAt     timestamp
  updatedAt     timestamp
  
  Индексы:
    - HNSW на embedding (vector_cosine_ops)
    - userId + category
    - userId + confidence DESC
```

### Дедупликация

При записи нового факта — semantic search по существующим фактам того же пользователя (cosine > 0.85). Если найден похожий — обновить, не создавать дубль. Старый помечается `supersededBy`.

### Opus-профиль

Ежедневно Opus получает все активные факты и генерирует нарративный профиль (800-1200 слов): кто этот человек, бизнес, ключевые люди, приоритеты, открытые вопросы. Профиль — первый блок system prompt.

Два слоя контекста в каждом разговоре:
1. **«Кто этот человек»** — Opus-профиль (~500 токенов)
2. **«Что релевантно сейчас»** — pgvector retrieval, top-5-10 фактов (~300 токенов)

### Точка интеграции

Текущий flow:
```
Запрос → загрузка истории → snapshot trimming → streamText → сохранение
```

С MIND + Compaction:
```
Запрос → Compaction (серверная) → retrieveRelevantContext() → 
инжекция в system prompt → streamText → сохранение → 
fire-and-forget: extract + embed
```

### Три смертных греха (защиты)

1. **Ложная память** → confidence score на каждом факте; мягкая форма в промпте
2. **Неуместное воспоминание** → retrieval привязан к контексту текущего вопроса
3. **Забытое важное** → Sonnet (не Haiku) на извлечении + Opus-ревизия

### UX памяти

- **Невидимость.** Нет лоадера «загружаю память...». Нет бейджа «использовано 5 воспоминаний»
- **Тишина по умолчанию.** Хороший помощник не кричит «Я помню ваш кофе!»
- **Нарастающая точность.** День 1 → мало. Неделя → люди и проекты. Месяц → стиль мышления
- **Страница «Что ты обо мне знаешь?»** — полная прозрачность + удаление в один клик

### Конфиденциальность MIND

- Полная изоляция: `WHERE userId = :currentUserId` без исключений
- Данные не для обучения AI (Anthropic API ToS + Voyage opt-out)
- Мгновенное физическое удаление: `DELETE FROM memory_entry WHERE id = ...`
- Кнопка «Удалить всё обо мне»
- Row Level Security (RLS) в PostgreSQL
- Шифрование at rest (Neon) и in transit (TLS)

### Что нужно для запуска MIND

1. Миграция БД: `CREATE EXTENSION vector`, таблица `memory_entry`, HNSW-индекс, RLS
2. Anthropic Compaction API: включить в `chat/route.ts`, упростить snapshot-систему
3. `lib/ai/memory/extract.ts` — Sonnet-извлечение (fire-and-forget)
4. `lib/ai/memory/embed.ts` — Voyage embed + upsert с дедупликацией
5. `lib/ai/memory/retrieve.ts` — semantic search + hybrid filter
6. `lib/ai/memory/consolidate.ts` — Opus-консолидация и профиль
7. Изменение `chat/route.ts` — Compaction + retrieve + extract
8. PE-контракт: промпт для Sonnet-извлечения и Opus-консолидации
9. API + UI: страница «Что ты обо мне знаешь?» (`/settings/memory`)
10. API: удаление фактов и полная очистка

### Стоимость MIND (на активного пользователя, 50 сообщений/день)

| Компонент | Расчёт | В день |
|-----------|--------|--------|
| Sonnet extract | 50 × ~5₽ | 250₽ |
| Opus консолидация | ~10 × 30₽ | 300₽ |
| Opus ночной профиль | 1 × 50₽ | 50₽ |
| Voyage embedding | ~100 × 0.1₽ | 10₽ |
| pgvector retrieval | SQL | 0₽ |
| **Итого** | | **~600₽/день ≈ $180/мес** |

### Развитие MIND (после Фазы 1)

| Этап | Название | Что добавляет |
|------|----------|---------------|
| MIND-2 | Граф знаний + Живая карта | Сущности, связи, дерево тем, календарь идей |
| MIND-2.5 | Контекстный поиск | Замена Google — исследование с пониманием контекста пользователя |
| MIND-3 | Проактивность | AI пишет первым, anticipation engine |

MIND-1 — самодостаточный продукт. MIND-2 и MIND-3 усиливают, но не обязательны.

## Фаза 2: Библиотека — База знаний пользователя

### Цель

Персональное хранилище документов, к которому AI обращается при ответах. Пользователь загружает файлы, ссылки, видео — система автоматически обрабатывает и индексирует. Ответы с указанием источников.

**Принцип:** Загрузил и забыл. Никаких настроек, параметров, технических решений от пользователя.

### Что получает пользователь

- Загрузил архив постов → агент проверяет: что уже писал по теме? Не повторяется
- Загрузил учебник → агент отвечает ТОЛЬКО на его основе, со ссылкой на страницу
- Загрузил шаблоны договоров → агент сравнивает новый договор с эталоном
- Загрузил протоколы совещаний → агент отвечает «что мы решили по логистике в Q3?»

### Целевые кейсы

**Блогеры / контент-мейкеры** — архив постов, стиль, отсылки к прошлому контенту.  
**Маркетологи** — конкуренты, бренд-бук, исследования рынка.  
**Студенты** — учебники, лекции, материалы курса. Нет галлюцинаций — ответ проверяем по источнику.  
**Юристы** — шаблоны договоров, чек-листы, сравнение с эталоном.  
**HR** — вакансии, регламенты, онбординг.  
**Предприниматели** — протоколы, стратегии, отчёты, история решений.

| Источник | Как добавляется | Обработка |
|----------|-----------------|-----------|
| PDF (цифровой) | Drag & drop | Извлечение текста (pdf-parse) |
| PDF (скан) | Drag & drop | OCR (Google Document AI) |
| DOCX | Drag & drop | Парсинг (mammoth) |
| TXT / MD | Drag & drop | Прямое чтение |
| Изображения | Drag & drop | Vision AI — описание содержимого |

**Расширение (Фаза 2b):**

| Источник | Как добавляется | Обработка |
|----------|-----------------|-----------|
| Сайты | Ссылка | Парсинг HTML (Supadata / Jina) |
| YouTube | Ссылка | Транскрипт (Supadata API) |
| Аудио/Видео файлы | Drag & drop | Транскрибация (ElevenLabs Scribe v2) |
| TikTok / Instagram / Facebook / X | Ссылка | Транскрипт (Supadata API) |

**Интеграции (Фаза 2c):**

| Источник | Описание |
|----------|----------|
| Telegram-канал | Импорт постов |
| Google Drive | Синхронизация папки |
| Notion | Импорт страниц |
| GitHub-репозиторий | Клонирование + индексация кодовой базы (OAuth) |

**GitHub-интеграция — почему это важно.** С приходом вайб-кодинга инженеры, менеджеры и предприниматели пишут приложения через AI. Их кодовая база — такой же рабочий документ, как договор или презентация. Проблема Claude Projects: весь репозиторий грузится в контекст (200K лимит), большие проекты не влезают. Simply решает это через RAG: каждый файл → chunking → voyage-context-3 → pgvector. При вопросе — semantic search находит 5-10 релевантных чанков. Хоть миллион строк — контекстное окно не страдает. Voyage AI предлагает специализированную модель `voyage-code-3` для кода — лучшее качество retrieval для programming languages.

### Стек Библиотеки

| Компонент | Технология | Зачем |
|-----------|-----------|-------|
| Embedding документов | **voyage-context-3 / voyage-law-2 / voyage-finance-2 / voyage-code-3** (авто-роутинг по типу контента, 1024 dim) | Доменно-оптимальные чанки |
| Embedding запросов | **voyage-4-lite** (1024 dim) | Быстрый поиск (shared space) |
| Реранкинг | **rerank-2.5** + instructions | Точное ранжирование |
| Массовая индексация | **Voyage Batch API** (−33%) | Большие коллекции |
| Vector DB | pgvector (та же БД, что MIND) | Единый поиск |
| Keyword search | PostgreSQL Full-Text Search (tsvector) | Hybrid search |
| Комбинирование | Hybrid Search с RRF | Vector + keyword |
| Фоновая обработка | Vercel Cron + p-limit / Inngest (TBD) | Обработка > 60 сек |
| Хранение оригиналов | Vercel Blob | Файлы пользователей |
| OCR | Google Document AI | Качество сканов |
| Транскрипция | ElevenLabs Scribe v2 | Аудио/видео файлы (batch + realtime) |
| Видео-транскрипты | Supadata API | YouTube/TikTok/Instagram |

### Почему ElevenLabs Scribe, а не Deepgram + AssemblyAI

Старый план использовал два провайдера: Deepgram Nova-3 для streaming (voice input) и AssemblyAI для batch (стенограмма, diarization). ElevenLabs Scribe v2 закрывает оба кейса одним API:

| Кейс | Было | Стало |
|------|------|-------|
| Voice Input (streaming, русский) | Deepgram Nova-3 | ElevenLabs Scribe v2 Realtime (~150ms) |
| Стенограмма (batch, diarization) | AssemblyAI Async + LeMUR | ElevenLabs Scribe v2 (до 48 спикеров) |
| Транскрипция для Библиотеки | Deepgram batch | ElevenLabs Scribe v2 |
| TTS (подкаст, озвучка) | Gemini TTS (текущий) | ElevenLabs TTS (будущее) |

Scribe v2: 90+ языков (включая русский), best-in-class WER, определение эмоций и звуковых событий, keyterm prompting для доменных терминов, entity detection. Один API-ключ (`ELEVENLABS_API_KEY`) на всё аудио в Simply — и ввод, и вывод.

Тот же принцип, что с Voyage AI: один лучший провайдер закрывает все задачи в своей области.

### Почему voyage-context-3, а не voyage-4-large для документов

voyage-context-3 специально создан для chunked documents. Обычная модель (даже voyage-4-large) создаёт эмбеддинг чанка изолированно — чанк теряет контекст документа. voyage-context-3 принимает на вход все чанки документа разом и создаёт эмбеддинг каждого с учётом полного контекста.

Это заменяет contextual enrichment через LLM (Gemini Flash), который закладывался в январском RAG-концепте. Дешевле, быстрее, качественнее.

### Chunking

| Параметр | Значение |
|----------|----------|
| Стратегия | Recursive (универсальная) |
| Размер | 400-500 токенов |
| Overlap | 15% |
| Contextual enrichment | **Не нужен** — voyage-context-3 делает это на уровне модели |

### Поиск в Библиотеке

```
Запрос пользователя
       ↓
voyage-4-lite embed (input_type: "query")
       ↓
┌──────────────────────────────────────┐
│  Hybrid Search                       │
│  ├─ Vector: pgvector cosine          │
│  └─ Keyword: PostgreSQL tsvector     │
│  → RRF merge (top 50)               │
└──────────────────────────────────────┘
       ↓
rerank-2.5 (с контекстной инструкцией)
       ↓
Top 5-10 чанков → в контекст LLM
       ↓
Ответ с источниками (документ, страница, чанк)
```

### Таблицы Библиотеки

```
knowledge_document:
  id            uuid PK
  userId        FK → User
  projectId     FK → Project (опционально)
  fileName      text
  fileType      text (pdf, docx, txt, url, youtube, audio)
  fileSize      int
  blobUrl       text (Vercel Blob)
  status        enum: pending | processing | completed | failed
  metadata      jsonb (страницы, длительность, автор, и т.д.)
  createdAt     timestamp
  updatedAt     timestamp

knowledge_chunk:
  id            uuid PK
  documentId    FK → knowledge_document ON DELETE CASCADE
  userId        FK → User
  content       text
  embedding     vector(1024)
  embeddingModel text (voyage-context-3 | voyage-law-2 | voyage-finance-2 | voyage-code-3)
  searchVector  tsvector (автообновление триггером)
  chunkIndex    int
  tokenCount    int
  metadata      jsonb (страница, таймкод, заголовок секции)
  createdAt     timestamp

  Индексы:
    - HNSW на embedding (vector_cosine_ops)
    - GIN на searchVector
    - userId + documentId
```

### Фоновая обработка

Vercel serverless имеет timeout 60 секунд. Обработка большого PDF не укладывается. Два варианта (решение при проектировании ТЗ):

**Вариант A: Inngest** — нативная интеграция с Vercel, step functions, retry, мониторинг. Бесплатно до 25K запусков/месяц. Требует установки нового сервиса.

**Вариант B: Vercel Cron + p-limit** — уже используется в проекте. Разбиваем обработку на мелкие шаги, каждый < 60 сек. Проще, но менее надёжно (нет автоматических retry).

### Citations / Источники

Каждый ответ на основе Библиотеки обязательно содержит источник:

```
📎 Источник: Финансовый_менеджмент.pdf, глава 3, стр. 47
📎 Источник: YouTube — «Лекция по маркетингу», таймкод 14:23
📎 Источник: competitor-site.com, раздел «О компании»
```

Формат зависит от типа документа. Для PDF — страница. Для видео — таймкод. Для сайта — URL. Метаданные хранятся в `metadata` чанка.

## Unified Retrieval: поиск по всему

Когда обе фазы реализованы, один запрос ищет в обоих слоях:

```
Запрос пользователя
       ↓
voyage-4-lite embed (input_type: "query", 1024 dim)
       ↓
┌────────────────────────┬────────────────────────┐
│  MIND (memory_entry)   │  Библиотека            │
│  vector search         │  hybrid search + RRF   │
│  + SQL filter          │  + rerank-2.5          │
│  top-5 фактов          │  top-5 чанков           │
└────────────────────────┴────────────────────────┘
       ↓
Merge + ранжирование
       ↓
Контекст для LLM:
  1. Opus-профиль (кто этот человек)
  2. Релевантные факты из MIND
  3. Релевантные чанки из Библиотеки
  4. Источники для каждого элемента
```

**Это работает потому, что Voyage 4 и voyage-context-3 создают эмбеддинги в совместимом пространстве (1024 dim, cosine similarity).** Один HNSW-индекс может искать по обоим таблицам, или два индекса с merge — архитектурное решение при проектировании ТЗ.

## Ключевые принципы

1. **Один провайдер — Voyage AI.** Embeddings, reranking, multimodal — всё в одном месте, одном пространстве, одном API-ключе
2. **Загрузил и забыл.** Никаких настроек от пользователя — ни для памяти, ни для документов
3. **Качество, не экономия.** voyage-4-large для индексации, rerank-2.5 с инструкциями, Sonnet для извлечения, Opus для консолидации
4. **Источники обязательны.** Каждый ответ с указанием откуда информация
5. **Конфиденциальность — фундамент.** Изоляция, opt-out, прозрачность, мгновенное удаление
6. **MIND первый.** Создаёт инфраструктуру, которую Библиотека переиспользует
7. **Один паттерн — `input_type`.** При индексации — `document`, при поиске — `query`. Везде и всегда
