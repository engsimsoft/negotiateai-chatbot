# ТЗ: Карточки MIND → артефакты с визуализацией

**Версия:** v3.77.0
**Приоритет:** Высокий
**Одна цель:** Нажатие на карточку MIND показывает полноценную визуализацию всех фактов этой категории — не редирект в чат.

---

## Проблема

Сейчас: карточка на `/context` показывает count + 2 preview-факта. Нажатие → редирект на `/simply` без фокуса. Пользователь видит badge «5 задач», нажимает — и попадает в обычный чат. Декоративные карточки.

Для органайзера это неприемлемо. Открыл записную книжку → видишь записи. Не «спроси AI что у тебя записано».

## Решение

Нажатие на карточку → открывается **страница категории** с визуализацией всех фактов. Данные — напрямую из MIND, без AI-вызова. Быстро, бесплатно, надёжно.

---

## Что сделать

### 1. Расширить API: полные факты по категории

Текущий endpoint `/api/user/memory/context` отдаёт только `{ category, count, preview: string[] }`. Этого недостаточно — нужны полные факты для визуализации.

**Новый endpoint:** `GET /api/user/memory/context/[category]`

Возвращает:
```typescript
{
  category: string,           // "task" | "calendar" | ...
  facts: Array<{
    id: string,               // для удаления/редактирования в будущем
    content: string,          // полный текст факта
    createdAt: string,        // дата создания
    source: string,           // "explicit" | "extracted"
    // metadata если есть (priority, date, status — из content, парсить не нужно)
  }>,
  totalCount: number
}
```

Данные из `memory_entry WHERE userId = :id AND category = :category AND isActive = true`, сортировка по `createdAt DESC`.

Claude Code: посмотри существующую функцию `getMemorySummaryByCategory()` — скорее всего нужна аналогичная `getFactsByCategory(userId, category)` которая вернёт полные записи вместо preview.

### 2. Страница категории: `/context/[category]`

Новая страница (dynamic route). Открывается при клике на карточку в `/context`.

**Общая структура (одинаковая для всех 7 категорий):**
- Заголовок с иконкой категории и count
- Кнопка «Назад» → `/context`
- Список фактов с визуализацией (формат зависит от категории — см. ниже)
- Каждый факт: текст + дата + бейдж source (если explicit — «Вы записали», если extracted — «Из разговора»)
- Пустое состояние если фактов нет: «Пока нет записей. Скажите Simply „задача: ..." чтобы добавить.» (текст адаптировать под категорию)

### 3. Визуализация по категориям

Не нужны сложные интерактивные виджеты. Нужны **чистые, читаемые списки** в стиле Simply — тёплый интеллект, минимализм.

| Категория | Визуализация |
|-----------|-------------|
| **Задачи** (task) | Список карточек. Каждая: текст задачи, дата создания. Иконка ✓ слева. Без чекбоксов — статус задач пока не реализован |
| **Календарь** (calendar) | Список карточек, сгруппированных по дате (если дата парсится из content). Если дата не парсится — просто хронологический список |
| **Решения** (decision) | Список карточек с вертикальной timeline-линией слева (точки по датам). Новые сверху |
| **Люди** (person) | Карточки с именем (первая строка content) и контекстом. Аватар-плейсхолдер (инициалы) |
| **Идеи** (idea) | Карточки с иконкой 💡. Простой список, новые сверху |
| **Заметки** (fact) | Карточки с иконкой 📝. Простой список, новые сверху |
| **Предпочтения** (preference) | Компактный список пар «что → как». Формат профиля/настроек |

**Принцип:** если сомневаешься в формате — делай простой список карточек. Лучше чистый список чем сломанный парсинг дат из свободного текста.

### 4. Навигация

**Из `/context`:** клик по карточке → `/context/task`, `/context/calendar`, и т.д. (вместо текущего `/simply`)

**Из страницы категории:** кнопка «Назад» → `/context`. Кнопка «Открыть Simply» → `/simply` (если хочет обсудить факты в чате).

**Из левого sidebar (будущее):** это отдельное мини-ТЗ (#5). Пока навигация только через dashboard `/context`.

### 5. Обновить текущую страницу `/context`

Минимальные изменения:
- Клик по карточке: было `→ /simply`, стало `→ /context/[category]`
- Всё остальное без изменений (badge, preview, Opus-профиль, кнопки)

---

## Чего НЕ делать

- НЕ делать интерактивное редактирование/удаление фактов в артефактах — для этого есть `/settings/memory`
- НЕ парсить структуру из content (даты, приоритеты, статусы) — факты хранятся как свободный текст, парсинг ненадёжен. Просто показывать content как есть
- НЕ вызывать AI для генерации артефактов — данные напрямую из БД
- НЕ менять левый sidebar — это отдельное ТЗ
- НЕ добавлять пагинацию — пока не нужна. Если у категории 100+ фактов, показать все (виртуализацию списка можно добавить позже)

## Критерии приёмки (проверки в браузере)

1. **Навигация:** на `/context` нажать карточку «Задачи» → открывается `/context/task` с полным списком задач
2. **Данные:** все факты категории отображаются (не только 2 preview). Сравнить с `/settings/memory` — количество совпадает
3. **Все 7 категорий:** каждая карточка ведёт на свою страницу, каждая отображает факты
4. **Пустая категория:** если фактов нет — показывается empty state с подсказкой
5. **Source badge:** факты от saveFact показывают «Вы записали», от Extract — «Из разговора» (или аналогичный индикатор)
6. **Назад:** кнопка «Назад» возвращает на `/context`
7. **Скорость:** страница категории загружается без задержки (нет AI-вызова, только запрос к БД)
8. **Mobile:** на мобильном экране карточки фактов читаемы, не обрезаны
