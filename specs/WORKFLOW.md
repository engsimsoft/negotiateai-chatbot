## КРИТИЧНОЕ ПРАВИЛО

**Задача НЕ выполнена пока не прошла валидация!**

```
❌ "Код написан" — НЕ выполнено
❌ "Я просмотрел код" — НЕ валидация
✅ npx tsc --noEmit = 0 ошибок — валидация
✅ npm run build пройден — валидация
✅ Проверено в браузере — валидация
✅ Пользователь подтвердил — валидация
```

---

## Быстрый старт

Когда получаешь новое ТЗ:

```
1. Создай папку: specs/TZ_XX_Name/
2. Скопируй содержимое ТЗ в SPEC.md
3. Создай ANALYSIS.md с анализом
4. Дождись ответов на вопросы
5. Создай ROADMAP.md
6. Начни разработку
```

---

## Структура папки ТЗ

```
specs/TZ_XX_Name/
├── SPEC.md           # Само ТЗ (спецификация)
├── ANALYSIS.md       # Анализ, вопросы, риски
├── ROADMAP.md        # План внедрения (этапы)
├── CHANGELOG.md      # История изменений по этому ТЗ
├── HANDOFF.md        # Передача между сессиями
└── notes/            # (опционально) Brainstorm, наброски
```

## Описание файлов

### SPEC.md
**Что:** Само техническое задание (копия из браузера Claude)
**Когда создаётся:** В начале работы
**Кто редактирует:** Только пользователь

### ANALYSIS.md
**Что:** Анализ ТЗ, вопросы, выявленные риски
**Когда создаётся:** Сразу после получения SPEC.md
**Формат:**
```markdown
# Анализ ТЗ-XX

## Резюме
Краткое описание что нужно сделать.

## Вопросы для уточнения
1. ...?
2. ...?

## Потенциальные риски
- Риск 1
- Риск 2

## Зависимости
- Что нужно сделать до начала
- Какие компоненты затронуты

## Оценка сложности
- [ ] Простое (1-2 сессии)
- [ ] Среднее (3-5 сессий)
- [ ] Сложное (5+ сессий)
```

### ROADMAP.md
**Что:** План внедрения с этапами
**Когда создаётся:** После ответов на вопросы из ANALYSIS.md
**Формат:**
```markdown
# Roadmap ТЗ-XX

## Этапы

### Этап 1: Название
**Цель:** ...
**Файлы:** ...
**Критерий готовности:** ...

### Этап 2: Название
...
```

### CHANGELOG.md
**Что:** История изменений в рамках этого ТЗ
**Когда обновляется:** После каждой сессии
**Формат:**
```markdown
# Changelog ТЗ-XX

## Сессия N — YYYY-MM-DD

### Added
- Что добавлено

### Changed
- Что изменено

### Fixed
- Что исправлено

### Files
- file1.tsx
- file2.ts
```

### HANDOFF.md
**Что:** Передача контекста между сессиями
**Когда обновляется:** В конце каждой сессии
**Формат:**
```markdown
# Передача сессии ТЗ-XX

**Дата:** YYYY-MM-DD
**Сессия:** N

## Статус этапов
- [x] Этап 1: ...
- [x] Этап 2: ...
- [ ] Этап 3: ... ← ТЕКУЩИЙ

## Следующая сессия: начни с
1. Конкретное действие
2. Конкретное действие

## В процессе
- Файл — что с ним делали

## Блокеры / Вопросы
- (если есть)
```

## Фазы работы

### Фаза 1: Анализ

**Триггер:** Получено новое ТЗ
**Действия:**
1. Создать папку `specs/TZ_XX_Name/`
2. Сохранить ТЗ в `SPEC.md`
3. Внимательно прочитать ТЗ
4. Создать `ANALYSIS.md`:
   - Задать уточняющие вопросы
   - Выявить риски
   - Оценить сложность
5. **СТОП** — дождаться ответов от пользователя

**Выход:** Пользователь ответил на все вопросы

### Фаза 2: Планирование

**Триггер:** Есть ответы на вопросы
**Действия:**
1. Создать `ROADMAP.md` с этапами
2. Создать пустой `CHANGELOG.md`
3. Создать `HANDOFF.md` с начальным статусом
4. Показать план пользователю

**Выход:** Пользователь одобрил план

### Фаза 3: Разработка

**Триггер:** План одобрен
**Действия (каждая сессия):**
1. Прочитать `HANDOFF.md` — понять где остановились
2. Работать по `ROADMAP.md`
3. **После КАЖДОЙ задачи:**
   - Запустить `npx tsc --noEmit`
   - Есть ошибки? → Исправить ДО отметки [x]
4. **После КАЖДОГО этапа:**
   - Запустить `npm run build`
   - Проверить в браузере
   - **Запросить мануальный тест у пользователя**
   - Дождаться подтверждения
5. В конце сессии:
   - Обновить `CHANGELOG.md` (что сделано)
   - Обновить `HANDOFF.md` (для следующей сессии)

**⛔ Gate-keeping:**
- НЕ начинать следующий этап без валидации текущего
- НЕ отмечать [x] без реальной проверки

**Выход:** Все этапы ROADMAP выполнены И провалидированы

### Фаза 4: Финализация

**Триггер:** Разработка завершена, тесты пройдены
**Действия:**
1. Мануальное тестирование (пользователь)
2. Перенести `CHANGELOG.md` → главный `CHANGELOG.md`
3. Обновить `SIMPLY_STATUS.md`
4. Обновить `CLAUDE.md`
5. Обновить `package.json` (версия)
6. Переместить папку: `mv specs/TZ_XX/ _archive/`

**Выход:** ТЗ в архиве, документация актуальна

## Именование

**Формат папки:** `TZ_XX_ShortName`

Примеры:
- `TZ_07A_Glavnaya`
- `TZ_08_ToolActivity`
- `TZ_09_RAG`

**Версионирование:**
- Minor features: X.Y.0 → X.Y+1.0
- Major changes: X.Y.Z → X+1.0.0
- Patches: X.Y.Z → X.Y.Z+1

---

## Важно

1. **Не редактируй главную документацию во время работы** — только в Фазе 4
2. **Всегда обновляй HANDOFF.md** — это твоя память между сессиями
3. **Задавай вопросы в ANALYSIS.md** — лучше спросить, чем переделывать
4. **CHANGELOG.md по сессиям** — не по дням, а по сессиям работы
