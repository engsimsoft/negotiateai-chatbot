# ТЗ-A1: Новая страница проекта — Layout

**Версия:** 1.0  
**Дата:** 2026-02-08  
**Приоритет:** 🔴 Высокий  
**Зависимости:** Нет (фундамент для всей оркестрации)

---

## Цель

Перестроить страницу проекта (`/projects/[id]`) из текущего карточного layout в двухколоночный layout с фазовой рабочей областью. Это фундамент для всей системы оркестрации проекта.

**Что меняется:** layout страницы, организация компонентов, появление фаз проекта.  
**Что НЕ меняется:** данные (те же queries), роутинг, существующая функциональность чатов и файлов.

---

## Результат

Пользователь открывает проект и видит:
- **Слева** — Пульс проекта (навигационная панель): план задач, файлы, паспорт
- **Справа** — Рабочая область, содержимое которой зависит от фазы проекта
- **Справа (overlay)** — Drawer Менеджера, открывается по кнопке

На этом этапе рабочая область показывает заглушки для будущих фаз. Drawer Менеджера — каркас без AI.

## Фазы проекта

Новая колонка `phase` в таблице `Project`:

```sql
ALTER TABLE "Project" ADD COLUMN "phase" varchar(20) NOT NULL DEFAULT 'setup';
-- Допустимые значения: setup, documents, planning, approved, execution, completed
```

**Логика переходов (на этом этапе — ручная, позже автоматическая):**

| Из | В | Триггер (будущий) |
|---|---|---|
| setup | documents | Первый вход в проект |
| documents | planning | Нажатие «Начать планирование» |
| planning | approved | Утверждение плана |
| approved | execution | Создание задач |
| execution | completed | Все задачи done |

На этом этапе: проект создаётся в фазе `setup`. Переход в `documents` — автоматически при первом открытии страницы проекта (если phase = setup → обновить на documents).

## Компоненты

### 1. ProjectPageLayout (новый)

**Главный layout-компонент.** Заменяет текущую разметку страницы.

- Двухколоночный: Пульс (фиксированная ширина ~280-320px) + Рабочая область (flex-1)
- Пульс скроллится независимо (sticky или отдельный scroll container)
- Рабочая область рендерит контент по `phase`
- На мобильных: Пульс сворачивается или становится табом (на усмотрение Claude Code)
- **Без max-w-960px** — полноэкранный

### 2. ProjectPulse (рефакторинг существующего)

Левая панель. Содержит три секции (все сворачиваемые):

**📋 План** — список задач со статусами. Сейчас задачи = чаты (маппинг сохраняется на этом этапе). В будущем — ProjectTask. Клик на задачу → навигация в рабочую область.

**📁 Файлы** — существующий ProjectFilesCard, адаптированный под узкую колонку. Кнопка загрузки.

**⚙️ Паспорт** — сворачиваемый блок. Название, описание, контекст. Упрощённая версия текущего ProjectPassport (без табов — просто сворачиваемые секции).

### 3. ProjectWorkArea (новый)

Правая часть. Рендерит контент по `phase`:

```
phase === 'setup' || 'documents':
  → WelcomeState: иконка, текст «Добро пожаловать в проект»,
    кнопка «Загрузить файлы» и «Начать планирование»

phase === 'planning':
  → PlanningState: заглушка «Планирование в разработке»

phase === 'approved':
  → ApprovedState: заглушка «План утверждён, задачи скоро»

phase === 'execution':
  → ExecutionState: сетка задач (карточки) или редирект в чат задачи

phase === 'completed':
  → CompletedState: заглушка «Проект завершён»
```

Все state-компоненты кроме `execution` — placeholder'ы с осмысленными текстами. Они будут заменены реальным содержимым в последующих ТЗ.

**ExecutionState** — отображает задачи (текущие чаты) как карточки-плитки с переходом в чат. Это рефакторинг текущего поведения в новый layout.

### 4. ManagerDrawer (новый)

Drawer справа. Каркас для будущего Менеджера проекта.

Структура:
- **Header**: аватар + «Менеджер проекта» + кнопка закрытия
- **Зона сообщений**: заглушка — «Менеджер проекта скоро будет доступен. Он поможет с планированием, разбором файлов и навигацией по задачам.»
- **Зона действий**: контекстные кнопки (пока скрыты, но layout зарезервирован). Высота зоны ~60-80px
- **Поле ввода**: заблокированное, с placeholder «Скоро здесь можно будет общаться с Менеджером»

Открывается по кнопке `[👤 Менеджер]` в header страницы.
Ширина: ~400px (на desktop).
Поведение: push (сжимает рабочую область), не overlay.

### 5. Что удаляется / переносится

| Компонент | Действие |
|---|---|
| ProjectActions (3 карточки) | **Удалить.** «Новая задача» → в рабочую область. «Менеджер» → drawer. «История задач» → план в Пульсе. |
| ProjectMeta (дата, счётчики) | **Удалить** или переместить в Паспорт (на усмотрение). |
| Текущий двухколоночный grid | **Заменить** на новый layout. |

## Что НЕ входит в это ТЗ

- AI-функциональность (Менеджер, Профессор, клерки)
- Таблица ProjectTask (задачи = чаты, как сейчас)
- Таблицы ProjectFolder, ProjectFile (файловая система — ТЗ-A2)
- Manifest, planJson, planReport
- Авто-переходы между фазами (кроме setup → documents)
- Мобильная адаптация (базовая — да, полноценная — отдельное ТЗ)

## Ожидаемый результат

После реализации:
1. Страница проекта — двухколоночная: Пульс слева, рабочая область справа
2. Рабочая область меняется по `phase` (пока заглушки)
3. Drawer Менеджера открывается по кнопке (каркас)
4. Все существующие данные (файлы, чаты-задачи, паспорт) отображаются в новом layout
5. Колонка `phase` в БД
