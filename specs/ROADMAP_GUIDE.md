# Руководство по созданию Roadmap

> **Инструкция для Claude Code**
> Используй при создании ROADMAP.md для нового ТЗ

---

## КРИТИЧНОЕ ПРАВИЛО

**НИКОГДА не отмечай задачу выполненной [x] без реальной валидации!**

```
❌ ЗАПРЕЩЕНО:
- "Код написан, отмечаю выполненным" — без проверки
- "Я просмотрел код, всё в порядке" — это НЕ валидация
- Проставлять чекбоксы пакетно в конце сессии

✅ ОБЯЗАТЕЛЬНО:
- Запустить npm run build — должен пройти
- Запустить npx tsc --noEmit — 0 ошибок
- Проверить в браузере — функционал работает
- Попросить пользователя сделать мануальный тест
```

## Формат этапа

```markdown
### Этап N: Название

**Статус:** ⬜ Не начат | 🔄 В работе | ✅ Завершён

**Цель:** Что должно быть достигнуто (1-2 предложения)

**Задачи:**
- [ ] Задача 1
- [ ] Задача 2

**Файлы:**
- `path/to/file.tsx` — что делаем

**Валидация этапа:**
- [ ] `npm run build` — успешен
- [ ] `npx tsc --noEmit` — 0 ошибок
- [ ] Проверка в браузере: [что проверить]
- [ ] 🧪 Мануальный тест пользователем

**Git (после валидации):**
```bash
git add [файлы этапа]
git commit -m "feat(tz-XX): название этапа"
```

**Критерий готовности:** Конкретное условие завершения
```

## Правила валидации

### После КАЖДОЙ задачи

```bash
# 1. TypeScript проверка
npx tsc --noEmit

# 2. Если есть ошибки — ИСПРАВИТЬ до отметки [x]
```

### После КАЖДОГО этапа

```bash
# 1. Полная сборка
npm run build

# 2. TypeScript
npx tsc --noEmit

# 3. Dev сервер
npm run dev
# Проверить в браузере что функционал работает

# 4. Git commit (ОБЯЗАТЕЛЬНО!)
git add [конкретные файлы]
git commit -m "feat(tz-XX): название этапа"
```

**Зачем Git после каждого этапа:**
- Гранулярный откат при проблемах (вместо "всё или ничего")
- История изменений для отладки (`git bisect`, `git diff`)
- Безопасность — код не теряется при ошибках

### Мануальное тестирование (пользователь)

**Когда требовать:**
- После завершения каждого этапа
- После значительных изменений UI
- После изменений в API
- После изменений в базе данных

**Формат запроса:**
```
Этап N завершён. Прошу провести мануальное тестирование:

1. Открой [URL]
2. Проверь: [конкретное действие]
3. Ожидаемый результат: [что должно произойти]
4. Проверь: [следующее действие]
5. ...

Сообщи результаты. Без подтверждения не перехожу к следующему этапу.
```

## Gate-keeping между этапами

**НЕЛЬЗЯ начинать следующий этап пока:**

1. ✅ Все задачи текущего этапа отмечены [x]
2. ✅ `npm run build` проходит успешно
3. ✅ `npx tsc --noEmit` — 0 ошибок
4. ✅ **Git commit** сделан (фиксация этапа)
5. ✅ Пользователь подтвердил мануальный тест
6. ✅ Обновлён CHANGELOG.md (локальный)
7. ✅ Обновлён HANDOFF.md

```
⛔ СТОП: Этап 2 не начинать без подтверждения Этапа 1
```

## Принципы задач

### Размер задачи

```
✅ Правильно: 1-3 часа работы
❌ Слишком большая: > 3 часов → разбить
❌ Слишком мелкая: < 15 минут → объединить
```

### Формулировка

```
❌ Плохо: "Улучшить UI"
✅ Хорошо: "Добавить кнопку 'Сохранить' в header страницы проекта"

❌ Плохо: "Исправить баги"
✅ Хорошо: "Исправить: при удалении проекта не обновляется sidebar"
```

### Группировка

```
❌ Плохо (по технологиям):
- Backend задачи
- Frontend задачи

✅ Хорошо (по функционалу):
- Этап 1: Создание чата
  - API endpoint
  - UI компонент
  - Интеграция
```

## Обязательные этапы

### Первый этап: Подготовка

Всегда начинай с:
- [ ] Изучить затронутые файлы
- [ ] Создать ветку (если нужно)
- [ ] Проверить текущее состояние (`npm run build`)

### Последний этап: Финализация

Всегда заканчивай:
```markdown
### Этап N: Финализация

**Задачи:**
- [ ] Финальное мануальное тестирование (пользователь)
- [ ] Обновить главный CHANGELOG.md
- [ ] Обновить SIMPLY_STATUS.md
- [ ] Обновить CLAUDE.md (если менялась структура)
- [ ] Обновить package.json (версия)
- [ ] Переместить папку в _archive/

**Валидация:**
- [ ] `npm run build` — успешен
- [ ] Production URL работает (если деплой)
- [ ] Документация актуальна
```

## Антипаттерны (НЕ ДЕЛАТЬ)

### ❌ Отмечать без проверки

```
❌ "Написал код, отмечаю [x]"
❌ "Просмотрел, выглядит правильно [x]"
❌ "Должно работать [x]"
```

### ❌ Пропускать валидацию

```
❌ "Потом проверим всё вместе"
❌ "Это мелочь, не надо проверять"
❌ "У меня нет ошибок TypeScript" (без запуска tsc)
```

### ❌ Игнорировать мануальные тесты

```
❌ "Код работает, тестировать не надо"
❌ "Я уверен что всё правильно"
```

### ❌ Спешить между этапами

```
❌ Начинать Этап 2 пока Этап 1 не проверен
❌ "Потом вернёмся и проверим"
```

---

## Правило: Доверяй, но проверяй

```
1. Написал код
2. Запустил npx tsc --noEmit
3. Есть ошибки? → Исправь
4. Запустил npm run build
5. Есть ошибки? → Исправь
6. Проверил в браузере
7. Работает? → Только теперь [x]
8. Не работает? → Исправь и повтори 2-7
9. Git commit — зафиксируй этап (защита от потери кода)
```

---

## Мантра

**"Непроверенный код = несуществующий код"**

Пока не прошла валидация — задача НЕ выполнена.
Чекбокс [x] = реальная проверка, а не "я написал код".
