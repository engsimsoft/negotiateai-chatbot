# ТЗ: saveFact v2 — метаданные для задач и календаря

**Версия:** v3.76.0
**Приоритет:** Высокий
**Одна цель:** Задачи получают статус, события получают дату — основа для канбана и визуального календаря.

---

## Проблема

saveFact записывает `content` как свободный текст. Для простых категорий (заметки, идеи, предпочтения) этого достаточно. Но для задач и календаря нужна структура: задача без статуса — не задача, событие без даты — не событие. Без метаданных невозможно показать канбан или визуальный календарь.

## Решение

Расширить saveFact опциональным полем `metadata` для двух категорий: task (статус) и calendar (дата/время). Остальные 5 категорий не трогаем — им метаданные не нужны.

---

## Что сделать

### 1. Расширить параметры tool saveFact

Добавить опциональное поле `metadata`:

```typescript
{
  content: string,
  category: "task" | "calendar" | "person" | "decision" | "idea" | "fact" | "preference",
  metadata?: {
    // Для task:
    status?: "new" | "in_progress" | "done",
    
    // Для calendar:
    date?: string,      // ISO 8601: "2026-04-11"
    time?: string,      // "14:00"
    endDate?: string,    // для многодневных событий
    endTime?: string,
  }
}
```

**Правила автозаполнения AI:**
- `category: "task"` → если пользователь не указал статус → `status: "new"` по умолчанию
- `category: "calendar"` → AI парсит дату и время из текста пользователя. Если дата не понятна — записывает без metadata, как сейчас
- Все остальные категории → metadata не передаётся

### 2. Хранение metadata в memory_entry

Добавить JSONB поле `metadata` в таблицу `memory_entry`.

Claude Code: проверь схему. Если поле `metadata` уже есть — использовать его. Если нет — добавить миграцию:

```sql
ALTER TABLE memory_entry ADD COLUMN metadata JSONB DEFAULT NULL;
```

JSONB а не JSON — для возможности индексации и фильтрации по полям.

### 3. Обновить execute saveFact

В execute добавить сохранение metadata в `memory_entry.metadata`. Если metadata не передан — поле остаётся NULL. Всё остальное (embedding, дедупликация, source) без изменений.

### 4. Управление статусом задач

Новый tool: `updateFact` — обновление существующего факта. Минимальный scope:

```typescript
{
  factId?: string,        // если известен ID
  search?: string,        // или поиск по тексту
  updates: {
    status?: "new" | "in_progress" | "done",
    content?: string,     // обновить текст
  }
}
```

**Сценарий:** пользователь говорит «задача сделана: позвонить Григорию».
1. AI вызывает `updateFact({ search: "позвонить Григорию", updates: { status: "done" } })`
2. Tool ищет факт по semantic search (embedding) в категории task
3. Обновляет status в metadata
4. Отвечает: «✓ Выполнено: позвонить Григорию»

**Поиск факта:** embedding content запроса → cosine similarity по фактам категории task → топ-1 с порогом > 0.7. Если не найден — сообщить пользователю.

### 5. Обновить промпт Simply

Добавить в блок saveFact инструкции про metadata и updateFact:

```
МЕТАДАННЫЕ:
Для задач — всегда передавай status: "new" (если пользователь не сказал иное).
Для событий — парси дату и время из текста. "В пятницу в 14:00" → date: ближайшая пятница ISO, time: "14:00".
Если дату не можешь определить — запиши без даты, это нормально.

ОБНОВЛЕНИЕ ЗАДАЧ:
Когда пользователь говорит "сделано: ...", "выполнил: ...", "готово: ..." → вызови updateFact с status: "done".
Когда говорит "начал: ...", "работаю над: ..." → вызови updateFact с status: "in_progress".
Ответ: «✓ Выполнено: [текст]» или «✓ В работе: [текст]»
```

### 6. Расширить API context/[category]

Endpoint `/api/user/memory/context/[category]` (из ТЗ карточек-артефактов) должен возвращать metadata в ответе:

```typescript
{
  facts: Array<{
    id: string,
    content: string,
    createdAt: string,
    source: string,
    metadata: { status?, date?, time?, endDate?, endTime? } | null
  }>
}
```

---

## Чего НЕ делать

- НЕ добавлять metadata для остальных 5 категорий — не нужно
- НЕ делать UI для изменения статуса — пользователь говорит Simply «сделано: ...»
- НЕ валидировать дату жёстко — если AI не может парсить, записать без metadata
- НЕ делать recurring events — одноразовые события достаточно
- НЕ удалять факты через updateFact — для удаления есть /settings/memory

---

## Критерии приёмки

1. **Задача с статусом:** сказать «задача: позвонить Григорию». В БД: metadata = `{ status: "new" }`. В DevPanel видно metadata
2. **Обновление статуса:** сказать «сделано: позвонить Григорию». В БД: metadata.status = "done". AI ответил «✓ Выполнено: позвонить Григорию»
3. **Событие с датой:** сказать «встреча: Григорий в пятницу в 14:00». В БД: metadata = `{ date: "2026-04-10", time: "14:00" }`
4. **Событие без даты:** сказать «встреча: обсудить контракт с юристом». В БД: metadata = NULL (дата не парсится — нормально)
5. **Заметка без metadata:** сказать «запомни: курс доллара 100 рублей». В БД: metadata = NULL (заметкам metadata не нужна)
6. **API возвращает metadata:** GET /api/user/memory/context/task → факты содержат metadata.status
